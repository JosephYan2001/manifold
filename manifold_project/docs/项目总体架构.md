# 项目总体架构与实现规范

更新：2026-09-22。状态：整体重构蓝图，尚未完成对应代码迁移。

[理论主稿](策略流形研究设计.CTDE本地策略改进版.md)定义数学对象和命题；[实验方案](策略流形研究设计.实验方案.md)定义研究问题、任务族、证据与推进顺序；本文件定义这些内容如何成为一致的实现。研究方案、代码实现、工程验收、正式冻结和结论成立分别记录，不能互相代替。

## 1. 现状与重构目标

当前问题不是文件数量本身，而是任务语义、算法条件、历史兼容和运行管理交叉修改：

| 当前依据 | 实际问题 | 目标边界 |
|---|---|---|
| [pair Runner](../experiments/pair_coordination/training/runner.py)、[nav Runner](../experiments/cooperative_navigation/training/runner.py) | 更新算法同时承担采样、检查点、恢复、评价和输出 | 算法返回明确更新结果；运行管理负责费用、提交与产物 |
| [nav 配置](../experiments/cooperative_navigation/configs.py)、[环境](../experiments/cooperative_navigation/envs/navigation.py)、[标签](../experiments/cooperative_navigation/training/ppo.py) | 三种任务模式及历史兼容影响多个消费者 | 单次解析任务及估计协议，运行时不靠缺省键猜任务 |
| [pair 损失](../experiments/pair_coordination/training/direction_loss.py)、[nav 数值函数](../experiments/cooperative_navigation/training/ppo.py) | 相同数学对象分散实现，时间权重和统计单位不同 | 共用定义与核验，显式传入权重，不强迫共享后端 |
| [nav 作者 PPO](../experiments/cooperative_navigation/training/author_ppo.py) | 作者算法状态与任务适配交织，不能视作普通 loss | 保留完整 PPO 后端，以轨迹、策略和状态接口接入 |
| [pair 配置别名](../experiments/pair_coordination/training/plan.py)、[nav 配置](../experiments/cooperative_navigation/configs.py) | 旧名称、条件覆盖和任务参数混在运行字典中 | 兼容只在读取边界处理，保存唯一有效配置 |

重构先保留可核验的旧行为，再实现新协议。文件移动、代码复用和协议改变分别评审；不直接合并两个 Runner，不建立无人使用的抽象框架，不把新奖励、目标槽或理论假设悄悄改成默认值。

## 2. 一条依赖链与职责归属

实现依赖顺序为：**任务及信息协议 → 轨迹与冻结对象 → 算法后端 → 运行和产物 → 研究任务及证据**。研究任务选择下层已经定义的能力，不把实验编号散布到环境或损失函数中；下层不根据图表或目标成绩改变行为。

| 职责 | 当前承载位置 | 应负责 | 不应负责 |
|---|---|---|---|
| 数学定义与核验 | 理论主稿、`tools/verification/`、成对精确评价 | 对象、恒等式、界、独立数学参照 | 代替应用协议验收 |
| 任务及信息适配 | 各环境的 `envs/`、观测构造、历史模块 | 奖励、终止、执行信息、集中字段、动作语义 | 调参、更新接收、算法胜负 |
| 轨迹与采样 | pair `SourceSampler`、nav `Collector` | 按请求采集、记录冻结概率与边界、即时计账 | 静默更换任务期限或估计目标 |
| 算法后端 | 各环境现有 `training/` | 方向方法、PG 或完整 PPO 的更新及状态 | 文件命名、目标评价选模 |
| 运行与产物 | 入口、Runner 运行外壳、storage/checkpoints | 配置、预算、提交恢复、评价调度、记录 | 重新解释奖励、标签或合法动作 |
| 研究任务与分析 | 套件入口、评价模块、实验矩阵 | 共同协议下的对照、统计和结论范围 | 绕开冻结条件反馈目标数据 |

先在现存位置形成清楚边界；仅在两个真实消费者需要同一语义时提取共用模块。pair 的解析梯度和精确枚举保留为独立参照；RWARE 尚无实现时不先造空接口目录。

### 2.1 信息协议与集中权限

每个任务分别声明执行输入、集中训练输入和仅供评价的诊断字段。Actor 与方向网络使用同一执行信息权限；集中 Critic 可使用获准的动作前全局字段，集中评价器可读取真值，但两者均不能向部署 Actor 注入额外信息。

执行输入记录字段、单位、历史、排序、空槽、容量、归一化和合法动作规则。当前输入不能包含当前动作或未来奖励；历史可以包含已发生的动作。集中权限不能隐藏在共享编码器、归一化统计或中央分配中。Actor、方向网络与 Critic 不共享可变参数。

固定形状只证明接口兼容，不能证明信息完整或目标占用覆盖。导航表示先完成实验方案第 6.2.1–6.2.2 节审查；本规范不选择槽位容量或新增任务信息。冻结部署包含输入处理及统计，不能只保存权重。

## 3. 最小语义契约

下列名称是待落实的语义约定，不表示仓库已经有这些类，也不要求每项各建一个文件。

| 契约 | 必须明确的内容 | 验收不变量 |
|---|---|---|
| `TaskSpec` | 任务版本、依赖、源/目标参数、动力学、团队奖励、折扣、成功/期限；信息及集中权限；动作及合法集合；已证有效界 | 同一配置只有一个目标定义；容量越界和空合法集明确失败；任务改变产生新身份 |
| `CollectionSpec` | 用途、冻结策略标识、完整回合或步数窗口、数量、种子流、费用上限、所需字段 | 不把窗口称完整回合；末段不足如何处理预先声明；采样即时记账 |
| `Rollout` | 回合/时间/机器人轴，本地与集中输入、动作、实际旧概率、合法集、奖励、终止/截断原因、末状态、有效位、长度、费用 | 填充不参与估计；末状态来自 reset 前；独立单位和权重可恢复；零步成功有记录 |
| `FrozenPolicy` | Actor 参数、概率头、输入处理及部署统计、合法动作规则、协议身份和指纹 | 同一快照的输入输出不因训练旁路改变；冻结策略不等于冻结动作随机流 |
| `MethodSpec` | 后端/版本、标签与基线、方向目标或 PPO 更新、网络、优化器、检查模式、候选规则、Critic 生命周期 | 差异显式可查；单模块消融只改登记项；不从 condition 名临时猜语义 |
| `StudySpec` | 问题/命题、环境职责、前提状态、对照、数据阶段、预算/种子、评价/选择及统计规则 | 已知假设失败、待证明和经验假设分开；源开发规则在目标评价前冻结 |
| `RunRecord` | 有效配置及身份、代码/依赖/种子、状态、提交点、各项费用、父运行、失败、检查和产物引用 | 成功和失败完整记录；恢复不回滚源费用；报告可追溯到提交对象 |

### 3.1 终止、标签和权重

任务成功和有限任务自身的期限结束均无后续任务价值；持续任务的采样窗口结束、有限任务尚未到期限时的收集截断，并不结束任务。是否 bootstrap 由任务及估计协议决定，不能只照搬环境的 `done` 或 `truncated` 名称。首次到达导航需处理初始成功、最后一步成功、期限失败；仓库交付后补货不构成首次完成终止。

完整 MC 指采集到任务终点的折扣回报。提前截断后加 Critic 尾值是有偏差风险的估计方案，GAE 也单独命名；旧配置的 `mc` 字符串不能证明已经满足完整 MC。有限任务期限是该任务终点，不为期限之后 bootstrap。时间、填充、折扣、机器人平均和归一化分母须在标签及损失两侧一致。

基线在使用数据之前冻结，依赖动作前允许信息，不依赖当前动作或未来结果。集中基线可以使用获准的动作前全局状态，但不能把本批拟合后的 Critic 重新代入已用标签。完整回合是独立检查单位，相关时间步或机器人不能增加独立样本。零步成功计入任务回合评价，但没有动作梯度；方向访问分布仍需正的期望折扣决策总权重。

## 4. 算法后端及冻结生命周期

### 4.1 主方法

数学定义与候选参数只由[实验方案第 3 节](策略流形研究设计.实验方案.md)维护。阶段链为：**冻结旧策略及标签基准 → 完整源回合 → 固定标签并拟合方向 → 独立方向检查 → 指数目标与候选拟合 → 独立回报检查 → 提交或保留旧策略 → 更新下一轮 Critic**。

- 旧策略、实际采样概率、标签、方向和目标各自在规定阶段固定。方向训练不能改变旧 Actor，Critic 优化不能修改旧标签。
- 各候选从同一旧 Actor 完整副本出发，用同一旧策略访问权重拟合；回退不是接着训练失败候选。指数目标与实际 Actor 分开记录，不能把目标低于 Actor 概率下界的问题静默裁掉。
- 方向或候选先固定，再采独立检查回合。后续自适应候选使用新检查数据；不能根据已读检查分数挑方向或拟合轮数后，仍称该批数据为独立验证。
- 经验检查只报告经验判断。置信版需要有效确定界、独立单位和跨轮/候选错误预算；样本最大值或检查通过率不替代有效界。
- 合法动作外概率为零，合法集合非空且满足所用方法的内点要求；采样、score、Fisher、指数归一化、KL 和概率比共用同一集合。动作屏蔽不替代输入覆盖证明。

旧 pair 先独立采样拟合本轮表 Critic；nav 冻结持久 Critic 用于标签，即使先优化在线 Critic，检查仍使用旧副本。它们不是同一生命周期。[pair 标签](../experiments/pair_coordination/training/labels.py)、[pair 检查](../experiments/pair_coordination/training/acceptance.py)和 [nav Runner](../experiments/cooperative_navigation/training/runner.py)的旧行为先分别保真；新方案的下一轮 Critic 流程属于协议变更，另给版本和验收。

### 4.2 PPO 与其他基线

作者 PPO 保留其完整 buffer、GAE、价值归一化、优化器、更新和检查点状态。[作者适配器](../experiments/cooperative_navigation/training/author_ppo.py)把共同轨迹转换为其输入，并提供同一评价器可用的 Actor；不能强加主方法的方向检查、候选回退或概率混合。MAPPO/IPPO 的集中/本地 Critic 权限明确区分，概率及合法动作接口与真实采样一致。

共同任务、信息、源费用和评价可以统一，不机械统一不同算法的全部超参数和生命周期。作者实现版本与项目覆盖参数分别披露；机制对齐控制另立 `StudySpec`，不改写作者基线后仍称原后端。PPO 标签和损失不是所有算法的隐式默认。

## 5. 配置只解析一次，运行身份可核对

入口按明确优先级解析默认值、文件、命令行及登记的方法覆盖，拒绝冲突或未知字段；历史别名只在这里转换。生成并校验一次完整有效配置，算法内部不再读取文件或临时补缺省值。

有效配置分为五块：任务、信息、方法、研究任务、运行资源与产物。方法块登记标签及采样策略，研究任务登记各阶段数量与费用，再解析为明确的采样请求。方法覆盖不能修改奖励和信息；消融覆盖只含声明改变的模块。记录字段来源与最终值；配置不完整或前置验收未满足时明确状态，不换默认协议继续运行。

| 操作 | 语义与身份要求 |
|---|---|
| `resume` | 同一运行从已提交边界继续；任务/信息/算法/预算和选择协议匹配，恢复优化器、归一化、随机状态、账本、采样计数；记录代码版本及兼容依据，同形权重不等于可恢复 |
| `fork` | 新运行和新身份；明示父检查点、改动及重置/继承状态。增加预算、改任务或方法不伪装成原运行续训；暖启动不冒充从头训练或零样本 |
| `evaluate` | 加载冻结部署对象，在声明的源/目标协议评价；不更新参数或部署统计，不加载训练期集中信息给 Actor |

提交边界包含 Actor、必要训练状态、账本和下一批种子位置。崩溃后已经消耗但未提交的数据仍计费；不能精确恢复成本时保守登记不可核实费用，不倒退账本。候选回退、方向检查和回报检查全部计入源训练，报告评价及机制诊断单列；不同用途分离随机流和数据阶段。

## 6. 运行产物与证据验收

文件布局由实验方案第 11.3 节唯一维护；本规范不复制第二套输出清单。运行管理执行精简元数据、表格、best/final 及预定快照保留规则，监控覆盖同一图。现有 JSON/JSONL 兼容输出不冒充新布局已实现；恢复所需账本纳入版本化状态或受控日志，不能为了精简文件丢失费用证据。

| 验收项 | 必须有的证据 |
|---|---|
| 数学与掩码 | score/Fisher/采样平方项的精确动作期望一致；合法概率、指数目标、KL 与权重正确；数值实现有独立参照 |
| 方向与 Actor | 同一冻结基准下评价旧策略、直接指数目标、拟合 Actor；独立输入误差与回报并列，训练 loss 不证明实现成功 |
| 采样与标签 | 完整终点/截断、reset 前末状态、填充、零步成功和冻结基线的受控例子；主 MC 不被预算末端窗口替代 |
| 数据隔离 | 训练、每项检查、源开发和报告数据用途可追溯；固定快照机制比较用共同原始数据，策略分化后不声称训练轨迹相同 |
| 统计单位 | 完整训练以训练种子为重复单位；快照、数据重复、回合保留层级与配对；机器人、步数和目标规模不增加训练样本数 |
| 成本与恢复 | 团队步、机器人动作及优化成本分列；中断前后账本单调，提交状态与记录一致；恢复和 fork 可区分 |
| 版本与结论 | 每项记录条件、检查方式、实际证据、限制、代码/协议版本；工程通过不等于运输前提成立，旧记录不自动成为新协议通过记录 |

调参、算法修改和检查点选择仅使用源数据。全部选择冻结后才执行正式目标评价；目标结果不反馈本批方法。预定失败、未达标和不稳定运行均保留。机制单轮结论、源学习曲线和最终零样本排名各自对应证据。

## 7. 按可验收增量迁移

| 顺序 | 工作与交付 | 验收后才允许继续 |
|---|---|---|
| 1. 固定边界 | 在现有模块标明任务、采样、算法和运行职责；记录旧行为及配置身份，落实最小契约 | 一个运行能从配置追溯到标签、采样、检查和产物；不引入新任务默认 |
| 2. pair 旧行为等价迁移 | 用现有一步任务贯通配置、轨迹、数学函数、更新结果和运行记录，逐项抽离职责 | 固定数据与状态下损失、梯度、候选、检查和费用在预定容差内一致；调用顺序和种子映射不静默改变，恢复不重用数据 |
| 3. pair 新研究协议 | 单独实现新机制族、多步固定策略 DP、完整标签及新 Critic 流程；更新任务/方法版本 | 奖励、占用、方向和误差独立核验；固定策略 DP 不称共享本地 Actor 最优求解；枚举超限明确失败 |
| 4. 导航定位后迁移 | 先完成理论与信息定位，再冻结观测、任务、采样和后端适配；复用已验收边界 | 目标信息要求与集中权限通过，终止/MC/三策略通过，作者 PPO 状态和评价兼容；形状测试不当覆盖证明 |
| 5. RWARE 实现 | 独立定位后锁定依赖、局部信息、奖励、交付补货和期限，再接入已有运行链 | 受控交付验证真实奖励和界，可达局部模式及拥堵偏移有明确结论边界；不照搬导航终止或配置 |
| 6. 正式研究 | 按实验方案冻结源开发、正式比较及目标评价配置 | 可调用入口、有效配置、工程证据、理论适用范围及预登记选择规则齐备 |

这不是要求所有环境等待同一条队列。导航理论审查可与 pair 边界迁移并行，但应用实现不能以架构调整替代未解决的研究判断。每一步只运行能验证该步的检查，不用长训练掩盖接口或数学问题。

本次文档重整不意味着契约已实现，也不修改现有训练语义。下一项工程工作是第一、二步；尚未验收的协议不提供虚构启动命令。
