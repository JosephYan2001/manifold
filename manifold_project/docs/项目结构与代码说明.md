# 项目结构与代码说明

当前目录按“论文文档、实验实现、运行配置、实验结果、文献与历史归档”组织。日常训练使用一个矩阵入口，任务回放使用一个 GIF 入口。旧导航套件入口、配套分析/回放工具、工程测试目录和重复依赖清单已清理。

## 1. 目录总览

命令在包含 `manifold_project` 的仓库根目录执行，本机为 `D:\manifold`。

```text
仓库根目录/
├─ manifold_project/
│  ├─ README.md                    项目阅读与运行入口
│  ├─ docs/                        理论、实验设计和开发路线
│  ├─ experiments/
│  │  ├─ __main__.py、cli.py        唯一矩阵训练/评价入口
│  │  ├─ registry.py               实验编号、方法和依赖关系
│  │  ├─ visualize.py              当前 checkpoint 的任务 GIF
│  │  ├─ requirements.txt          统一安装清单
│  │  ├─ configs/                  日常实验参数和检查开关
│  │  ├─ common/                   配置、运行信息、统计、报告和图表
│  │  ├─ finite/                   P/T 机制诊断及两步模型
│  │  ├─ pair_coordination/        成对环境、模型与训练器
│  │  ├─ cooperative_navigation/   导航环境、实体模型与共用应用训练器
│  │  ├─ applications/             应用任务接口及冻结评价
│  │  ├─ results/                  正式运行数据和判断报告
│  │  └─ reuse_audit.csv           归档源码复用与移除记录
│  └─ tools/                       文稿公式提取与数学核验
├─ references/                     参考论文和索引
├─ archive/                        原始实现与历史设计 ZIP
└─ .venv/                          本机 Python 环境
```

`.git/`、`.vscode/`、`.claude/` 属于版本管理、编辑器或本机工具配置，不是实验数据。`__pycache__/` 等缓存是可再生成产物，不放研究文档或正式结果。

## 2. 日常只需要哪些入口

| 工作 | 入口 |
|---|---|
| 安装依赖 | `python -m pip install -r manifold_project/experiments/requirements.txt` |
| 列出实验 | `python -m manifold_project.experiments --list` |
| 训练、机制诊断、冻结评价 | `python -m manifold_project.experiments`，由 `--experiments` 指定任务 |
| 核对参数而不训练 | 对训练命令追加 `--dry-run` |
| 生成任务 GIF | `python -m manifold_project.experiments.visualize` |
| 修改导航参数、复制训练命令 | [导航实验手册](../experiments/cooperative_navigation/README.md) |
| 查看结果 | [结果索引](../experiments/results/README.md) |

成对模块的 `train.py/evaluate.py` 保留作单次底层训练和精确评价入口；论文矩阵统一走上表命令。工程单元测试源码与测试专用依赖已按用户要求移除，日常运行不依赖它们。`tools/verification/` 是理论数值核验工具，职责不同，继续保留。

## 3. 代码如何连接

```text
__main__.py → cli.py → registry.py 与 common/config.py
  ├─ P/T → finite/
  │    ├─ 固定基点诊断 → diagnostics.py、linked_realization.py
  │    ├─ P-L → pair_coordination/current_protocol.py → training/runner.py
  │    └─ T-L → finite/training.py
  ├─ N/W/P-TB → cooperative_navigation/current_protocol.py → training/runner.py
  │    └─ training/collector.py → envs/tasks.py → 对应原生任务
  └─ 冻结评价 → applications/evaluation.py
所有当前矩阵结果 → common/reporting.py、common/plotting.py
```

`cooperative_navigation/` 同时承载导航和其他应用任务的共用训练器，这是直接复用旧代码的目录安排。`applications/` 提供字典观测、原生任务接口和冻结评价，没有另一套训练循环。保留这些模块路径，避免破坏训练依赖和 checkpoint 加载。

## 4. 导航各层职责

| 文件或目录 | 职责 |
|---|---|
| `current_protocol.py` | 公共配置映射到 Runner，汇总训练记录和源成本 |
| `envs/navigation.py` | MPE2 原生动力学、奖励、首次同时覆盖判定和集中状态 |
| `envs/tasks.py` | 导航、仓库、实体成对任务路由 |
| `observations/history.py` | 8 帧观测、上一动作和有效标记；末状态只读快照 |
| `models/entities.py` | 实体编码、关系注意力、按时间融合；显存分块与反向重计算 |
| `models/__init__.py` | Actor、方向、集中/本地 Critic、平铺历史解码 |
| `models/deployment.py` | 将训练 Actor 接到冻结评价的字典观测接口 |
| `training/collector.py` | 独立 episode 采样、成功/超时、变长 batch、实际成本 |
| `training/runner.py` | 冻结、收集、计算标签、更新、检查、提交和保存 |
| `training/ppo.py` | 自举价值目标、GAE、样本权重、方向和策略损失 |
| `training/author_ppo.py`、`entity_policy.py` | 作者 PPO 优化器与本项目实体网络/批次的适配 |
| `evaluation/evaluate.py`、`monitoring.py` | 训练器内部源监控和进度输出 |
| `evaluation/fit_probe.py` | 固定方向、改变 Actor 拟合预算的额外机制诊断 |
| `vendor/mappo/` | 固定版本作者 PPO 源码、许可证和来源记录 |
| `applications/envs/` | 导航、仓库、实体成对的统一观测和任务接口 |
| `applications/evaluation.py` | 冻结源 Actor，在指定规模和场景种子下评价 |

当前导航每个 episode 成功即结束，否则 400 步截断硬重置；收齐 16 个 episode 后更新。历史仅在 episode 内累积，重置清空；集中 Critic 读取当前全局状态。超时保留末状态自举，独立评估默认观察 1000 步。完整参数和边界只在导航手册维护。

## 5. 配置只有一套日常入口

```text
experiments/configs/defaults.json
→ configs/<环境>.json
→ configs/profiles.json
→ --config 覆盖文件
→ 命令参数和实验编号设置
→ current_protocol.py 映射到训练器
```

| 修改目标 | 修改位置 |
|---|---|
| 导航历史、episode、网络、分块和学习率 | `experiments/configs/navigation.json` |
| 检查开关 | `experiments/configs/navigation/checked.json`、`no_checks.json` |
| pilot/formal 默认预算与种子 | `experiments/configs/profiles.json`，单次也可用命令覆盖 |
| 其他环境 | `experiments/configs/pair.json`、`two_step.json`、`warehouse.json` 等 |
| 底层默认值与校验 | 环境目录下的 `configs/`、`configs.py` 或 `training/config.py` |

环境内部的配置仍被训练器读取，属于实现依赖，不能当重复文件删除；日常调参只改上面的公共配置。`direction_steps/actor_fit_steps/critic_steps` 在应用训练器中映射为 epoch；环境步、episode、epoch 和 round 不同。

## 6. 结果与文档放在哪里

每组正式运行保存到 `experiments/results/`：`manifest.json` 记录配置和协议；`training.csv` 与 `events.jsonl` 记录过程；`overview.png` 覆盖更新；`final.pt/best.pt` 保存模型；逐场景报告与汇总另列。失败记录保留用于诊断，不能把低分运行当临时文件删除。

主比较使用 final，best 是源监控挑选的辅助模型。应用 final 包含优化器、随机状态与成本；旧 streaming 模型还包含持久场景状态。统一矩阵入口没有自动续训开关，更换输入或采样协议需使用新输出目录。

理论进入[CTDE 主稿](策略流形研究设计.CTDE本地策略改进版.md)，研究任务进入[总体实验方案](总体实验方案.md)，当前证据进入[开发路线](研究主张与开发路线.md)，训练命令进入环境手册，运行判断进入对应结果目录。不要再把临时检查脚本或第二套启动说明放到环境根目录。
