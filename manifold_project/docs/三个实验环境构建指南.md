## 2. 共同数据约定

### 2.1 环境与执行接口

每个环境封装提供 `reset`、`step` 和集中训练状态读取能力。可以保留第三方原生接口，但进入训练收集器时应满足以下约定：

| 字段 | 约定 |
|---|---|
| 本地观测 | 按机器人索引存放；单个 actor 只接收自己的记录 |
| 动作 | 每个机器人一个原生离散动作编号 |
| 团队奖励 | 每个团队步一个标量，各方法使用同一定义 |
| 终点 | 区分任务结束与采样器临时截断，并记录原因 |
| 集中状态 | 单独读取与存储，只送入训练评价模块 |
| 动作掩码 | 原生全部动作可提交时为全真；若额外限制，须声明本地计算规则 |

可枚举环境的 `local_types` 数组含全队记录，只有 `local_types[i]` 属于机器人 $i$ 的本地输入。导航和仓库的团队观测容器遵循同一信息限制。

### 2.2 回合记录

收集器在内存中按完整回合组织，至少包含回合、时间步和机器人索引所对应的本地观测、自身过去动作、当前动作、冻结概率、团队奖励、终点和集中字段；索引可由张量轴表示。成对已有单步批次和成本账目，导航已有完整回合张量、本地历史、固定时域终点与用途账目，仓库仍待实现。完整 rollout 不默认落盘，统一事件日志保存统计所需字段。

actor 输入由预先声明的本地历史构造。回合开头补齐并带有效标记；不能将当前动作或未来奖励拼入当前输入。集中字段保存在独立键中，训练代码显式选择可读字段。

每轮使用一个冻结 actor。score、Fisher、方向标签和指数目标都记录该快照标识。方向训练中的旧概率、优势标签，以及 actor 拟合中的目标分布停止梯度。

### 2.3 权重和预算

可枚举任务一步终止，机器人记录权重为 $1/(Nn)$，其中 $N$ 为回合数、$n$ 为人数。多步任务使用实验方案的折扣回合权重，并检查所有有效记录权重之和为 1。

总源预算分别累计训练回合、方向检查、步幅选择和回报检查的团队环境步数。另记机器人动作数。正式比较中，两种计数不能混作同一横轴。

### 2.4 依赖和设备

各环境先建立可复现的 CPU 冒烟测试，再选择训练设备。新增学习代码采用的深度学习框架及其版本需实际安装验证后记录。依赖锁定文件保存于各环境目录，并记录第三方环境提交号；不要根据当前网页主分支名称假定本地发行包已有全部参数。

## 3. 共同训练模块与验收

### 3.1 方向训练

实现两个可单独选择的目标：解析 Fisher 二次项，以及采样动作对应的平方项。两者共用优势标签和方向函数结构。固定源数据的比较还应共用初始化和优化预算。

测试至少验证：

1. score 为实际动作独热向量减冻结概率。
2. 解析二次项与显式 Fisher 矩阵乘法相同。
3. 在相同有限数据上，两种目标可能有不同最优解。
4. 对动作精确求期望后，采样平方项恢复解析二次项。
5. 更新方向网络时，actor 参数与冻结概率不变。

方向输出在动作维度上和为零并有明确幅度上限。可枚举环境有两个动作，导航和仓库有五个动作，相关函数应从动作维度推导形状。

### 3.2 actor 目标拟合

从冻结概率与方向构造指数目标，采用前向 KL 拟合 actor。每个候选步幅从旧 actor 副本开始。验收时检查目标归一化、目标停止梯度、旧快照不变，以及拟合损失与实际回报的分项记录。

actor 的经验平均 KL 用于已采样输入上的拟合诊断。它不能直接替代全历史一致策略误差。若输出概率下限妨碍拟合目标，应记录残差并按预设规则处理步幅。

### 3.3 标签与接受检查

首版使用完整回报减动作前基线，源评价回合中的基线在评价数据生成前冻结。加入 GAE 时，配置和日志明确标签方式、折扣及终点处理。

方向与实际回报的检查使用各自独立回合，候选在对应评价数据产生前固定。先核验有效回报界及重复检验预算，再使用理论置信规则。若采用经验筛选变体，在配置和结果中明确标记。

### 3.4 训练入口的职责

`train.py` 读取一个源配置，循环执行冻结、采样、标签、方向、目标、拟合、检查和接受。它不读取目标评价结果。`evaluate.py` 加载冻结 actor 和预处理状态，关闭参数更新，执行预先列出的目标配置。

入口应校验配置并保存完整生效参数。成对的 train.py、evaluate.py、run_experiments.py 已实现；导航和仓库的同类入口尚待建设，不能混称全部入口均未实现。

## 4. 可枚举协作环境的现状与验收

### 4.1 现有代码与运行

目录：`experiments/pair_coordination/`。

| 文件 | 职责 |
|---|---|
| `configs/pair_source.json` | 固定 4 人、2 类型的源环境 |
| `envs/pair_coordination.py` | 类型采样、一步执行、成对奖励与固定策略采样 |
| `evaluation/exact_pair.py` | 真实回报、Fisher 方向、能量与误差 |
| `train.py`、`run_experiments.py` | 单次训练及 P-C/P-A/机制套件 |
| `evaluate.py` | 冻结策略与方向评价 |
| `tests/` | 环境、优化、检查、恢复、统计与日志回归验证 |

在仓库根目录执行：

```powershell
python -m manifold_project.experiments.pair_coordination.run_experiments --profile smoke --experiments all --dry-run
python -m unittest discover -s manifold_project/experiments/pair_coordination/tests -v
```

### 4.2 已完成的建设路径

下列功能已实现，不应按“新建模块”重新开发；当前工作是运行论文补充协议和复核结果。

1. training/direction_loss.py 实现两种方向目标及共同计算函数。
2. 先用每个类型一行的可训练方向表，完成固定数据优化；然后加入小型神经网络方向函数。两者分别标记容量。
3. 在 `evaluation/` 中比较学得方向与精确本地方向，保存误差和总体分数。
4. 加入 actor 及指数目标拟合，分别记录精确目标和实际 actor 的回报变化。
5. 接通回合独立的接受检查，形成完整单源训练入口。
6. 按实验方案重复样本量、独立数据集与冻结目标评价。

精确评价器只在显式评价或精确标签实验中调用。普通采样标签训练不得读取真实本地方向作为训练目标。

### 4.3 验收条件

- 环境、数学和训练回归检查持续通过，数量以当前测试输出为准。
- 固定数据和种子下可复现两个经验目标及对应优化结果。
- 给定方向的经验分数随独立样本量增加与精确分数相符；报告误差及重复统计。
- 精确指数更新与 actor 拟合后的回报分别计算。
- 相关类型、非完全图扩展如需加入，分别增加真值和采样测试。

当前精确枚举默认最多 100 万事件。超过上限应明确报错，不能把近似求和结果命名为精确真值。

## 5. 合作导航环境的建设

目录：`experiments/cooperative_navigation/`。环境选用 MPE2 `simple_spread_v3`，源码与配置依据见实验方案第 4 章。

### 5.1 先完成版本与环境接口

锁定支持 `num_agent_neighbors` 和 `num_landmark_neighbors` 的 MPE2 版本或提交。`envs/navigation.py` 负责构造 Parallel API 环境、动作字典转换、共同团队奖励和终点标记。

| 项目 | 源配置要求 |
|---|---|
| 规模 | 4 个智能体、4 个地标 |
| 动作 | 5 个离散动作 |
| 获准信息 | 自身信息、最近 2 个其他智能体、最近 2 个地标 |
| 回合 | 100 个完整联合步，成功不提前结束 |
| 奖励 | `local_ratio=0.5` 的原生个体奖励取均值 |
| 课程与缩放 | 关闭课程及动态缩放 |
| 目标规模 | 冻结后测试 3、6、8，同时改变智能体和地标数 |

先实现随机动作接口验收（脚本名由实现确定），验证一个源回合完整结束，并记录实际观测形状、动作数和奖励组成；不假定 run_demo.py 已存在。

### 5.2 本地历史与集中字段

`envs/observations.py` 构造最近 8 步本地历史、过去自身动作、有效标记和时间比例。最近邻槽位按每个时刻重新排序，不默认追踪同一个实体。保持所有对照相同的字段和历史规则。

最近邻数量限制不等同于有限距离视野。当前方案沿用原生最近邻规则；若另加距离裁剪，需形成新的明确环境协议。

记录 `state()` 的实际内容。若它只是各智能体部分观测的拼接，应如实命名；额外读取完整物理状态时，作为集中训练字段扩展并统一对照。

### 5.3 必须通过的测试

1. 源规模与目标规模下每个智能体的输入结构及 5 个动作语义一致。
2. 最近邻数、排序、实体不足补齐及历史初始补齐符合协议。
3. 将个体奖励求均值所得团队奖励与手工覆盖、碰撞项计算一致。
4. 一个 Parallel API 步对应一个完整团队步。
5. 第 100 步作为任务终点，完整回报在此结束；与 API 的截断标记正确衔接。
6. actor 输入没有其他机器人观测集合或额外全局字段。
7. 相同种子与动作序列可复现观测、奖励和终点。

### 5.4 训练与评价

接口验收后接入四种主算法和三项额外消融，共七个训练条件。具体标签、预算、评价网格和可选诊断以[导航详细设计](../experiments/cooperative_navigation/实验设计.md)为准。源评价记录团队回报、方向分数、actor 拟合与接受率；冻结目标评价记录每地标最近距离、终点覆盖率、全覆盖比例及唯一碰撞对数。

覆盖阈值初始为 0.1，沿用实验方案的按距离覆盖定义。该指标不额外求解一对一地标分配。显示窗口大小不能作为奖励有界性的证明；置信检查前另行确定有效回报界。

## 6. 仓库环境的建设

目录：`experiments/rware/`。环境选用 RWARE，源码依据见实验方案第 5 章。

### 6.1 先完成环境封装

`envs/warehouse.py` 负责原生环境构造、动作格式、团队奖励与终点处理。保留原生移动、转向、装卸和碰撞动力学。

| 项目 | 源配置要求 |
|---|---|
| 机器人 | 4 |
| 布局 | `shelf_columns=3`、`shelf_rows=2`、`column_height=8` |
| 请求队列 | 4 |
| 视野 | `sensor_range=2`，5×5 区域 |
| 通信 | `msg_bits=0` |
| 动作 | 5 个原生动作 |
| 奖励 | `GLOBAL` 奖励向量均值 |
| 回合 | 500 个团队步，关闭不活跃提前终止 |
| 目标规模 | 冻结后测试 2、6、8，保持布局和请求队列固定 |

先实现随机动作演示，确认源回合完成。增加受控交付状态测试，以验证一次交付对应一个团队奖励单位。

### 6.2 输入与动作职责

`envs/observations.py` 展平获准本地字段，构造最近 8 步历史、自身过去动作、有效标记及时间比例。动作接口只按机器人索引提交原生动作。环境原生碰撞规则及无效移动处理继续生效。

集中 critic 的状态字段独立列出。源数量固定，critic 可以使用固定长度源状态；部署只调用共享 actor。

### 6.3 必须通过的测试

1. 不同人数下本地观测字段、历史结构和动作语义一致。
2. 自身位置、朝向、载货状态和局部区域字段与原生观测一致。
3. 团队奖励等于实际交付次数，未因人数发生额外倍乘。
4. 同时提交各机器人动作时，碰撞和移动结果与原生环境一致。
5. 回合在规定任务终点结束，奖励累计和折扣正确。
6. 采样、方向和 actor 拟合均使用同一冻结快照。

### 6.4 训练与评价

接口通过后接入完整源训练。额外报告交付次数、每机器人交付数和达到交付阈值的回合比例。各方法使用同一输入与源重置分布。

仓库奖励可能稀疏，源试运行需要同时观察有效交付回合比例和接受率。若训练停滞，先区分采样缺少回报、方向估计、actor 拟合和统计门槛的影响，并保留失败日志。

## 8. 结果保存与完成标准

每次运行在所属环境的 `results/<run_id>/` 保存解析后配置、依赖版本、代码提交、随机种子、模型快照、回合预算和逐轮指标。保存 checkpoint 时连同 actor 结构、预处理规则及概率下限一起保存。

成对套件成功子运行采用 4 个 JSON 和一个 events.jsonl，已有目录按实验内容命名；导航计划采用统一事件日志与 PT 模型。精确布局由各环境文档维护，不再要求按记录类别分散保存一批 JSONL。上表 A/B 已完成开发实现，F 的正式结果仍需单独验收。

冻结测试前记录模型与配置校验值。评价程序重新加载后应复现相同输入的动作概率，并确认所有部署参数未更新。统计以独立训练种子为单位，完整回合用于采样依赖分组。

一个环境完成构建，应具备可运行入口、环境和信息协议测试、复现说明及实际运行记录。完成环境构建后，方向学习、actor 拟合和正式比较的状态仍分别记录。
