## 1. 这个环境要回答什么

成对协作环境已经说明：局部方向估计改善不必然转化为完整训练优势；检查可能消耗大量交互而没有展示保护收益；Actor 拟合预算可能有冗余。导航应在多步、部分观测、连续物理状态下检验这些现象，而不是重复可枚举任务的数学核验。

| 研究问题 | 需要的证据 | 不足以支持结论的现象 |
|---|---|---|
| Q1：在相同源交互预算下是否更有效率？ | 与 sampled、MAPPO、IPPO 比较独立评价回报曲线和覆盖表现，同时报告耗时 | 训练回报较高、网络更新次数更多或只挑最佳种子 |
| Q2：解析二次项是否带来训练收益？ | 完整方法与 sampled 除二次项外完全一致的比较 | 两个不同 loss 的绝对数值大小 |
| Q3：方向与回报检查是否值得其成本？ | 去检查消融、实际采样账目、检查决定及独立评价变化 | 接受率高、检查均值为正就称“真实不退化” |
| Q4：Actor 拟合是否成为瓶颈？ | 1/4 拟合预算下的 KL、回报和计算成本 | KL 小就认定回报更好 |
| Q5：冻结策略能否适应团队与任务数量变化？ | 相同 final actor 在各目标规模的独立评价，与各基线同规模比较 | 输入维度不变、人数增加后原始团队奖励变化 |

论文中主张的强度随结果调整。零差异、检查更慢、迁移下降都属于有效结果；不通过删除种子或事后挑环境构造优势。

## 2. 固定环境、奖励和终点

### 2.1 环境协议

选用 Farama MPE2 Simple Spread 的 Parallel API，已锁定并本地核验发行版 mpe2==1.1.1。接口提供离散动作、最近邻观测和课程/提前结束开关。[官方接口](https://mpe2.farama.org/environments/simple_spread/)

| 项目 | 本实验规定 |
|---|---|
| 源规模 | N=4：4 个机器人、4 个地标 |
| 动作 | continuous_actions=False，5 个离散原生动作，不额外动作掩码 |
| 本地可见邻居 | 最近 2 个其他机器人、最近 2 个地标 |
| 奖励混合 | local_ratio=0.5 |
| 回合长度 | 100 个联合步，每轮动作同时提交 |
| 成功提前结束 | terminate_on_success=False |
| 课程与缩放 | curriculum=False；dynamic_rescaling=False，均显式传入 |
| 重置与物理参数 | 锁定版本的原生重置和动力学，不按方法或目标规模改动 |
| 折扣 | gamma=0.99，训练与主评价一致 |
| 部署策略 | 从训练概率分布随机采样；贪心动作只能作为额外标明的评价 |

最近邻是数量限制，不是固定半径感知。远处实体也可能进入列表。规模变化时邻居数始终为 2。原生字段顺序、补齐、同距离排序及通信槽含义，以锁定源码和实测为准。当前在线说明与源码对部分默认值的展示存在差异，因此不能依赖省略参数后的默认行为。[环境源码](https://github.com/Farama-Foundation/MPE2/blob/main/mpe2/simple_spread/simple_spread.py)

### 2.2 共同团队奖励

所有方法使用同一个团队奖励：对原生返回的 n 个个体奖励取均值，不改为求和，也不让 IPPO 使用不同的个人奖励。

令机器人位置为 p_i，地标位置为 l_k，唯一碰撞对集合为 C_t。需通过源码和单步测试核验以下分解：

```text
g_t = -sum_k min_i ||p_i - l_k||
c_i,t = -sum_{j != i} 1{机器人 i 与 j 碰撞}
r_team,t = (1 - 0.5) * g_t + 0.5 * mean_i(c_i,t)
         = 0.5 * g_t - |C_t| / n
```

碰撞条件使用原生机器人半径和距离判据，不能用覆盖阈值替代。MPE2 1.1.1 在 N=2/3/4/6/8 的 100 步固定动作回合已通过此奖励分解验收。若后续换版后与公式不一致，先解释并修订协议，不能悄悄修改奖励。

### 2.3 有限时域

第 100 个联合步是本实验定义的任务终点，即使 API 将其标为 truncation，也设置终点价值为零。采样器临时切片与任务终点是不同概念：首版只收完整回合，禁止把中途切片当作终点。最终 transition 的奖励必须计入回报；历史缓存每次 reset 清空。

距离奖励的有效上下界不能由显示窗口或样本极值推断。首版使用 empirical 检查，不宣称 Hoeffding 安全保证。若后续启用置信检查，必须先根据有限时域、重置范围和动力学建立有效奖励、标签与回合分数界，再单独冻结协议。

## 3. 输入与网络必须一致

### 3.1 Actor 与方向网络

每个机器人只读取自身最近 8 步获准观测与过去自身动作。历史元素定义为 `(o_i,s, onehot(a_i,s-1), valid_s)`，s=t-7…t；首次动作前的前一动作填零，回合起点之前全部补零且 valid=0。附加当前时间 t/100，当前动作 a_i,t 不得进入当前输入。

每步观测原生维度记为 d，输入维度为 `8*(d+5+1)+1`。不要直接套用文档默认 N=3 时的维度；在 3/4/6/8 人实测形状、字段与固定维度。最近邻槽位表示距离排序，不保证跨时间是同一个实体。所有方法共用同一历史构造器。

初始 Actor：两层 tanh MLP，每层 128 单元，五维 logits，共享参数。概率规定为 `pi=(1-beta)*softmax(logits)+beta/5`，beta=0.02；MAPPO/IPPO 同样使用这一分布，并按混合后的实际采样概率计算 log_prob、熵和 PPO ratio。所有合法动作概率严格为正。

初始方向网络：独立的两层 128 单元 tanh MLP，输出五维 z；令 `u=tanh(z)`，`q=(q_max/2)*(u-mean(u))`，q_max=1，以保证零和且每个分量绝对值不超过 q_max。Actor 与方向参数独立，方向训练期间冻结 Actor。

首版使用 float32，涉及独立回合汇总的均值和统计区间用 float64 累积。实测 N=2/3/4/6/8 的原生观测均为 16 维，8 步历史 Actor 输入为 177 维。机器精度和优化稳定性由 smoke 核验，不继承成对任务全程 float64 的成本。

### 3.2 Critic 与信息边界

完整方法、sampled、三种消融和 MAPPO 使用相同集中字段与价值网络结构：源环境 state() 与时间，初始为两层 128 单元 MLP、标量价值输出。MPE2 1.1.1 的 state() 已核查为各机器人原生观测拼接，源规模加时间后 65 维，不称为完整物理状态。

IPPO 的价值网络读取与 Actor 相同的本地历史和时间，各机器人共享价值网络参数，预测同一个团队奖励目标。集中与本地 critic 的输入维度不同，因此不能声称全部方法总参数数完全相同；应报告 Actor、critic、方向网络各自参数量。

首版不使用运行中的观测标准化，以免候选更新或迁移时隐式改变策略。若 pilot 确需归一化，必须统一全部方法、只用源数据拟合、包含在 checkpoint，并在检查和目标评价时冻结。评价器为距离/碰撞指标读取物理位置是允许的，但这些字段不得经日志或旁路进入 Actor。

## 4. 七个训练条件

| 标识 | 条件 | 与完整方法的唯一预定差异 |
|---|---|---|
| ours | 解析方向＋Actor 拟合＋两项 empirical 检查 | 参考方法 |
| sampled | 采样平方方向目标 | 只替换方向损失二次项；线性项、标签、网络、预算及检查一致 |
| mappo | 共享本地 Actor＋集中 critic 的 PPO | 直接优化 PPO 策略目标，不训练方向、不做两项接受检查 |
| ippo | 共享本地 Actor＋本地 critic 的 PPO | 与 MAPPO 共享 PPO 设置，critic 信息范围不同 |
| no_direction_check | 删除方向检查 | 不采方向检查回合，直接进入候选构造；回报检查保留 |
| no_return_check | 删除回报检查 | 方向通过后接受首个有效候选；同时取消回报驱动的步幅回退 |
| fit_quarter | Actor 拟合预算为标准的 1/4 | 仅减少 Actor epochs，方向、critic 和检查不变 |

MAPPO 以[官方实现](https://github.com/marlbenchmark/on-policy)为实现参考；对本地历史、概率混合、团队奖励及终点的适配必须显式记录。这里比较的是本协议下的适配版本，不把未经运行的官方结果当作本地基线。

## 5. 每轮训练与接受检查

### 5.1 标签和优化

初始每轮采集 16 个完整源回合，即 1600 团队步。完整回合是 minibatch 分组单位，初始每批 4 回合；单回合时间步和机器人不作为独立统计重复。

方向方法首版标签为 `G_t - V_old(state_t,t)`，其中 G_t 为完整折扣 return-to-go。先冻结上一轮 critic 并计算本批标签，再用本批回报拟合 critic 供下一轮使用；首轮 critic 为固定初始化。独立方向检查沿用本轮预先冻结的 critic。这样避免先用检查数据拟合基线再检验。首版不对方向优势做减均值、缩放或截断，不悄悄改变方向目标。

方向损失和 Actor 拟合使用 `gamma^t / (n * sum_{episode,time} gamma^t)` 权重，权重和为 1。旧概率、标签与目标均 stop-gradient。analytic 二次项为 `sum_a mu_a*q_a^2 - (sum_a mu_a*q_a)^2`；sampled 为 `(q_taken - sum_a mu_a*q_a)^2`。

MAPPO/IPPO 初始采用 GAE(lambda=0.95) 和 PPO clipping，终点 bootstrap 为零；ratio 按单个机器人条件动作概率计算，不改为联合概率乘积。可使用批内优势标准化，但需固定并记录。完整方法与 PPO 的标签处理不同是算法整体比较的一部分；N-A1 的 analytic/sampled 必须保持相同标签。若声称优势来自方向目标而非标签，需要补 N-L 标签对齐实验。

为对齐本文的折扣目标，PPO 策略项也按 gamma^t 与团队内机器人平均加权；记录这是对参考实现的协议适配。GAE 使用 rollout 开始前固定的 critic 预测及完整奖励序列，计算后 stop-gradient，再更新价值网络。PPO 首版不使用价值裁剪、学习率衰减或 KL 早停，避免隐含设置；若开发阶段加入，必须纳入全部 PPO 条件的冻结配置。

Actor 和 critic 跨轮延续权重；方向网络每轮按派生种子重新初始化。方向与候选拟合每次重置 Adam，critic 与 PPO 的优化器跨轮保留。完成轮次 checkpoint 保存相应优化器、全部随机流和环境采样计数；开发验证恢复与连续运行一致。每轮固定 Actor 的概率及预处理，不能在收集期间异步更新。

实现补充：所有条件的 critic 均回归团队 MC return，包括 PPO 使用 GAE 策略标签时；价值损失为按时间折扣加权 MSE×value_coef。该选择与关闭价值裁剪等设置一同进入配置，不将本地适配版本等同于官方 MAPPO 的全部实现。

### 5.2 方向检查

拟合后冻结方向，在旧 Actor 下另采 8 个完整源回合。每回合计算按时间折扣、机器人平均的 `2*A*S^T*q - q^T*F*q`，再对独立回合取均值。empirical 规则为均值严格大于零才通过。不从回合内部样本数计算“独立样本置信度”。

### 5.3 目标、拟合和回报检查

初始 eta=0.1，每轮至多 2 个候选，第二次 eta=0.05。每个候选都从同一个旧 Actor 副本开始，构造 softmax(log(mu)+eta*q) 并拟合前向 KL。按训练状态分布记录拟合前后 KL、p95、最大样本 KL 及目标落到概率下限以下的比例。

冻结候选后，旧 Actor 与候选各采 8 个新回合；两组使用相互独立的训练检查种子。折扣团队回报均值差严格大于零则接受，否则回退一次步幅或保留旧 Actor。不复用独立论文评价回合做接受检查。

no_return_check 直接接受首个数值有效候选，其有效性只检查概率、有限数值等工程条件，不偷偷加入回报判据。任何 NaN/非法分布属于运行异常，记录后停止该种子，不用重试挑选成功轨迹。

### 5.4 起始超参数及冻结规则

| 参数 | 首次 pilot 候选 | 冻结前要确认 |
|---|---:|---|
| Actor/方向/critic 隐藏层 | 128×2 | 维度、梯度与有效容量 |
| 方向 epochs | 16 | 方向 loss 和输出饱和情况 |
| Actor 拟合 epochs | 16；fit_quarter=4 | KL 是否仍明显下降 |
| critic epochs | 10 | 回报预测误差及尺度 |
| 三个 Adam 学习率 | 3e-4 | 优化是否稳定 |
| PPO epochs / clip | 10 / 0.2 | 实际 KL、clip fraction |
| PPO 熵系数 / 价值系数 | 0.01 / 0.5 | 不让熵项掩盖主目标 |
| 梯度范数上限 | 0.5 | 各模块统一记录裁剪前后范数 |
| 概率下限混合 beta / q_max | 0.02 / 1 | 概率合法、方向界成立 |
| 源采集 / 方向检查 / 每侧回报检查 | 16 / 8 / 8 回合 | 回报噪声与检查开销 |

这些值不从成对实验直接宣布有效。开发只用种子 40/41/42：若需搜索，初始候选限定学习率 {1e-4,3e-4}，方向方法另选 eta {0.05,0.1}；MAPPO/IPPO 可比较 PPO epochs {5,10}。每个主方法最多 4 组候选，同一开发预算，按源验证 AUC 选择，平局按最终源回报再按预定配置序号。消融继承选定完整方法的设置，不各自调到最优；sampled 与 ours 共享超参数以隔离二次项，不独立选择有利配置。保存全部候选结果及规则。

若候选全部无学习信号，先排查实现；新增搜索应另记开发版本，不能查看正式种子或目标规模结果后再回头选择。正式冻结保存所有配置、代码版本、依赖版本和选择记录。

## 6. 预算、阶段和种子

### 6.1 预算单位

一次所有机器人联合动作推进计 1 团队步，不乘人数。训练、critic 专用采样（若以后增加）、方向检查、旧策略回报检查、候选回报检查都计入源优化预算 B；重复使用同一数据做 epoch 不重复计交互，但需计优化次数和耗时。

按首版批量，每轮成本为：

| 分支 | 团队步 |
|---|---:|
| 完整方法，一个候选 | 1600+800+800+800=4000 |
| 完整方法，第二个候选也检查 | 5600 |
| 方向检查拒绝 | 2400 |
| 去方向检查，一个候选 | 3200 |
| 去回报检查 | 2400 |
| MAPPO/IPPO | 1600 |

所以相同预算下轮数不同是预定结果。整回合计账，不超预算；下一轮预留方法对应最低成本，剩余不足时停止并报告未用预算。回退候选也必须先检查剩余预算。

### 6.2 阶段表

| 阶段 | 条件及种子 | 每次源预算 | 用途 |
|---|---|---:|---|
| 接口验收 N-S0 | 无训练，N=2/3/4/6/8 | 少量固定动作回合 | 形状、奖励、终点、随机性 |
| smoke N-S1 | 7 条件，种子 0 | 16000 团队步 | 至少能走通采集、优化、检查、保存和评价 |
| pilot N-P | 7 条件，40/41/42 | 200000 团队步 | 21 次开发训练；评估学习与成本，不当正式证据 |
| 正式 N-C/N-A | 7 条件，100–109 | 候选 2000000 团队步 | 冻结后 70 次训练，含去重 |

正式 200 万是规划值，不是已证明足够。pilot 后若各方法仍明显上升，可先仅在开发种子上按共同预算检查 50 万和 100 万；最终选择一个统一正式预算，再启动新种子。不按哪个预算让 ours 领先来选择，也不在正式运行中按表现提前停种子。

训练随机流分为初始化、训练 reset/动作、方向检查、回报旧策略、回报候选；用任务标识、训练种子、用途、计数派生。独立评价使用另外的种子空间，不能与训练检查共用。相同训练种子只是配对实验块，不保证不同方法经历相同轨迹。

## 7. 每个实验具体做什么

### N-C：四种算法的正式比较（必做）

- 条件：ours、sampled、mappo、ippo；每种 10 个新种子，统一 B，共 40 次训练。
- 主结果：独立源评价的折扣回报 AUC/B、final 回报；报告平均终点覆盖率与碰撞作为任务解释。
- 图表：回报—总源步曲线及训练种子区间；方法对比表（回报、覆盖、全覆盖率、碰撞、耗时、优化次数）。
- 待检验预期：方向方法可能在学习速度或最终表现上有竞争力，也可能因检查成本落后。若最终相近，重点报告达到覆盖阈值的成本与计算代价，不把微小均值差写成优势。

### N-A1：解析二次项（必做，复用 N-C）

- 直接比较 ours 与 sampled，不新增训练；共享标签、网络、采集量、epochs、检查和评价协议。
- 报告同种子配对 AUC/final 差值、方向检查分数、目标与拟合 KL。
- 导航没有精确本地方向，不能把采样分数命名为“真实方向误差”。若二者无明显差别，结论是该条件下没有发现训练收益，不能靠 loss 数值证明解析项更好。

### N-A2：方向检查的收益与成本（必做）

- ours vs no_direction_check；新增 10 次训练，参考组复用。
- 报告方向拒绝率、候选数、后续回报拒绝率、各用途交互成本及 AUC。
- 待检验预期：若方向不可靠，筛选可能减少无效拟合；若几乎全通过，移除检查可能更有效率。两种结果都应保留。

### N-A3：回报检查的收益与成本（必做）

- ours vs no_return_check；新增 10 次训练，参考组复用。
- 报告采样检查回报差、接受率、独立评价曲线的下降、样本效率及总耗时。
- 预期检验检查是否值得其预算；常规评价曲线只能显示评价节点间变化，不能估计每次更新的真实退化率，更不能称“没有下降即安全”。
- 若需要论文主张“逐次保护收益”，执行下方 N-D 独立审计；否则将结论限定为成本和整体训练表现。

### N-A4：Actor 拟合预算（必做）

- ours vs fit_quarter；新增 10 次训练，参考组复用。
- 标准 16 epochs 时对照为 4；若正式标准在开发阶段改变，则为 ceil(标准/4)，其余配置一致。
- 报告拟合 KL 分布、回报/AUC、梯度更新次数和耗时。预期可能性能近似且更省计算，也可能拟合不足导致性能下降；成对任务的 16 轮结论不直接推广。

### N-T：冻结人数迁移（必做，不新增训练）

- 复用 N-C 的 4 方法×10 个 final actor，评价 N=3/4/6/8；N=4 使用相同 final 源评价结果，不重复采样。
- 每模型每规模 200 个独立回合。N=3/6/8 合计 24000 回合、240 万团队步，单独记为目标评价成本。
- 保持原生重置、动力学、100 步时域、邻居数 2、奖励系数和随机策略不变；只改变 N，因此地标数量也同步改变。
- 报告同规模下方法对比，以及每地标距离、覆盖率、唯一碰撞对数、每机器人碰撞数。原始回报跨规模不可单独解释为迁移优劣。
- 无目标 fine-tuning、无目标 critic 更新、无目标观测统计更新；不得按目标结果从 best/final/中间 checkpoint 中挑选。
- 预期是检验经验泛化，不要求人数变化时回报恒定；也不把经验指标当成方向运输定理的验证。

### N-D：独立更新审计（条件必做）

若论文要声称回报检查降低逐次退化或存在误拒绝，预先启用此诊断。仅对 ours/no_return_check，每训练种子第 1、5、10、20 个完成轮次的首个有效候选，保留旧 Actor 和候选、冻结预处理及检查决定；无候选时记缺失，不移动到更有利轮次。

训练结束后，每对策略用 200 个独立 reset 种子配对评价；旧/新策略动作随机流分开，全部回合独立于训练检查。按每个 reset 的候选−旧回报差计算配对区间。区间上界<0 为“评价支持的退化”，下界>0 为“评价支持的改善”，否则为“不确定”。拒绝且区间下界>0 为有证据的误拒绝；不能将点估计符号当成精确真值。

最多 2 方法×10 种子×4 对×2 策略×200 回合×100 步=320 万审计步。此为固定轮次诊断，不是全部更新退化率的无偏估计；检查组和消融组的第 k 轮交互成本也不同。候选集合按正式协议预先确定，不能看检查真假后才保存。比较结果以训练种子为重复块，不把所有候选当成独立训练种子。报告逐候选区间时注明多重比较，未经校正不得作总体错误率保证。

### N-L：标签对齐（条件实验）

若主比较显示明显差异且论文要将其归因于方向目标，而非 MC/GAE 或优势标准化，应在开发阶段预先增加标签对齐：ours/sampled 使用统一 GAE(lambda=0.95)；或 MAPPO/IPPO 改用 MC 标签。先用 3 个开发种子确认实现，再冻结完整的对齐对照，不只展示有利的一侧。该实验不属于基本 70 次训练，不默认扩大范围。

## 8. 独立评价与统计口径

### 8.1 评价时机、数量与成本

pilot 在 0、20%、40%、60%、80%、100% 的共同源预算节点评价，每节点 20 回合。正式在 0、5%、…、100% 的 21 个节点评价；前 20 个节点各 100 回合，final 200 回合。运行完成后以实际最后提交策略作为 B 节点策略。

节点使用预算不超过节点的最近已提交 Actor，禁止用越过节点后才得到的新策略。实现方式：下一轮可能越过节点时保留当前 Actor，在预算节点登记该快照；评价可延后执行，不能让结果反馈到训练。曲线不插值未来策略；AUC 用节点间左端已提交策略评价均值作矩形积分，末端 final 另报。报告这是固定网格近似，不是每轮精确积分。

各方法使用相同的预定 reset 种子表和源评价节点，以减少比较噪声；动作流按模型隔离，评价不得消耗训练 RNG。源节点评价可以共用 reset 集合，但不能将这些相关节点当作独立重复。final 使用另一套 reset 种子表。

源优化预算 B 不包含仅用于论文报告的独立评价，后者单独计账且不得用于训练接受或正式调参。正式 70 次训练的报告评价为 `70*(20*100+200)*100=1540 万` 团队步；训练预算若取 200 万则总优化交互为 1.4 亿步。再列目标和可选审计成本，不能把评价成本隐藏在“零成本”中。

### 8.2 必报指标

| 指标 | 定义与用途 |
|---|---|
| 团队折扣回报 J | 每回合 sum_{t=0}^{99} gamma^t*r_team,t，源主指标 |
| AUC/B | 固定共同源预算网格上的评价回报积分/B，源效率主指标；可能为负 |
| 平均终点距离 | t=100 时每地标到最近机器人的距离均值，越低越好 |
| 终点覆盖率 | t=100 时距离严格小于 0.1 的地标比例；与奖励不混淆 |
| 全覆盖率 | 每个地标均满足上述阈值的回合比例 |
| 碰撞 | 每步唯一无序碰撞对数的回合均值；另报每机器人 `2*对数/n` |
| 到覆盖阈值的成本 | 首个独立评价均值达到 0.8 的预算节点，未达到记 NA并报告达到比例；只是网格分辨率下的描述性指标 |
| 检查和拟合 | 回合均值分数、接受/拒绝、目标与拟合 KL、候选数、分项源成本 |
| 计算 | 训练墙钟、评价墙钟、优化更新数、硬件与精度、各模块参数量 |

覆盖不要求一对一分配；相邻地标可能被同一机器人覆盖。碰撞用唯一机器人对，不能把两个个体的记录再误当两次独立事件。

### 8.3 独立重复与不确定性

先对每个训练种子的评价回合求均值，再跨 10 个训练种子报告均值、标准差和 95% bootstrap 区间。方法差异按相同训练种子配对 bootstrap；同时给出每个种子的点，不能把 200 个评价回合称为 200 个训练种子。

预先将源 AUC/B 和 final J 列为主要结果；覆盖、碰撞及成本为解释指标。区间默认为逐比较区间，不是多个算法/规模同时覆盖的区间。若报告多项显著性检验，应事先指定比较集合并作多重比较校正。数据不支持差异时报告不确定，不能把“未显著”写成“证明等价”。

失败、NaN、预算耗尽、未达阈值均保留。运行错误可修复后按新代码版本重跑受影响的预定集合，但不能默默删掉失败种子或反复重试到成功。中断恢复只到完成轮次边界，额外采集但未提交的步数单列；正式训练不按评价表现提前停止。

## 9. 预期论文图表与结果解释

基本输出为一张源训练总览、一张迁移总览及 CSV；论文排版时再导出所需独立面板。

| 结果 | 内容 | 能支持的结论 |
|---|---|---|
| 源训练总览 | 4 方法回报曲线、覆盖、碰撞；3 项消融、检查成本和拟合开销 | 效率/性能与成本的具体取舍 |
| 正式方法表 | 7 条件 final J、AUC、覆盖、碰撞、耗时及区间 | 同源预算比较，失败种子数一并列出 |
| 迁移总览与表 | 4 方法×4 个规模的回报、距离、覆盖和碰撞 | 固定本地输入协议下的冻结迁移表现 |

若 ours 与 sampled 相同，报告未发现解析项训练收益；若去检查更好，报告检查成本超过已观察收益；若缩短拟合不降性能，报告计算冗余；若源性能好而迁移下降，报告分布变化的限制。不要为了维持预期而改换主指标。

## 10. 保存规则与建议模块

吸收成对任务的文件管理经验，设计每个成功训练目录只保留 config.json、summary.json、events.jsonl、checkpoints/best.pt、checkpoints/final.pt。PT 包含网络、必要优化器、预处理与恢复状态，不把大型权重展开成 JSON。best 如保存只用于开发诊断，论文使用 final；不为每个轮次另存文件。

套件根目录保存 manifest.json、status.json、training_results.csv、training_summary.csv、learning_curves.csv 和 overview.png；目标评价单独保存 transfer_results.csv、transfer_summary.csv、transfer_overview.png。无训练记录的机制/接口验收不生成空 CSV。

events.jsonl 用 stream/record 区分采样、训练、方向、拟合、检查、提交和耗时；默认关闭逐梯度日志，不保存全部 rollout。失败时才额外保留 failure.json 和进度信息。若启用 N-D，预定候选统一保存到单个 audit_snapshots.pt，其评价结果写 audit_results.csv，作为显式诊断例外。

建议套件目录：`results/nav_01_smoke`、`nav_02_pilot`、`nav_03_formal`；正式迁移放在对应 formal 目录下，不与源训练混淆。重跑用新版本目录，不覆盖既有结果。

## 11. 执行顺序与完成标准

1. **锁版本与验环境。** 安装后记录包版本/源码提交，验证 N=2/3/4/6/8 的观测、动作和种子；单步手算奖励分解；第 100 步无 bootstrap；本地历史没有当前动作或全局状态泄漏。验证原生默认设置不会覆盖显式参数。
2. **跑通七条件 smoke。** 检查所有概率和梯度有限、标签和目标 stop-gradient、冻结副本不变、两项检查数据独立、预算不超支、PPO ratio 初始为 1、checkpoint 恢复和连续训练一致。零/负/正人工统计量验证检查分支。
3. **完成 pilot 与有限调参。** 固定开发种子与搜索范围，报告全部条件。评价是否有覆盖学习、基线是否正常、检查是否几乎全拒绝及运行成本。此阶段不做目标规模调参。
4. **冻结正式协议。** 确定唯一 B、标签、超参数、指标、种子、评价网格、是否启用 N-D/N-L；保存配置与依赖锁定，不以正式结果回调。
5. **运行 70 次正式源训练。** P-C 式主比较与消融共用参考条件，每个条件每个种子只训练一次；输出成功与失败记录。
6. **冻结迁移与统计。** 复用四种主方法 final，完成 3/4/6/8 规模评价、必要审计与论文图表，明确结论边界。

接口、七条件 smoke、迁移/审计链路及恢复已完成首版验收，记录见[实现验收记录](实现验收记录.md)。当前下一步是第 3 项 pilot，不直接启动正式训练。smoke 使用每条件 16000 步，源节点 0/50%/100% 各 2 回合；仅减少验收报告成本，不改变 pilot/正式评价规则。训练入口会要求正式配置显式标为 frozen；不替用户提前宣布参数有效。
