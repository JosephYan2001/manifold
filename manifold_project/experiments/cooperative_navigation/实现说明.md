# 合作导航：实现说明

本页记录现有代码，研究设计由[总实验方案](../../docs/策略流形研究设计.实验方案.md)维护。以下实现现状不代表新协议已完成验收。

## 模块与数据流

| 模块 | 职责 |
|---|---|
| `run_experiments.py`、`configs.py` | 合并配置、选择条件、预算、指纹、恢复和 dry-run |
| `envs/navigation.py` | MPE2 1.1.1 动力学与奖励适配、全覆盖及截止判定 |
| `observations/history.py` | 本地观测历史、过去动作、历史有效位、任务时钟 |
| `models/` | 方向方法 Actor、Critic、方向网络及检查点加载 |
| `training/collector.py` | 训练与检查采样、变长批次、末端观测、源成本记账 |
| `training/ppo.py` | 冻结 MC/GAE 标签、终止与截断处理、padding 屏蔽 |
| `training/author_ppo.py` | 作者 MAPPO/IPPO 的 buffer、更新与 ValueNorm 适配 |
| `training/runner.py` | 方向学习、Actor 拟合、经验检查、回退及模型保存 |
| `evaluation/evaluate.py`、`arrival.py` | 独立评价、首达指标与已有策略诊断 |
| `evaluation/transfer.py` | final 冻结迁移评价及候选审计 |
| `evaluation/reporting.py`、`plotting.py`、`monitoring.py` | CSV、统计、汇总图和训练监控 |
| `../visualize_navigation.py` | 冻结 Actor 的任务回放 |

数据依次经过任务适配器、历史编码、采样批、冻结标签、算法更新和独立评价。环境中的全局诊断量用于报告，不自动进入 Actor 输入。现存持续任务、有限期限任务和首达任务是不同协议，不能合并统计。

## 任务、输入与网络

`source.json` 默认仍为 `continuing`；`configs/first_arrival/*.json` 显式启用首达任务，当前任务期限为 500 步。训练配额为 `train_episodes × horizon = 16 × 100 = 1600` 个真实联合步：100 不是任务截止，16 也不是每轮完整任务数。

覆盖要求每个目标到最近机器人的距离严格小于 0.1，不要求一对一匹配。任务首次同时全覆盖即成功，不按历史访问累积，也不要求成功后继续占位。

| 边界 | 现有处理 |
|---|---|
| 首次全覆盖，包括最后一步成功 | 真终止，保留末次奖励，后续价值为零 |
| 截止时仍未完成 | 真终止，保留末次奖励，后续价值为零 |
| 训练配额耗尽而任务未结束 | 采样截断，用 reset 前末端观测 bootstrap，切断 GAE 递推 |
| 初始已全覆盖 | 零步成功，不采动作 |

适配器关闭原生提前成功终止，统一作上述判断。团队奖励为原生个体奖励均值；评价 J 为实际终止前的折扣团队奖励，与成功率分别报告。

当前每帧含最近 2 个机器人、最近 2 个地标，观测维度为 16。首达 Actor 输入为 `8 × (16 + 5 + 1) + 1 = 177`：5 是过去动作 one-hot，1 是历史有效位，最后 1 是任务时钟。历史有效位不是目标槽掩码。源集中 Critic 为 `4 × 16 + 1 = 65` 维，IPPO Critic 读取各自 177 维历史。持续任务模型不含时钟，不能直接当作首达模型使用。

方向方法 Actor、Critic 和方向网络均为两层隐藏层的 tanh MLP，当前默认宽度 128。Actor 输出五个物理动作的概率并作 beta 均匀混合；Critic 输出标量；方向网络输出有界零和向量，默认 `q_max=1`，每轮重新初始化。当前没有全目标槽接口、集合编码或方向网络软更新。

## 完整方法的一轮

1. 冻结旧 Actor/Critic，按真实联合步配额采集训练批；任务结束后 reset，批末未完成任务保留末端观测。
2. 用旧 Critic 生成固定标签，再训练 Critic；本轮方向标签不随 Critic 更新重算。“MC”在批末采样截断处仍含 Critic 补尾。
3. 训练新方向网络。`sampled` 将解析二次项替换为采样 score 平方，其他模块继承配置。
4. 独立采完整任务做经验方向检查；分数不大于零则不更新 Actor。
5. 从旧 Actor 出发，拟合 `softmax(log(mu)+eta*q)` 指数目标。
6. 旧策略与候选各采完整任务；实际 J 均值严格提高才接受，否则减半 eta 并重新拟合。候选次数由 `attempts` 限制。
7. 训练、方向检查和回报检查均计入源预算；独立报告评价单列计账。保存 final、诊断 best，按设置刷新监控。

`no_direction_check` 只去方向检查；`no_return_check` 去回报检查及其回退；`no_checks` 去两者；`fit_quarter` 将 Actor 拟合 epochs 减为四分之一并向上取整。经验检查不构成默认的高概率不退化保证。padding 不进入有效标签、损失、标准化和诊断；折扣损失按共同任务期限归一化。

MAPPO/IPPO 默认接入 `vendor/mappo` 作者实现，保留其 PPO、GAE、ValueNorm、价值裁剪与 Huber 选项。MAPPO Critic 读集中输入，IPPO Critic 读本地输入；首达批次只把有效 transition 装入作者 buffer。作者 Actor 的 LayerNorm、初始化及输出参数化与方向方法不同，整算法比较不能归因于单一方向模块。

评价只部署 Actor。首达 best 按成功率、截尾步数和碰撞排序，仅作诊断；现有主表及迁移使用 final。恢复校验原任务、配置、源码、依赖及随机状态。

## 新协议的实现边界

现有代码和旧测试不能作为新协议已验收的凭据。后续实施至少要重新核验以下接口，完整研究条件以总方案为准：

- 信息接口：完整目标信息、容量边界、合法动作、时钟和冻结统计；远目标测试只能确认信息传入，不能证明理论覆盖。
- 轨迹与标签：完整回合采样、首达/截止/初始成功、MC 与 GAE 的适用范围、折扣权重、padding 和实际成本。
- 更新与诊断：AN/SA 共同快照与数据、独立验证、旧策略/指数目标/拟合 Actor 三策略评价、拟合与接受规则的对应关系。
- 运行与产物：恢复、预算、评价节点、final 冻结、精简日志和可视化；先完成短程工程验证，再执行冻结后的正式实验。

源码仍保留旧配置和兼容分支。其存在不表示总方案中的理论覆盖、结构可识别性或方向偏移界已经建立。
