## 2. 结论与尚未解决的问题

1. **方向64值得继续诊断。** A1 回报提高 12.40，碰撞减少约 16%，结束平均目标距离从 0.452 降至 0.420。2.82M 附近一次监控成功 1/8，但最终为 0/20，尚未形成可靠完成能力。额外方向优化并非完全无效；仅有 2M 时的判断应更新。
2. **还不能证明方向更准确。** 最后约 20% 轮次中，A1 实际策略 KL 为 1.587e-4，A0 为 7.767e-5，A2 为 2.691e-5。A1 每轮走得更大，也可能解释改善，需要同 KL 的直接执行比较。
3. **Actor 实现值得优先排查。** A2 续训新增 68 轮中有 29 轮 `fit_kl_after > fit_kl_before`（42.6%）；A0 为 18/273，A1 为 7/273。这个指标说明训练批次上的拟合目标没有改善，并不直接等价于真实回报下降。
4. **当前仍存在学习效率差距。** AN 后期策略熵约 1.54/1.53/1.57，五动作均匀分布为 1.609；MAPPO 约 0.62。熵衡量动作分布，不能把强行降低熵当成解决方向问题。AN/MAPPO 访问状态不同，日志 KL、价值解释方差也不能直接作为方向准确度的公平比较。
5. **MAPPO 也有明显失败。** 一个最终场景的平均目标距离达到 18.392，导致其 20 场景平均结束距离为 1.136；中位数为 0.140。不能只看平均距离认定 AN 更强，也不能只看回报掩盖 MAPPO 的远离目标失败。
6. **先不改成功终止规则、不盲目扩大所有组预算。** 三组 AN 成功终止仍很少，现有证据优先指向到达能力和有效更新问题。稳定覆盖属于另一个任务协议，应单独比较。

## 4. 第一批只跑两个固定策略诊断

入口：`python -m manifold_project.experiments.cooperative_navigation.diagnose`。读取 checkpoint 中的 Actor、Critic、观测/任务配置，冻结旧 Actor/Critic 后重新采样；不更新原模型、不改变原训练器、不恢复历史未保存批次。旧运行没有保存方向网络和训练批次，因此无法逐轮复现那 29 次拟合恶化。

### D1 方向16与方向64的同 KL 比较

固定 A0 4M 的同一个 Actor/Critic、16 个训练 episode、32 个独立验证 episode、方向初始化和小批次随机顺序。分别训练方向 16/64 epoch，用原 eta=0.1 构造目标策略，各按原 Actor 配置拟合 16 epoch。比较四个候选：两个直接执行的指数目标策略、两个拟合 Actor。

KL 统一为验证集旧策略状态上的折扣加权 `KL(old || candidate)`。为避免把不同步长解释成方向质量，取共同值 `min(请求KL, 0.95 × 四候选原始KL的最小值)`，再用候选与旧策略的概率混合达到该值。它是诊断策略，不写回训练 Actor。共同值不保证恰等于请求的 1e-4；`common_kl` 和 `matched_actual_kl` 会显式记录。若 `low_common_kl=true`，说明共同更新太小，微弱收益不应被解释为没有方向效果。

这比较的是同一经验状态分布上的平均 KL，不保证新策略轨迹上 KL 相同；混合后的策略也不等于原训练候选。单独看 `direction_scores.csv` 仍无法证明真实优势方向正确，因为其标签来自冻结 Critic 的 GAE。

### D2 固定目标的 Actor 拟合

固定 A2 4M 的 Actor/Critic，重新采 64 个训练 episode。按保存配置训练一次方向（16 epoch），固定方向和 eta=0.1。比较 Actor 学习率 3e-4、1e-4、3e-5，每组 16 epoch，使用相同初始化和小批次顺序。每个 epoch 保存训练/验证目标 KL、实际策略 KL；对每个学习率分别评价最终 Actor 和训练目标 KL 最低的 Actor（含 epoch 0）。

最佳 epoch 只按训练目标 KL 选，不按验证回报选。D2 不匹配 KL，因为要观察拟合行为本身；不能用 D2 不同步长的回报排序直接证明方向更好。

### 可直接执行的 PowerShell 命令

在已安装 PyTorch、MPE2 的原训练环境运行，单 GPU 顺序执行。首轮诊断数据种子 40，评价 40 场景；这不是重新训练一个 seed 40 模型。

```powershell
Set-Location D:\manifold
$src = "manifold_project/experiments/results/navigation_diagnosis_20261012_4m_s40_v1"
$out = "manifold_project/experiments/results/navigation_fixed_diagnosis_20261014_v1"
$base = "$src/an_base/N-C_source_learning/full/AN_s40/checkpoints/final.pt"
$batch = "$src/an_batch64/N-C_source_learning/full/AN_s40/checkpoints/final.pt"

# D1：相同旧策略/数据，方向16 vs 64；直接目标与拟合Actor在共同实际KL下比较
python -m manifold_project.experiments.cooperative_navigation.diagnose --mode direction --checkpoint "$base" --output "$out/direction_s40" --seeds 40 --batch-episodes 16 --validation-episodes 32 --evaluation-episodes 40 --direction-epochs 16 64 --fit-epochs 16 --target-kl 0.0001 --device cuda --allow-duplicate-openmp

# D2：固定方向和目标，只比较Actor学习率与最佳/最终epoch
python -m manifold_project.experiments.cooperative_navigation.diagnose --mode fit --checkpoint "$batch" --output "$out/fit_s40" --seeds 40 --batch-episodes 64 --validation-episodes 32 --evaluation-episodes 40 --fit-epochs 16 --actor-lrs 0.0003 0.0001 0.00003 --device cuda --allow-duplicate-openmp
```

可先给任一命令追加 `--dry-run`：读取 checkpoint、输出计划、不创建目录、不采样。正式运行时去掉该参数。

这两条命令最多新增 219200、318400 个诊断环境步，合计 537600（按 400 步采样、1000 步评价上限计算，成功提前结束会减少）。它们单独计入 `diagnostic_steps`，不混入原 4M 预算。方向和 Actor 优化计算另计。不要同时在单 GPU 上启动两条命令。

首轮结果有区分度后，将命令的 `--seeds 40` 换成 `--seeds 41 42`，输出目录改成 `direction_s41_42` / `fit_s41_42`；其余保持不变。这里是同一个训练 checkpoint 上的独立采样/方向初始化复验，不是算法训练种子复验。

诊断入口目前不提供中断恢复；已存在的输出目录会拒绝覆盖。中断后保留部分 CSV，换新的输出目录重新执行。原公共训练入口的 `--resume` 不适用于这里。

## 5. 跑完后按什么决策

| 结果 | 支持的解释 | 下一步 |
|---|---|---|
| 同 KL 时，64 epoch 的直接目标稳定优于16，跨诊断种子复现 | 增加方向优化改善了该基点的有效建议 | 保留64，换A1 checkpoint复验，再考虑完整训练确认 |
| 直接目标有收益，拟合Actor在同KL下收益变弱/变负 | Actor实现损失值得优先修正 | 根据D2选择学习率或训练目标KL最佳epoch规则，再做完整训练对照 |
| D2最终epoch拟合变差，最佳epoch明显更好 | 末轮选择/优化震荡可能有影响 | 先验证较小学习率或保留最佳拟合epoch，不改方向算法 |
| D2训练KL改善、验证KL恶化 | 新批次上的拟合泛化问题 | 再做独立批次/样本量诊断；不能直接归咎方向网络 |
| 两个直接目标同KL收益都不稳定或为负 | 问题可能在方向、标签或状态分布 | 再查Critic与优势标签；当前诊断不能单独区分二者 |
| 场景区间很宽或共同KL过小 | 诊断分辨率不足 | 增加评价场景或单独预设另一KL/eta设置；不要先下算法结论 |

主要读取 `diagnostics.csv` 的共同/实际KL、`return_gain`、场景区间与成功率，以及 `fit_trace.csv` 的训练/验证目标KL。`evaluation_episodes.csv` 保存配对逐场景结果，`direction_scores.csv` 保存训练/验证代理目标，`manifest.json` 保存checkpoint哈希、配置、成本和冻结验证。评价结果不用于自动选择或更新原模型。

当前已完成 CPU 小网络双模式集成检查及 KL 校准检查；正式诊断命令留给训练环境执行，尚无 D1/D2 实验结论。
