# 合作导航：训练指标与调参说明

更新：2026-09-19。本页只解释指标和诊断；候选参数、选参顺序与全部执行命令统一见[实验运行说明](实验运行说明.md)。

## 1. 三张源 CSV

| 文件 | 行单位 | 主要用途 |
|---|---|---|
| training_results.csv | condition×训练 seed | status、J、AUC、覆盖、成本、剩余预算、时间 |
| training_summary.csv | condition×metric 或 ours−对照×metric | mean/std/95% 区间、有效 count、failed/incomplete |
| learning_curves.csv | condition×seed×预算节点 | 核对预算节点与实际 Actor 提交成本 |

J 是独立折扣团队回报的回合均值，一般为负，越大越好。AUC 列保存的是 AUC/B，用固定节点左矩形近似，也可为负。训练回报和接受检查差值不是论文评价。

coverage 是终点最近机器人距离严格小于 0.1 的地标比例；all_covered 是全部地标满足条件的回合比例；distance 是每地标最近距离平均。collision_pairs 是每步唯一无序碰撞对数，collisions_per_agent=2*对数/N。覆盖不要求一对一分配。

coverage_cost 是独立评价均值首次达到 0.8 的预算节点，未达为空；summary 中 coverage_reached 的均值为达到比例。未达到不能记为 0，也不能只报达到种子的成本而不报达到率。

先对一个模型的评价回合求均值，再跨训练种子 bootstrap。count 是训练种子数；单种子 std/区间为空。kind=paired_difference 按相同 seed 做 ours−对照。区间跨 0 不代表证明等效，多个逐比较区间也不是同时覆盖保证。

## 2. 总览图

源图 3×3：回报、覆盖、碰撞曲线；AUC/B、final J、用途成本；训练秒数、优化次数、拟合 KL。柱上黑点是训练种子。迁移图 2×3：回报、距离、覆盖、全覆盖、碰撞对数、每机器人碰撞数。原始奖励随人数和地标数变化，应同规模比较方法，不能仅凭 N=8 奖励更负宣布迁移失败。

训练中的 `training_monitor.png`（外部日志监控为 `live_monitor.png`）只显示当前条件/种子。训练批回报每轮更新；独立评价回报、覆盖和距离只在原评价节点增加数据，误差条为 `1.96×回合标准误`，不是跨训练种子区间。20轮滑动平均用于观察趋势，不能替代原始曲线或正式统计。PPO的更新比例按算法定义恒为1，不表示更安全；消融缺少的检查面板显示“不适用”。候选KL可能来自被拒绝的候选，不能直接解释为已提交策略变化。

## 3. 预算与新增诊断

预算以团队联合步计数，100步为一个完整回合，不是agent-step或optimizer step。检查采样也计入源训练预算，因此同预算下ours与PPO更新轮数不同。报告评价另计成本；不同预算的AUC不直接混比。

| 诊断 | 解释与限制 |
|---|---|
| J_se / coverage_se / distance_se | 独立评价回合均值的标准误，不是跨训练种子的区间 |
| explained_variance | Critic最后训练minibatch的解释方差，不是独立泛化误差 |
| policy_step_kl | ours候选相对旧策略的实际变化，区别于目标拟合残差 |
| fit_kl_before / fit_kl_after | 拟合目标与候选的差距，小不代表任务回报更高 |
| policy_entropy | 策略随机性；不能只据此判断探索有效 |
| ppo_kl / clip_fraction | 最后优化minibatch的统计，不能与ours全训练批KL严格等同比较 |

源奖励是密集距离与碰撞奖励，覆盖率使用独立距离阈值。覆盖不变时，距离或碰撞改善仍可能提高回报；应结合曲线与任务动画判断。

## 4. 末段稳定性

检查末30%预算内最后5个非final评价点，final单列，因为其随机流不同。预定实用阈值：J极差≤2、覆盖极差≤0.02、平均距离极差≤0.02；各点近似95%误差半径也应低于相应阈值，并检查final与末段一致。

| 诊断 | 后续动作 |
|---|---|
| 回报继续改善，即使覆盖不变 | 结合距离/碰撞，考虑延长共同预算，不提前宣布收敛 |
| 波动大或评价精度不足 | 增加评价分辨率或排查优化；不能以最后一点定排名 |
| 低覆盖且进入平台 | 优先调参或机制诊断，不机械扩大步数 |
| 高覆盖（≥80%）且经验稳定 | 在开发种子41/42上复核，再冻结正式预算 |

这些阈值是开发诊断约定，不是收敛定理或统计等效检验。源网格可能共用评价场景，不能把节点当独立训练重复；旧结果缺少标准误时报告信息不足，不补造精度。运行稳定性工具的命令见运行说明第2节。

## 5. 常见现象


| 现象 | 先查证据 | 再考虑什么 |
|---|---|---|
| 全部无学习 | 环境验收、value_mse、终点、源网格 | 开发预算，再有限学习率搜索 |
| 方向几乎全拒绝 | 回合分数、q_abs_max、critic 误差 | 标签尺度与方向学习率；改检查样本数须新协议 |
| 回报经常拒绝 | 两组检查回报、eta、fit KL | 开发阶段降低 eta；不重复抽到通过为止 |
| KL 小但无收益 | 独立 J、目标与 mu 距离、概率下限 | KL 只说明拟合，不证明目标更优 |
| 1/4 拟合相近 | 多种子配对 J/AUC、KL、步数与耗时 | 可检验计算冗余，不凭单种子宣布等效 |
| PPO clip fraction 大 | 最后 minibatch 的 ppo_kl、独立曲线 | 开发阶段降低学习率或 epochs |
| 资源消耗高 | history/hidden、完整回合数、threads | 先测 CPU 单线程吞吐；改 minibatch 也改变优化轨迹 |
| NaN/非法概率 | failure.json 与最后优化事件 | 修复后新版本运行，不当普通检查拒绝 |

fit_kl_after 在种子表是每轮最后一个候选的平均，逐候选在 events。optimizer_steps 是实际 Adam 次数总和。train_seconds 含采集/优化/检查，不含独立评价和轮次保存/套件汇总；评价单列，完整作业墙钟另报。
