# 合作导航：训练指标与调参说明

更新：2026-09-18。默认参数仍是开发候选。先验证实现和学习信号，再选择预算与超参数；不根据正式种子或迁移结果回头调参。

## 1. 三张源 CSV

| 文件 | 行单位 | 主要用途 |
|---|---|---|
| training_results.csv | condition×训练 seed | status、J、AUC、覆盖、成本、剩余预算、时间 |
| training_summary.csv | condition×metric 或 ours−对照×metric | mean/std/95% 区间、有效 count、failed/incomplete |
| learning_curves.csv | condition×seed×预算节点 | 核对预算节点与实际 Actor 提交成本 |

J 是独立折扣团队回报的回合均值，一般为负，越大越好。AUC 列保存的是 AUC/B，用固定节点左矩形近似，也可为负。训练回报和接受检查差值不是论文评价。

coverage 是终点最近机器人距离严格小于 0.1 的地标比例；all_covered 是全部地标满足条件的回合比例；distance 是每地标最近距离平均。collision_pairs 是每步唯一无序碰撞对数，collisions_per_agent=2*对数/N。覆盖不要求一对一分配。

coverage_cost 是独立评价均值首次达到 0.8 的预算节点，未达为空；summary 中 coverage_reached 的均值为达到比例。未达到不能记为 0，也不能只报达到种子的成本而不报达到率。

先对一个模型的评价回合求均值，再跨训练种子 bootstrap。count 是训练种子数；单种子 std/区间为空。kind=paired_difference 按相同 seed 做 ours−对照。区间跨 0 不代表证明等效，多个逐比较区间也不是同时覆盖保证。

## 3. 预算和覆盖配置

预算是团队联合步，100 步为一个完整回合，不是 agent-step 或 optimizer step。完整方法需要检查采样，所以同预算下轮数少于 PPO 属于预定差异。

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-C N-A --budget 500000 --plot
```

这是相同开发种子、统一增加预算的新套件，不是原地给旧套件续跑。评价网格同比例变化，不直接混合不同预算的 AUC。自己的覆盖文件可以只写改动键：

```json
{"budget":200000,"actor_lr":0.0001,"direction_lr":0.0001,"critic_lr":0.0001,"eta":0.05}
```

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/my_pilot.json --experiments N-C N-A --plot
```

配置合并顺序：source → profile → 自定义 JSON → CLI。未知键报错。完整有效配置落盘到 manifest/各运行 config。

## 4. 有限调参与冻结

1. 先过接口测试和 smoke，不用调参掩盖实现错误。
2. 跑默认 3 种子 pilot，看基线学习信号、覆盖与方向拒绝率。
3. 学习率只试 1e-4/3e-4，方向 eta 试 0.05/0.1；PPO epochs 试 5/10。一个学习率候选统一作用于该方法的各 Adam，避免扩成三个独立搜索维度。每主方法最多 4 组，同开发预算，保留全部候选。
4. ours 与 sampled 共用参数，按 ours 的源 AUC 选取，sampled 不单独选最优；消融继承 ours。MAPPO/IPPO 可分别按源开发 AUC 选择。平局按 final J，再按预定配置序号。
5. 若预算末端仍明显上升，只在开发种子统一检查 50 万、100 万步，选唯一正式 B；冻结标签、网络、参数、网格、种子、审计计划，再开始正式运行。

若三类方法选择了不同参数，用 `method_overrides` 明确写入同一配置，例如：

```json
{
  "method_overrides": {
    "ours": {"actor_lr":0.0001,"direction_lr":0.0001,"critic_lr":0.0001,"eta":0.05},
    "mappo": {"actor_lr":0.0003,"critic_lr":0.0003,"ppo_epochs":5},
    "ippo": {"actor_lr":0.0001,"critic_lr":0.0001,"ppo_epochs":10}
  }
}
```

sampled 与所有方向消融自动继承 ours；不允许给它们独立覆盖。预算、环境、网络和评价设置仍共同固定。入口不自动网格搜索，也不删除非胜出候选；自定义配置和 `--output` 保留候选，选择规则与记录另行归档。

## 5. 常见现象

| 现象 | 先查证据 | 再考虑什么 |
|---|---|---|
| 全部无学习 | 环境验收、value_mse、终点、源网格 | 开发预算，再有限学习率搜索 |
| 方向几乎全拒绝 | 回合分数、q_abs_max、critic 误差 | 标签尺度与方向学习率；改检查样本数须新协议 |
| 回报经常拒绝 | 两组检查回报、eta、fit KL | 开发阶段降低 eta；不重复抽到通过为止 |
| KL 小但无收益 | 独立 J、目标与 mu 距离、概率下限 | KL 只说明拟合，不证明目标更优 |
| 1/4 拟合相近 | 多种子配对 J/AUC、KL、步数与耗时 | 可检验计算冗余，不凭单种子宣布等效 |
| PPO clip fraction 大 | 最后 minibatch 的 ppo_kl、独立曲线 | 开发阶段降低学习率或 epochs |
| 资源消耗高 | history/hidden、完整回合数、threads | 先测 CPU 单线程吞吐；改 minibatch 也改变优化轨迹 |
| NaN/非法概率 | failure.json 与最后优化事件 | 修复后新版本运行，不当普通检查拒绝 |

fit_kl_after 在种子表是每轮最后一个候选的平均，逐候选在 events。optimizer_steps 是实际 Adam 次数总和。train_seconds 含采集/优化/检查，不含独立评价和轮次保存/套件汇总；评价单列，完整作业墙钟另报。

## 6. 何时形成论文结果

smoke 只验证工程链路，pilot 选择参数。正式需完成预定七条件×十新种子，保留失败，以 AUC/B 和 final J 为主指标，再做四主方法冻结迁移。声称逐次保护要预先启用 N-D；将差异归因于方向目标而非标签要 N-L。无明显优势也应保留，不删种子、不改报 best。
