# 合作导航：指标与调参

更新：2026-09-22。当前以首次全覆盖为目标，命令和配置只在[运行说明](实验运行说明.md)维护。

## 1. 先读哪些表

training_results.csv每行是条件×训练种子；learning_curves.csv每行是条件×种子×预算节点；training_summary.csv汇总训练种子及ours−对照配对差。count是训练种子数，单种子区间为空，不把评价场景当作独立训练重复。

| 字段 | 解释 |
|---|---|
| success_rate | 截止前首次同时全覆盖的场景比例，越高越好 |
| success_by_100/200/500 | 指定步数前累计成功比例；只生成不超过task_horizon的阈值 |
| success_AUC | 成功率对源优化预算的左矩形积分/B，越高越好 |
| restricted_mean_steps | 成功计实际首达步，失败计任务截止；越低越好，必须与成功率同看 |
| success_steps_mean | 仅成功场景的平均首达步数，全失败为空；不能独立排名 |
| success_cost | 首次独立评价成功率≥0.9的预算节点，未达到为空 |
| episode_steps | 实际运行步数的场景平均值；评价成本另以evaluation_steps记总和 |
| collision_pairs_total | 实际结束前累计唯一碰撞对数 |
| path_length | 实际结束前所有机器人的路程之和 |
| J、AUC | 实际结束前折扣原生团队奖励与其学习曲线积分/B，辅助指标 |
| coverage、distance | 实际结束时覆盖比例、每地标最近距离均值；成功回合coverage=1 |
| mean_coverage、tail_coverage | 实际变长轨迹内均值及后半均值，仅兼容诊断，不再表示完成后的保持能力 |
| unused_budget | 无法预留下一轮所余源步数，不隐藏 |
| *_se | 单个冻结模型的评价场景标准误，不是跨训练种子不确定性 |

截尾步数并非“假定失败在截止成功”；它是包含失败成本的统计量。累计碰撞和路径随任务长度变化，应连同成功率和步数解释。覆盖阈值严格<0.1，不要求一对一匹配。奖励是密集距离/碰撞，覆盖指标不变时J仍可能改善；不能把J改善当作首达成功改善。

train_J来自训练批实际奖励；批末未完成片段只记录已见奖励。train_value_target含训练截断bootstrap，因此不同于J。方向方法、作者GAE目标也不完全相同，不按该列排名。

## 2. 图像与检查点

overview.png为一张3×3总图：首达成功率、截尾完成步数、累计碰撞曲线；success_AUC、final J、分项成本；耗时、优化次数、拟合KL。transfer_overview.png合并目标规模结果，主看同N算法比较。

training_monitor.png每若干轮覆盖更新，独立成绩仅随评价节点更新。逐轮训练曲线不是独立评价，20轮滑动均值也不能替代原曲线。best按成功率、截尾步数、累计碰撞依次选取，只作诊断；主表与迁移均用final。

PPO每轮更新、no_checks直接接受是定义，不意味着安全。候选KL可能属于被拒绝策略，不能视为已提交策略变化。单种子不画跨种子置信带。

## 3. 网络与优化诊断

| 指标 | 用途及限制 |
|---|---|
| critic_mse、explained_variance | 本地为最后小批次；作者PPO为更新后整批原尺度。均非独立泛化误差 |
| author_stats.value_loss | 作者实际归一化、裁剪Huber损失，不能与原尺度MSE混淆 |
| policy_step_kl | 候选与旧策略的实际变化 |
| fit_kl_before/after、p95/max | 目标拟合残差，不能证明目标有收益 |
| direction_score | 独立方向任务的经验分数，正值才通过，不是真实方向误差 |
| return_difference | 旧/候选独立完整任务的实际J均值差，严格正值才接受 |
| ppo_kl、clip_fraction | 作者分支为更新后整批，local分支为最后小批次 |
| policy_entropy | 策略随机性，不等于有效探索 |

Critic图为symlog，避免早期大值把后期误差压成视觉上的0。变长数据padding不进入损失、归一化或诊断。碰撞或距离改善能提高回报，但是否更常完成任务需看success_rate。

## 4. 稳定性与下一步调参

稳定性脚本按first_arrival识别新口径：末30%预算内最后5个非final节点，成功率极差≤0.02、截尾完成步数极差≤任务上限2%（500步时为10步）。近似95%误差半径及final与末段差值也需满足；成功率≥0.9才称高平台。final用独立场景，单列核对。

这些阈值是开发诊断，不是收敛定理、等效检验或自动停止规则。成功率仍改善或首达步数继续减少时，不因预算到2000万就宣布收敛。低成功率平台应优先诊断；高成功率平台还需41/42种子复核。

| 现象 | 优先检查与实验 |
|---|---|
| 全部方法低成功率 | 任务边界、时间输入、末端价值、奖励、足够探索，再看预算 |
| 完整方法落后no_checks | 分项费用、方向/回报拒绝，补两项单模块消融 |
| 核心方法低平台 | 冻结旧Critic标签质量、MC/GAE单因素、方向epochs或学习率 |
| 方向大多被拒绝 | q边界比例、方向分数分布、有效样本量；不先放宽到总能通过 |
| 回报经常拒绝 | 完整任务J方差、eta和拟合KL；改变检查样本数须新配置 |
| KL很小但任务差 | 方向/目标是否改善，不能仅提高拟合轮数 |
| PPO波动 | 全批KL/clip、优势尺度、学习率/epochs，保留作者参考 |
| 评价误差太大 | 补评价精度，不用单个final点或GIF定排名 |

学习率、预算等候选只用源开发数据选；sampled和消融继承ours，不按目标N调参。涉及新的方向网络软更新、奖励或检查策略时，应作为明确机制实验，不同时混改多个因素。

旧continuing结果仍保留100步J和500步保持覆盖的原义，新first_arrival不能套用其stable_high判据。数据不足时报告不足，不从短程验收推断算法性能。
