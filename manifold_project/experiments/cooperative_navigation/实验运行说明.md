# 合作导航：实验运行说明

更新：2026-09-19。本页统一维护安装、当前实验命令、输出与恢复；研究问题见[实验设计](实验设计.md)，实现见[模块说明](模块说明.md)。

## 1. 环境与配置

命令在包含 `manifold_project` 的仓库根目录执行，并先激活要训练的 Python 环境。已有可用 PyTorch/CUDA 时，只补环境依赖：

```powershell
python -m pip install -r manifold_project/experiments/cooperative_navigation/requirements-environment.txt
```

完整依赖见 [requirements.txt](requirements.txt)；历史验收环境见[实现验收记录](实现验收记录.md)。`PackageNotFoundError: mpe2` 表示当前解释器缺少该包的安装元数据，应在同一个解释器下安装。

当前 `run_experiments.py` 按既有设置，在导入数值库前设置 `KMP_DUPLICATE_LIB_OK=TRUE`，不主动拒绝该变量。它允许重复OpenMP运行时继续执行，不能视为依赖冲突已修复；运行时变量会写入manifest。此次整理不改变该行为。

CUDA训练保留 `torch.use_deterministic_algorithms(True)`。入口在CUDA初始化前默认设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，保留用户显式设置，并将该变量写入manifest。它满足确定性矩阵运算的cuBLAS要求，不保证不同硬件或软件版本间逐位一致。[PyTorch说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)

另一台电脑尚未同步修复时，在同一个PowerShell窗口、启动Python前执行：

```powershell
$env:CUBLAS_WORKSPACE_CONFIG = ':4096:8'
```

然后重跑原命令；若原命令指定的输出目录已有失败记录，改用新的 `--output` 目录，或省略 `--output` 自动分配新编号。同步入口修复后源码指纹会变化，应新建套件，不修改旧manifest来绕过恢复检查。此设置与OpenMP环境变量用途不同，也无需关闭确定性检查。

```text
configs/
  source.json            # 共同环境与算法默认值
  smoke.json             # 链路验收
  pilot.json             # 初版开发默认值，非当前长预算方案
  formal.json            # 尚未冻结的正式模板
  label_alignment.json   # N-L标签对齐
  study_v3/
    reference.json       # 当前完整方法参考
    eta_0p3.json          # 单因素：目标步幅
    batch64.json          # 单因素：训练采样量
    gae.json              # 单因素：方向标签
    selected/            # 选参后生成，当前不预建
```

合并顺序为 source → profile → `--config` JSON → CLI；未知键报错，完整有效配置保存在manifest及各运行config。仅传 `--profile pilot` 仍使用初版默认预算；当前实验必须传下方配置。`--dry-run` 只打印计划，不训练或创建结果。

候选放在 `configs/study_v3/` 子目录；现有源码指纹只计入configs顶层JSON，候选的有效参数另由manifest保存。本次迁移保持四个JSON内容和训练源码不变，不改已有套件的版本记录。

## 2. 当前实验顺序

先开发ours → 补种子复核 → 同等资源调优PPO → 主比较与单模块消融 → 冻结正式协议 → 零样本迁移。完整方法与双检查消融的1000万步seed40参考均已完成，见[nav_04对照判断](results/nav_04_pilot_双检查消融判断.md)：双消融final J从-50.14提高到-40.43，覆盖从11.25%提高到28.25%，但稳定性未确认，记录训练耗时多约17%。已有两组不默认重跑。

后续平台诊断见该报告第6节：重新学习的方向在训练与独立轨迹上有明显表现差距，冻结策略也难以维持占位。优化上优先用短诊断检验MC/GAE标签与16/64回合采样的影响，再做匹配预算训练；不先单纯追加预算。N-A2/N-A3仍是缺失的模块对照，用来解释检查的净收益，无需等待它们完成才排查方向质量。只读诊断入口为 `python manifold_project/experiments/diagnose_navigation_direction.py`，默认额外19200团队步，仅打印结果，不改模型或已有成绩。

热启动/参数平滑的5条件短对照及独立种子90220复核均已完成，仍未确认胜出设置。下一步转为候选Actor真实回报配对评价，结果解释和唯一执行命令见[该报告第8节](results/nav_04_pilot_双检查消融判断.md#8-独立诊断种子90220复核尚无可直接采用的胜出设置)。诊断脚本支持 `--compare --candidate-episodes`；主训练尚未切换热启动/EMA，训练JSON不接受这些新键。

当前优先排查两项检查的瓶颈：在reference开发阶段提前加入同配置的N-A2、N-A3及N-A5诊断，分别去掉方向检查、回报接受/回退模块、两者共同去掉，形成四个条件。命令见下文。N-A5单列为联合消融，保留原单模块对照；单种子开发不替代选参后的多种子确认，也不改变完整方法定义。

### 2.1 完整方法的四个开发候选


统一新开发起点：Actor学习率3e-4、Critic学习率1e-3、方向学习率3e-4。Critic提速也用于后续PPO，满足本轮公共参数约定。它相对nav_02改变了学习率和评价密度，因此不能把旧结果与新结果的全部差异归因于预算。若需独立识别Critic提速效果，可另以同预算同评价设置将critic_lr恢复3e-4做对照，记作追加开发资源。

| 候选 | 相对新起点的变化 | 研究目的 |
|---|---|---|
| reference.json | eta=0.1、每轮16回合、MC标签 | 长预算与更快Critic下的完整方法参考 |
| eta_0p3.json | 只改eta=0.3，回退候选按既有规则减半 | 目标变化是否过小 |
| batch64.json | 只改每轮训练采样为64回合 | 减少方向估计噪声；同时记录增加的计算开销 |
| gae.json | 只改方向标签为GAE，lambda=0.95 | 检查MC标签方差是否限制学习；这是有偏标签变体，不默认继承精确方向解释 |

四候选均不移除检查，不组合调参。Actor拟合与方向epochs仍16，minibatch仍4回合。检查每批仍8回合，beta仍0.02，q_max仍1。后续可考虑direction_lr、check_episodes、q_max、共同学习率衰减或奖励尺度，但仅在当前诊断支持时增加新开发轮次，不立即做全参数网格。

每候选默认1000万团队步，先用种子40；评价21节点，每节点100回合（含final），源评价共21万团队步，另计成本。这是新预算下从头训练，不修改旧套件预算继续训练。所有候选设备必须一致，下面统一使用CUDA；需要CPU时所有命令一起改为cpu，CPU/GPU耗时不混比。

**参考组复现命令**：已完成的 `results/nav_03_pilot` 对应本配置的seed40、CUDA、1000万步。下面保留复现入口，不是新的待办；新代码与原训练版本不同，补实验时记录变更并核对可比性。

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --conditions ours --config manifold_project/experiments/cooperative_navigation/configs/study_v3/reference.json --device cuda --output manifold_project/experiments/cooperative_navigation/results/nav_v3_ours_reference_s40_10m --plot
```

**模块对照：一次补齐两个缺失的单检查消融**，与已完成reference保持相同种子、预算、设备及评价设置，记录训练实现和运行时设置差异：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-A2 N-A3 --conditions no_direction_check no_return_check --config manifold_project/experiments/cooperative_navigation/configs/study_v3/reference.json --device cuda --plot --plot-every 10
```

共两次训练，每次seed40、1000万源步；不包含已完成的ours/no_checks。下面保留各条件的独立入口和解释，与合并命令二选一执行。

**N-A2独立入口：**

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-A2 --conditions no_direction_check --config manifold_project/experiments/cooperative_navigation/configs/study_v3/reference.json --device cuda --plot
```

该命令只新增去方向检查条件，完整方法参考复用已有reference；保留方向学习、原eta和回报接受/回退模块。比较源J/AUC、覆盖、接受轮数及用途成本，不能仅以接受率提高宣布成功。去掉检查也改变同预算内训练与检查的交互分配，因此只能解释整个方向检查模块的收益与成本，不能直接证明某次检查误拒绝。额外诊断资源单独披露，不作为隐含的完整方法调参候选。

当前方向门槛为独立检查批上的 `mean(2*A*score - fisher) > 0`，不含eta，发生在候选拟合之前。步长候选检验的是通过方向检查后的更新幅度；小步长、低KL或单次通过检查均不保证任务回报改善。已有200万步去检查结果仍低覆盖，不预先认定删除检查就解决学习问题。若需判断误拒绝，应另设冻结旧策略、构造被拒方向候选并独立评价的诊断；现有N-D对方向拒绝轮次不构造候选，不能直接提供该反事实证据。

**回报检查同样提前做单模块对照**：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-A3 --conditions no_return_check --config manifold_project/experiments/cooperative_navigation/configs/study_v3/reference.json --device cuda --plot
```

该组保留方向检查、方向学习、首个候选的eta与Actor拟合，只移除回报接受/回退控制及其采样。它不同时去掉方向检查，也不同时改步长。当前回报检查对旧策略和候选各独立采8回合，均值差严格大于0才接受；不是带置信保证的真实改善检验。真实改善较小时，估计噪声既可能拒绝有效候选，也可能接受无效候选。原200万步seed40中完整方法有362次候选回报检查、200次拒绝；回退可能造成一轮多次检查，不能把200次误写为200轮，更不能都称为误拒绝。

三组首先检验整个模块在相同源交互预算下的实际收益与成本。若去回报检查更好，还需区分节省采样带来的训练机会与接受规则本身的影响。原结果去回报检查的final J有所提高，但覆盖从2.5%降至1.25%，不预设删除模块全面有益。只有独立候选评价才能判断具体更新的改善与退化；需要N-D时应在训练前统一指定审计计划，不能事后补造缺失候选。

**N-A5：同时去掉两项检查**，已完成于nav_04_pilot；下列仅作复现入口，当前无需重跑：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-A5 --conditions no_checks --config manifold_project/experiments/cooperative_navigation/configs/study_v3/reference.json --device cuda --plot --plot-every 10
```

`no_checks` 保留解析方向学习、Critic、原eta、Actor拟合和所有公共参数；不采两项检查数据，每轮直接采用首个数值有效的候选，不触发回报驱动的回退。NaN或非法概率仍报错。使用现有reference JSON，无需增加配置文件。默认每轮只有16个训练回合、1600团队步计入源预算，检查成本为0；方向学习和拟合的计算开销仍在。

若四组都尚未运行，可统一执行下面的去重命令；已有参考或单消融时只补缺失条件，不重复运行：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-A2 N-A3 N-A5 --config manifold_project/experiments/cooperative_navigation/configs/study_v3/reference.json --device cuda --plot --plot-every 10
```

去重后为ours、no_direction_check、no_return_check、no_checks，默认seed40共4次训练，每次1000万团队步。只补三种消融时在上述命令追加 `--conditions no_direction_check no_return_check no_checks`。所有结果须使用相同训练实现、配置和运行环境；不同版本的旧结果不能无说明地混入。原 `N-A`、`N-P`、`N-S1` 计划不自动加入N-A5，联合消融须显式指定；N-D审计范围仍为ours/no_return_check。

四组用于检验检查模块的整体收益及交互影响。联合去除后接受比例按定义接近100%，不能以此宣布成功；看同预算J/AUC、覆盖、碰撞、耗时和后期稳定性。即使联合去除最好，也不能仅据此证明检查误拒绝，因为节省检查成本同时带来更多训练更新。研究解释见实验设计N-A5。

完成检查模块诊断后，再运行三个单因素候选，保持相同预算与设备：

```powershell
foreach ($candidate in @('eta_0p3','batch64','gae')) {
    python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --conditions ours --config "manifold_project/experiments/cooperative_navigation/configs/study_v3/$candidate.json" --device cuda --output "manifold_project/experiments/cooperative_navigation/results/nav_v3_ours_${candidate}_s40_10m" --plot
    if ($LASTEXITCODE -ne 0) { throw "候选 $candidate 运行失败，先处理错误" }
}
```

如计算资源不足，可以先对四候选全部统一追加 `--budget 2000000` 做同预算筛选，再将参考和最佳候选扩到1000万；此时输出名中的10m也改为2m。不能把1000万参考的AUC与200万候选直接比较。长预算如果仍改善，可继续设计共同2000万预算实验，不能仅增加ours的正式预算而保留短预算PPO。

### 2.3 公共配置与PPO比较

选定ours的源配置后，生成完整的公共比较配置和四个PPO专属候选：

```powershell
python manifold_project/experiments/prepare_navigation_comparison.py --selected-suite "manifold_project/experiments/cooperative_navigation/results/实际选定的ours开发套件" --output-dir manifold_project/experiments/cooperative_navigation/configs/study_v3/selected
```

生成的matched.json从实际manifest继承有效设置，避免把命令覆盖的预算/设备/学习率遗漏。脚本不自动宣布候选最优，不冻结formal，不读取目标结果。

| 严格保持一致 | 允许不同并明确报告 |
|---|---|
| 源环境、奖励、观测历史、动作空间、gamma、beta、Actor结构/初始化、设备/精度 | ours方向目标与PPO代理目标 |
| 源交互总预算，ours检查采样计入预算 | 更新轮数因检查成本而不同 |
| Actor学习率3e-4、Critic学习率1e-3、训练采样批量、minibatch、Critic训练epochs | PPO Actor优化epochs与ours拟合epochs含义不同 |
| 独立评价场景、回合数、节点、训练种子和统计规则 | IPPO使用本地Critic，其余使用集中Critic |

eta和ppo_clip都控制策略变化，但不强制数值相同。PPO的熵奖励0.01、GAE及优势标准化是其原生设置，ours没有熵奖励；不能称全部损失一致。若要将差异归因于方向目标，再做N-L统一标签且关闭PPO优势标准化的控制实验，不能用整算法对比直接作唯一机制归因。

先做**共同参数控制比较**：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/study_v3/selected/matched.json --seeds 40 41 42 --experiments N-C --device cuda --plot
```

这提供matched条件下的结果；如果ours调过而PPO未获得同等搜索资源，不能声称各算法最佳配置下ours更强。为公平调优，MAPPO/IPPO各提供四候选：clip∈{0.1,0.2}×ppo_epochs∈{5,10}，保持公共学习率与批量不变。每个算法候选预算、初筛seed40、验证seed41/42与ours相同；已经跑过完全相同的配置可复用，不重复消耗预算。

```powershell
foreach ($clip in @('0.1','0.2')) {
    foreach ($epochs in @(5,10)) {
        python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config "manifold_project/experiments/cooperative_navigation/configs/study_v3/selected/ppo_clip${clip}_epochs${epochs}.json" --conditions mappo ippo --seeds 40 --device cuda --plot
        if ($LASTEXITCODE -ne 0) { throw 'PPO候选运行失败，先处理错误' }
    }
}
```

主方法各选定设置后再冻结同一正式预算、评价协议和种子100–109。formal配置的protocol_status只能在开发选择完成后改为frozen；当前文件保持candidate_not_frozen。如果预算继续增大，正式主比较和消融共同采用最终选定预算，不分别挑各算法最有利的终点。

### 2.4 单模块消融

N-A1替换方向二次项，N-A2去方向检查，N-A3去回报接受/回退模块；每次只改一个模块，全部继承所选ours参数。研究问题和归因边界见[实验设计第7节](实验设计.md#7-每个实验具体做什么)。

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/study_v3/selected/matched.json --seeds 40 41 42 --experiments N-A1 N-A2 N-A3 --device cuda --plot
```

该命令去重后只有ours、sampled、no_direction_check、no_return_check四个条件，共12次训练。若与主比较一起运行，可用 `--experiments N-C N-A1 N-A2 N-A3` 自动去重，六条件×三种子=18次，避免重复ours/sampled。fit_quarter单列为N-A4拟合预算敏感性，不能写成“删除Actor拟合模块”。不执行完全删除拟合的无更新变体来制造性能差距。

正式若要声称检查有逐次保护收益，应在训练前决定 `--audit`，保存独立候选供N-D评价；当前版本的检查仍是empirical，不提供安全保证。

### 2.5 训练过程监控

现在每个完成轮次都会打印累计源步及百分比、旧策略训练批回报 `train_J`、Critic最后小批次 `critic_mse`、接受/拒绝原因、该轮采样与优化秒数，以及最近独立评价的节点、回报、覆盖和距离。方向方法另打印方向分数、回报检查差、拟合KL和候选数；PPO打印KL与裁剪比例。未执行的检查显示 `-`。独立评价开始和完成均即时打印，避免把评价等待误认为训练卡住。

`--plot` 现在默认每10个完成轮次更新一次套件根目录的 `training_monitor.png`，初始评价、新评价节点和训练结束也会刷新。追加 `--plot-every 20` 改为每20轮；`--plot-every 0` 仅保留原最终汇总图。绘图间隔不改变训练配置或评价采样计划，默认不弹窗口。

总图含9个面板：训练回报及20轮滑动均值、独立评价回报、覆盖率、距离、Critic误差、KL、20轮更新比例、方向检查、回报检查。图像覆盖保存，不生成逐轮图片或新的JSON/JSONL。多条件套件只显示当前运行条件，标题标明条件和种子；完成后 `overview.png` 仍汇总全部条件。图片查看器若缓存旧内容，需要刷新或重新打开。

监控只用已有日志及内存记录，不额外采集评价回合。独立评价曲线仍按配置节点更新；当前1000万步配置通常每50万步一个节点，不能把最新评价值当成每轮重新评价。训练回报来自更新前旧策略的小样本训练批，不与独立源回报混为同一个指标。绘图耗时不包含在 `train_seconds` 中，完整作业墙钟会增加。

**已在运行的旧版训练**：在另一个PowerShell窗口运行下面命令，将路径替换为训练终端打印的实际套件目录，无需停止训练：

```powershell
python manifold_project/experiments/monitor_navigation.py --suite manifold_project/experiments/cooperative_navigation/results/实际套件目录 --watch --interval 30
```

该入口每30秒增量读取现有 `events.jsonl`，打印新提交轮次并覆盖 `live_monitor.png`，兼容此前不含新增监控字段的日志。不传 `--watch` 只生成一次；Ctrl+C只停止监控。它不读取模型、不检查训练源码指纹、不改变训练进程或采样，只写一张独立监控图；批次中途的数据不当作已提交轮次。建议同套件只启动一个外部监控进程。

正在运行的Python进程不会自动获得新的内置打印功能，外部监控窗口可以显示这些已有日志指标。同步代码后新建训练将启用内置监控；训练代码指纹已更新，旧套件恢复仍需原版本代码，不修改manifest绕过检查。

每回合开始先登记预算预留，结束记实际账目。中断后未提交的采样在恢复时单列 `interrupted_uncommitted`；最后一个未完成回合按整回合保守计费，最多高估 99 步，防止超预算。恢复一致性指正常轮次边界暂停，不把硬终止后额外消耗说成与连续训练一致。强制终止前未提交的计算/评价耗时无法完整追溯，正式作业应保留外部运行记录。
