# 合作导航：实验运行说明

更新：2026-09-22。顺序为旧模型首达诊断、新首达任务训练、稳定性复核、单模块消融与冻结迁移。任务定义见[实验设计](实验设计.md)，实测判断见[当前实验判断](results/当前实验判断.md)。

## 1. 路径与环境

在包含manifold_project的仓库目录执行，先激活已有PyTorch/CUDA的环境：

```powershell
$nav = 'manifold_project/experiments/cooperative_navigation'
python -m pip install -r "$nav/requirements-environment.txt"
```

其他工作目录请用绝对路径，例如 `$nav = 'D:/manifold/manifold/manifold_project/experiments/cooperative_navigation'`。可用 `Test-Path "$nav/configs/first_arrival/mc_20m.json"` 核对路径，不能省略配置绕过报错。

入口保留KMP_DUPLICATE_LIB_OK=TRUE，并在CUDA初始化前默认设置CUBLAS_WORKSPACE_CONFIG=:4096:8，不关闭确定性算法。实际环境变量写入manifest。无需安装作者仓库旧版Gym/PyTorch。

## 2. 已完成：旧模型首达诊断

旧持续任务MAPPO/IPPO曾各训练2000万步，已在相同200场景中补做首次全覆盖或500步截止的评价。旧训练产物随后按清理要求删除，诊断单独保存在：

`results/legacy_ppo_arrival_s40_h500/`

episodes.csv记录各场景，summary.csv汇总各模型，overview.png合为一张图，provenance.json合并保存原manifest、运行配置、训练汇总及文件摘要。该目录不是可恢复训练套件。原模型权重已删除，历史评价不能直接重跑，故不再保留指向已删除套件的启动命令。

500步成功率为MAPPO98.5%、IPPO97.5%。诊断保留旧Actor176维输入，不强加新时钟；不据单训练种子排名，也不将旧目标训练结果当作新协议重训成绩。

## 3. 从头训练新任务

共同规则为first_arrival、task_horizon=500、原生密集奖励、随机策略执行、共同源预算与评价场景。每轮训练配额train_episodes×horizon=16×100=1600个真实联合步；horizon=100不是任务截止。

以下是长训练命令，本次修改没有代为启动2000万步作业。追加--dry-run只检查计划；新建输出目录须为空。

### 3.1 作者MAPPO/IPPO

```powershell
python "$nav/run_experiments.py" --profile pilot --experiments N-C --conditions mappo ippo --config "$nav/configs/first_arrival/author_mpe_20m.json" --device cuda --output "$nav/results/arrival_20m_author_mpe_s40" --plot --plot-every 10
```

沿用已采用的作者MPE优化候选：Tanh、Actor/Critic学习率7e-4/7e-4、梯度裁剪10、价值系数1、10 epochs且每epoch一个完整批次。保留作者GAE、ValueNorm、价值裁剪、Huber及Categorical；隐藏宽度128。属于作者代码适配共同任务，非原论文场景成绩复现。

### 3.2 完整方法与双检查消融

```powershell
python "$nav/run_experiments.py" --profile pilot --experiments N-A5 --conditions ours no_checks --config "$nav/configs/first_arrival/mc_20m.json" --device cuda --output "$nav/results/arrival_20m_ours_checks_mc_s40" --plot --plot-every 10
```

两组共用Actor/Critic/方向学习率3e-4/1e-3/3e-4、方向与拟合各16 epochs、eta=.1、同一网络及标签。完整方法额外计入检查步数，故更新轮数少于no_checks。PPO保留作者优化设置，不能声称全部优化参数完全相同。

以上为4个任务，各2000万源步，共8000万。每50万源步评价1024场景、final也1024场景，含起点共41节点。单模型评价最多41×1024×500=20,992,000步，成功提前结束后实际成本减少，单独计账。评价可能明显耗时，[eval]期间没有训练轮次输出属正常现象。

### 3.3 标签诊断（需要时开展）

若MC核心方法仍学习较差，用同种子、仅替换direction_label进行诊断：

```powershell
python "$nav/run_experiments.py" --profile pilot --experiments N-A5 --conditions no_checks --config "$nav/configs/first_arrival/gae_20m.json" --device cuda --output "$nav/results/arrival_20m_no_checks_gae_s40" --plot --plot-every 10
```

MC名称沿用：完整任务为实际reward-to-go，批末未完成片段以冻结旧Critic补尾。GAE候选只改变方向标签，不改PPO基线。

## 4. 训练后评价、复核与消融

```powershell
$suite = "$nav/results/arrival_20m_author_mpe_s40"
python "$nav/../assess_navigation_stability.py" --suite "$suite"
python "$nav/evaluation/evaluate.py" --suite "$suite" --steps 500 --episodes 200
```

ours/no_checks套件同样执行。首先看success_rate、restricted_mean_steps、success_AUC和碰撞。2000万步不是收敛保证；已有final评价用于主表，额外200场景是另一组独立诊断。首达模型--steps必须等于其训练task_horizon，不能改变倒计时含义。

开发趋势明确后加--seeds 41 42并换新目录复核，选定唯一源开发配置，再冻结正式种子/预算。单模块消融不能被双检查消融代替：

```powershell
# 补MC参考对应的单模块组，复用已有同协议ours
python "$nav/run_experiments.py" --profile pilot --experiments N-A --conditions sampled no_direction_check no_return_check fit_quarter --config "$nav/configs/first_arrival/mc_20m.json" --device cuda --output "$nav/results/arrival_20m_single_ablations_mc_s40" --plot --plot-every 10

# 同版本源码下，对完成的主方法final做N=3/4/6/8冻结迁移
python "$nav/run_experiments.py" --resume-suite "$nav/results/arrival_20m_author_mpe_s40" --experiments N-T --plot
python "$nav/run_experiments.py" --resume-suite "$nav/results/arrival_20m_ours_checks_mc_s40" --experiments N-T --plot
```

选参改变后，消融必须继承选定ours，而非照抄旧候选。N-T只取ours/sampled/mappo/ippo；no_checks不默认作为主算法迁移。正式运行使用formal与冻结参数文件，seed40仅属开发。若需研究逐候选检查作用，必须训练前加--audit。

## 5. 恢复、监控与GIF

```powershell
python "$nav/run_experiments.py" --resume-suite "$nav/results/arrival_20m_author_mpe_s40" --experiments N-C --plot --plot-every 10
```

恢复不追加新配置/预算。源码、依赖或配置变化需原版本恢复或新实验，不修改manifest绕过检查；旧176维模型不能直接续接新177维任务。预算不足下一轮最大预留时停止并报告unused_budget。

每轮打印训练回报、误差、更新或拒绝及最近评价；每10轮或新评价后覆盖training_monitor.png。独立成绩只在原评价节点增加，不把训练批指标冒充评价。

```powershell
python "$nav/../visualize_navigation.py" --suite "$nav/results/arrival_20m_author_mpe_s40" --condition mappo --seed 40 --agents 4 --reset-seed 20260922 --action-seed 20260922 --steps 500 --output "$nav/results/arrival_20m_author_mpe_s40/mappo_arrival.gif"
```

新任务GIF在success/deadline停止，末帧显示结束原因。旧continuing模型仍按旧语义回放完整窗口，不能混淆。输出已存在时另选文件名。

## 6. 产物与配置

套件：manifest.json、status.json、3张源CSV、overview.png和覆盖更新的training_monitor.png。每个条件/种子：config.json、summary.json、一个events.jsonl、best.pt、final.pt；启用审计才增加快照，失败才增加failure.json。best按成功率、截尾步数、累计碰撞依次选择；主表和目标迁移固定用final。

configs/first_arrival包括author_mpe_20m.json、mc_20m.json、gae_20m.json。learning_20m与study_v3保留旧语义。基础source默认仍continuing，因此新任务必须显式传入first_arrival配置。
