# 合作导航：实验运行说明

更新：2026-09-20。本页统一维护安装、当前实验命令、输出与恢复；研究问题见[实验设计](实验设计.md)，实现见[模块说明](模块说明.md)。

当前默认和learning_20m配置采用 `task_mode=continuing`：100步是采样窗口，超时补入冻结旧Critic的末端价值，Actor/Critic不含期限时间；达到覆盖不终止。旧study_v3明确保留finite_horizon，仅供历史复现。新旧目标和输入维度不同，需新目录从头训练，不使用旧checkpoint或修改旧manifest续接。同步本次代码后，旧套件若要继续原任务，必须使用原软件快照。

## 1. 环境与配置

命令在包含 `manifold_project` 的仓库根目录执行，并先激活要训练的 Python 环境。已有可用 PyTorch/CUDA 时，只补环境依赖：

```powershell
python -m pip install -r manifold_project/experiments/cooperative_navigation/requirements-environment.txt
```

完整依赖见 [requirements.txt](requirements.txt)；历史验收环境见[实现验收记录](实现验收记录.md)。`PackageNotFoundError: mpe2` 表示当前解释器缺少该包的安装元数据，应在同一个解释器下安装。

如果读取 `configs/learning_20m/mc.json` 报FileNotFoundError，先核对当前工作目录与配置文件是否同步。`--config`的相对路径以终端工作目录为基准，不以run_experiments.py所在目录为基准。另一台电脑的脚本若位于 `D:\manifold\manifold\manifold_project\experiments\cooperative_navigation`，可以直接使用绝对路径：

```powershell
$nav = 'D:\manifold\manifold\manifold_project\experiments\cooperative_navigation'
Test-Path -LiteralPath "$nav/configs/learning_20m/mc.json"
python "$nav/run_experiments.py" --profile pilot --experiments N-C N-A5 --conditions mappo ippo no_checks --config "$nav/configs/learning_20m/mc.json" --output "$nav/results/learning_20m_continuing_mc_s40" --plot --plot-every 10
```

先确认Test-Path返回True再运行Python；False表示该绝对位置缺少文件，需要同步整个 `configs/learning_20m/`（mc.json与gae.json），或把$nav改为实际目录。本机仓库若位于 `D:\manifold\manifold_project`，$nav相应少一层manifold。不能省略--config来绕过错误，否则会退回pilot默认预算。该错误发生在创建结果目录之前，这次失败无需清理结果。

当前 `run_experiments.py` 按既有设置，在导入数值库前设置 `KMP_DUPLICATE_LIB_OK=TRUE`，不主动拒绝该变量。它允许重复OpenMP运行时继续执行，不能视为依赖冲突已修复；运行时变量会写入manifest。此次整理不改变该行为。

CUDA训练保留 `torch.use_deterministic_algorithms(True)`。入口在CUDA初始化前默认设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，保留用户显式设置，并将该变量写入manifest。它满足确定性矩阵运算的cuBLAS要求，不保证不同硬件或软件版本间逐位一致。[PyTorch说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)

另一台电脑尚未同步修复时，在同一个PowerShell窗口、启动Python前执行：

```powershell
$env:CUBLAS_WORKSPACE_CONFIG = ':4096:8'
```

然后重跑原命令；若原命令指定的输出目录已有失败记录，改用新的 `--output` 目录，或省略 `--output` 自动分配新编号。同步入口修复后源码指纹会变化，应新建套件，不修改旧manifest来绕过恢复检查。此设置与OpenMP环境变量用途不同，也无需关闭确定性检查。

```text
configs/
  source.json            # 共同环境与算法默认值
  smoke.json             # 链路验收
  pilot.json             # 初版开发默认值，非当前长预算方案
  formal.json            # 尚未冻结的正式模板
  label_alignment.json   # N-L标签对齐
  learning_20m/
    mc.json              # 当前2000万步：MAPPO/IPPO/no_checks MC
    gae.json             # 当前2000万步：no_checks GAE
  study_v3/
    reference.json       # 旧有限时域完整方法参考
    eta_0p3.json          # 单因素：目标步幅
    batch64.json          # 单因素：训练采样量
    gae.json              # 单因素：方向标签
  continuing_selected/   # 后续从新协议选参生成，当前不预建
```

合并顺序为 source → profile → `--config` JSON → CLI；未知键报错，完整有效配置保存在manifest及各运行config。仅传 `--profile pilot` 仍使用初版默认预算；当前实验必须传下方配置。`--dry-run` 只打印计划，不训练或创建结果。

历史候选保留在 `configs/study_v3/`，现已显式标记finite_horizon；新持续任务配置位于learning_20m。源码指纹计入configs顶层JSON，子目录覆盖后的完整有效参数由manifest保存。旧数据和版本记录不改写。

## 2. 当前实验顺序

当前先做统一配置下的长预算训练能力对照（MAPPO、IPPO、no_checks MC、no_checks GAE）→ 改善并复核我们的核心更新 → 配合检查模块验证完整ours → 正式公平比较与零样本迁移。旧200万步PPO尚未确认收敛，不能以其终点作为最终能力判断。本轮每组先训练2000万步，再结合预定稳定性指标决定是否继续。

旧有限时域结果、模型和详细判断已按用户要求清理；当前结果状态见[结果索引](results/README.md)与[当前实验判断](results/当前实验判断.md)。新持续任务尚无训练结果，本轮从头运行。

当前阶段暂缓扩大检查消融和迁移实验。两个no_checks版本用于检验核心更新的学习能力，不把其成绩记为完整ours的提升；MAPPO/IPPO保留各自算法设置，公共环境、奖励、Actor结构、学习率、训练批量、种子、设备与评价协议一致。

### 长预算训练：当前待办

每组按新持续任务从头训练2000万源团队步，seed40、CUDA。两份有效配置只差direction_label=mc/gae；其中mc名称沿用，但实际为带末端bootstrap的多步回报。方向epochs仍16、eta=0.1，Actor/Critic学习率分别为3e-4/1e-3。MAPPO/IPPO的策略标签仍为GAE，保持优势标准化和熵项。四组共享超时处理和176维Actor输入，都不采接受检查轨迹，每轮1600步、每组12500轮；预算是环境步，不是回合数。

先运行MAPPO、IPPO及我们的MC核心版本，共三次训练：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-C N-A5 --conditions mappo ippo no_checks --config manifold_project/experiments/cooperative_navigation/configs/learning_20m/mc.json --output manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40 --plot --plot-every 10
```

再运行我们的GAE核心版本，共一次训练：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-A5 --conditions no_checks --config manifold_project/experiments/cooperative_navigation/configs/learning_20m/gae.json --output manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_gae_s40 --plot --plot-every 10
```

两条命令合计8000万源训练步。每50万步评价一次，加起点共41节点；每节点及final各1024回合，每组另计4198400评价团队步，四组合计16793600步，不混入训练预算。增加评价样本是为了分辨后期变化；这仍不是跨训练种子证据。每轮打印指标，每10轮覆盖监控图，仅保留best/final模型。启动前可加 `--dry-run` 核对计划，已完成目录不会被覆盖。

两套完成后分别检查稳定性：

```powershell
python manifold_project/experiments/assess_navigation_stability.py --suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40
python manifold_project/experiments/assess_navigation_stability.py --suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_gae_s40
```

预定诊断取最后5个非final节点（1750万–1950万步），回报极差≤2、覆盖极差≤2个百分点、距离极差≤0.02，且各点近似95%误差半径不超过对应阈值；另核对独立final的一致性。高覆盖还需final覆盖≥80%；低覆盖的平台只称训练停滞，不能写成训练效果良好。详见[指标说明](训练指标与调参说明.md)。

2000万步是本阶段预算，不保证收敛。若PPO到终点仍持续提高，记录“尚未收敛”，下一阶段优先安排延长训练（可统一扩至4000万步），保留共同预算截面的比较；若仅评价精度不足，先补评价；若低覆盖且稳定，则改进训练机制，不能无限追加同一配置。预算扩展需单独的续训协议；现有run_experiments的resume只恢复原预算，不能编辑旧manifest冒充扩展。正式结论仍需独立训练种子复核。

如中断，用对应套件恢复，不能再次用原新建命令覆盖输出：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40 --experiments N-C N-A5 --plot --plot-every 10
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_gae_s40 --experiments N-A5 --plot --plot-every 10
```

训练完成后，再对同一final模型做持续占位评价：

```powershell
python manifold_project/experiments/cooperative_navigation/evaluation/evaluate.py --suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40 --steps 500 --episodes 200
python manifold_project/experiments/cooperative_navigation/evaluation/evaluate.py --suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_gae_s40 --steps 500 --episodes 200
```

每个模型200段×500步，段内不reset，每个套件仅新增long_rollout_h500.csv。四个模型共新增40万评价团队步，独立于训练预算。比较mean_reward、mean_coverage、tail_coverage和tail_all_covered；500步J不能与100步J直接作差。重复评价需另指定--output，不覆盖已有结果。

若要看具体执行，可在既有动画命令后加 `--steps 500`，仅支持新持续任务模型。例如：

```powershell
python manifold_project/experiments/visualize_navigation.py --suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40 --condition no_checks --seed 40 --steps 500 --output navigation_continuing_500.gif
```

动画只是单场景说明，不能替代上述统计。后续正式比较必须在新持续协议上重新冻结。

### 2.1 后续开发与诊断

旧有限时域的训练、方向epochs续训及详细判断已清理，相应的复现、补跑与默认父模型命令一并移出本页。study_v3四份配置仅作历史参数参考，不作为当前实验入口。

后续方向诊断使用diagnose_navigation_direction.py并显式提供--checkpoint；分支续训使用continue_navigation.py，且新建分支也必须提供--checkpoint。两者都不再默认寻找已删除的模型。先完成当前持续任务训练，再根据新结果决定是否使用这些工具。

下列公共比较和单模块消融属于后续阶段，必须从新持续协议的有效manifest生成配置，不能借用旧有限时域模型或成绩。

### 2.2 公共配置与PPO比较

选定ours的源配置后，生成完整的公共比较配置和四个PPO专属候选：

```powershell
python manifold_project/experiments/prepare_navigation_comparison.py --selected-suite "manifold_project/experiments/cooperative_navigation/results/实际选定的ours开发套件" --output-dir manifold_project/experiments/cooperative_navigation/configs/continuing_selected
```

生成的matched.json从实际manifest继承有效设置，避免把命令覆盖的预算/设备/学习率遗漏。脚本不自动宣布候选最优，不冻结formal，不读取目标结果。

| 严格保持一致 | 允许不同并明确报告 |
|---|---|
| 源环境、奖励、观测历史、动作空间、gamma、beta、Actor结构/初始化、设备/精度 | ours方向目标与PPO代理目标 |
| 源交互总预算，ours检查采样计入预算 | 更新轮数因检查成本而不同 |
| Actor学习率3e-4、Critic学习率1e-3、训练采样批量、minibatch、Critic训练epochs | PPO Actor优化epochs与ours拟合epochs含义不同 |
| 独立评价场景、回合数、节点、训练种子和统计规则 | IPPO使用本地Critic，其余使用集中Critic |

eta和ppo_clip都控制策略变化，但不强制数值相同。PPO的熵奖励0.01、GAE及优势标准化是其原生设置，ours没有熵奖励；不能称全部损失一致。若要将差异归因于方向目标，再做N-L统一标签且关闭PPO优势标准化的控制实验，不能用整算法对比直接作唯一机制归因。

先做**共同参数控制比较**：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/continuing_selected/matched.json --seeds 40 41 42 --experiments N-C --device cuda --plot
```

这提供matched条件下的结果；如果ours调过而PPO未获得同等搜索资源，不能声称各算法最佳配置下ours更强。为公平调优，MAPPO/IPPO各提供四候选：clip∈{0.1,0.2}×ppo_epochs∈{5,10}，保持公共学习率与批量不变。每个算法候选预算、初筛seed40、验证seed41/42与ours相同；已经跑过完全相同的配置可复用，不重复消耗预算。

```powershell
foreach ($clip in @('0.1','0.2')) {
    foreach ($epochs in @(5,10)) {
        python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config "manifold_project/experiments/cooperative_navigation/configs/continuing_selected/ppo_clip${clip}_epochs${epochs}.json" --conditions mappo ippo --seeds 40 --device cuda --plot
        if ($LASTEXITCODE -ne 0) { throw 'PPO候选运行失败，先处理错误' }
    }
}
```

主方法各选定设置后再冻结同一正式预算、评价协议和种子100–109。formal配置的protocol_status只能在开发选择完成后改为frozen；当前文件保持candidate_not_frozen。如果预算继续增大，正式主比较和消融共同采用最终选定预算，不分别挑各算法最有利的终点。

### 2.3 单模块消融

N-A1替换方向二次项，N-A2去方向检查，N-A3去回报接受/回退模块；每次只改一个模块，全部继承所选ours参数。研究问题和归因边界见[实验设计第7节](实验设计.md#7-每个实验具体做什么)。

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/continuing_selected/matched.json --seeds 40 41 42 --experiments N-A1 N-A2 N-A3 --device cuda --plot
```

该命令去重后只有ours、sampled、no_direction_check、no_return_check四个条件，共12次训练。若与主比较一起运行，可用 `--experiments N-C N-A1 N-A2 N-A3` 自动去重，六条件×三种子=18次，避免重复ours/sampled。fit_quarter单列为N-A4拟合预算敏感性，不能写成“删除Actor拟合模块”。不执行完全删除拟合的无更新变体来制造性能差距。

正式若要声称检查有逐次保护收益，应在训练前决定 `--audit`，保存独立候选供N-D评价；当前版本的检查仍是empirical，不提供安全保证。

### 2.4 训练过程监控

现在每个完成轮次都会打印累计源步及百分比、旧策略训练批回报 `train_J`、Critic最后小批次 `critic_mse`、接受/拒绝原因、该轮采样与优化秒数，以及最近独立评价的节点、回报、覆盖和距离。方向方法另打印方向分数、回报检查差、拟合KL和候选数；PPO打印KL与裁剪比例。未执行的检查显示 `-`。独立评价开始和完成均即时打印，避免把评价等待误认为训练卡住。

`--plot` 现在默认每10个完成轮次更新一次套件根目录的 `training_monitor.png`，初始评价、新评价节点和训练结束也会刷新。追加 `--plot-every 20` 改为每20轮；`--plot-every 0` 仅保留原最终汇总图。绘图间隔不改变训练配置或评价采样计划，默认不弹窗口。

总图含9个面板：训练回报及20轮滑动均值、独立评价回报、覆盖率、距离、Critic误差、KL、20轮更新比例、方向检查、回报检查。图像覆盖保存，不生成逐轮图片或新的JSON/JSONL。多条件套件只显示当前运行条件，标题标明条件和种子；完成后 `overview.png` 仍汇总全部条件。图片查看器若缓存旧内容，需要刷新或重新打开。

监控只用已有日志及内存记录，不额外采集评价回合。独立评价曲线仍按配置节点更新；当前1000万步配置通常每50万步一个节点，不能把最新评价值当成每轮重新评价。训练回报来自更新前旧策略的小样本训练批，不与独立源回报混为同一个指标。绘图耗时不包含在 `train_seconds` 中，完整作业墙钟会增加。

**已在运行的旧版训练**：在另一个PowerShell窗口运行下面命令，将路径替换为训练终端打印的实际套件目录，无需停止训练：

```powershell
python manifold_project/experiments/monitor_navigation.py --suite manifold_project/experiments/cooperative_navigation/results/实际套件目录 --watch --interval 30
```

该入口每30秒增量读取现有 `events.jsonl`，打印新提交轮次并覆盖 `live_monitor.png`，兼容此前不含新增监控字段的日志。不传 `--watch` 只生成一次；Ctrl+C只停止监控。它不读取模型、不检查训练源码指纹、不改变训练进程或采样，只写一张独立监控图；批次中途的数据不当作已提交轮次。建议同套件只启动一个外部监控进程。

正在运行的Python进程不会自动获得新的内置打印功能，外部监控窗口可以显示这些已有日志指标。同步代码后新建训练将启用内置监控；训练代码指纹已更新，旧套件恢复仍需原版本代码，不修改manifest绕过检查。

## 3. 正式实验与可选诊断

正式参数尚未冻结。完成源开发后，将选定公共参数及各PPO专属设置写入正式覆盖配置，明确 `protocol_status=frozen`、种子100–109和正式评价设置；不要直接沿用开发配置中的seed40。正式模板仅供检查，未冻结时入口拒绝实际训练。

主比较及三项单模块消融使用 `--experiments N-C N-A1 N-A2 N-A3`：去重后六条件，共60次正式训练。N-A4拟合预算敏感性、N-A5联合消融各另加10次，加入一项共70次，两项均加入共80次。正式是否纳入应在冻结前确定；`N-A`别名会包含N-A4，但不包含N-A5。

冻结迁移复用实际完成套件，替换下面的目录名：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/实际正式套件 --experiments N-T --plot
```

## 6. 恢复与重画


```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40 --experiments N-C N-A5 --plot
python manifold_project/experiments/cooperative_navigation/analyze.py manifold_project/experiments/cooperative_navigation/results/learning_20m_continuing_mc_s40
```

恢复不附加新 profile/config/budget/device，源码与主要依赖版本必须一致；完成运行跳过，未完成的从最后完成轮次恢复。修复实现后新建套件。`analyze.py` 仅重建 CSV/图，不训练采样。

每回合开始先登记预算预留，结束记实际账目。中断后未提交的采样在恢复时单列 `interrupted_uncommitted`；最后一个未完成回合按整回合保守计费，最多高估 99 步，防止超预算。恢复一致性指正常轮次边界暂停，不把硬终止后额外消耗说成与连续训练一致。强制终止前未提交的计算/评价耗时无法完整追溯，正式作业应保留外部运行记录。

先看 status 是否失败，再看 overview 和 training_summary。统计表的 `kind=paired_difference` 表示 ours 减对照；J/AUC 越大越好，距离/碰撞越小越好。详见[训练指标与调参说明](训练指标与调参说明.md)。
