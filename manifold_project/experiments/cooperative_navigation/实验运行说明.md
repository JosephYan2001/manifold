# 合作导航：实验运行说明

更新：2026-09-18。命令从 `D:\manifold` 执行；参数语义见[实验设计](实验设计.md)，实现细节见[模块说明](模块说明.md)。

## 1. 环境与安装

**另一台电脑已有可用 PyTorch/CUDA 时**，在运行实验的同一个 Python 环境中补齐环境依赖即可。若报错来自 `D:\anaconda3\Lib`，可在 PowerShell 执行这一条命令（无需切换到项目目录）：

```powershell
& 'D:\anaconda3\python.exe' -m pip install "mpe2==1.1.1" "pettingzoo==1.27.0" "pygame-ce==2.5.8" "gymnasium==1.2.0" "scipy==1.16.0" "matplotlib==3.10.3"
```

`PackageNotFoundError: mpe2` 表示当前解释器找不到 MPE2 的安装元数据，报错发生在记录依赖版本时，尚未开始训练。这条命令不安装或替换 PyTorch/CUDA；上述依赖兼容现有 NumPy 1.26.4，无需强制升级到 NumPy 2。安装后用同一个解释器重跑实验；若实际使用的是其他 Conda 环境，请替换解释器路径。相同依赖也保存在 [requirements-environment.txt](requirements-environment.txt)，便于使用 `python -m pip install -r` 安装。

以下为原验收环境的完整安装方式：

本地验收使用 `D:\python_exercise_program\dqn+pso\.conda\python.exe`，Python 3.11.13、PyTorch 2.7.1+cu118。MPE2、PettingZoo、pygame-ce 已安装到该环境，不是系统默认 Python。

```powershell
conda activate 'D:\python_exercise_program\dqn+pso\.conda'
python -m pip install -r manifold_project/experiments/cooperative_navigation/requirements.txt
python -m unittest discover -s manifold_project/experiments/cooperative_navigation/tests -v
```

也可以用 `& 'D:\python_exercise_program\dqn+pso\.conda\python.exe'` 替换 `python`。依赖文件锁定主要包，Torch CUDA 构建需与驱动匹配；实际版本、设备、解释器路径会写入 manifest。默认 CPU 单线程；`--device cuda` 可切换设备，但 CPU 验收不等于 CUDA 确定性验收。

本次 CPU 运行没有使用 `KMP_DUPLICATE_LIB_OK`，脚本也不以该变量忽略重复 OpenMP。若其他环境仍报 Error #15，应先核查 NumPy/Torch/MKL 是否混用了不同安装来源；指定编译器不是唯一解决方式。优先在独立环境中整理依赖，不通过改算法绕过包冲突。

## 2. 执行顺序与命令

### 2.1 接口和七条件 smoke

```powershell
python -m unittest discover -s manifold_project/experiments/cooperative_navigation/tests -v
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile smoke --experiments N-C N-A --plot
```

smoke 使用 seed=0、每条件 16000 团队步，0/50%/100% 节点各评价 2 回合，只验证链路。若同时检验迁移与审计：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile smoke --experiments N-C N-A N-T --audit --plot
```

### 2.2 开发 pilot

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-C N-A --dry-run
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-C N-A --plot
```

第一条不创建结果。实际 pilot 为 7 条件×3 种子（40/41/42），每次 200000 团队步，总上限 420 万源步。源评价 6 个节点、每节点 20 回合，成本另记。默认不做目标迁移，避免用目标结果调参。

| 标识 | 训练或评价内容 |
|---|---|
| N-C | ours、sampled、mappo、ippo |
| N-A | 全部消融，与 N-C 参考条件去重 |
| N-A1 / N-A2 / N-A3 / N-A4 | ours 对 sampled / no_direction_check / no_return_check / fit_quarter |
| N-P / N-S1 | 七条件别名，预算仍由 profile 决定 |
| N-T | 四主方法 final 冻结迁移；单独使用必须指定已有套件 |
| N-D / --audit | 训练前固定候选保存计划，训练后做独立审计 |
| N-L | 独立套件的四方法标签对齐 |

### 2.3 正式训练与迁移

200 万正式预算仍为候选。未冻结时 formal 允许 dry-run，但拒绝实际训练。完成 pilot 后，建立自己的 `configs/formal_frozen.json`，写入选定预算与参数，例如：

```json
{"protocol_status":"frozen","budget":2000000,"actor_lr":0.0003,"direction_lr":0.0003,"critic_lr":0.0003,"eta":0.1}
```

该文件需要参数选择完成后创建，仓库不预先假装冻结；另保留调参选择记录。随后：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile formal --config manifold_project/experiments/cooperative_navigation/configs/formal_frozen.json --experiments N-C N-A --plot
```

正式为 70 次训练。预先决定需要 N-D 时，在这条命令加 `--audit`。迁移复用实际完成套件，例如：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/nav_03_formal --experiments N-T --plot
```

路径中的编号必须换成实际输出目录。N=4 复用 final 源评价，N=3/6/8 各 200 回合，不训练、不挑 best、不更新观测统计。正式源前 20 个节点各 100 回合，final 200 回合。重复执行迁移/审计会复用已完成评价，不重新采集这些回合。

### 2.4 可选标签对齐

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --experiments N-L --plot
```

默认四方法统一 GAE，并关闭 PPO 优势标准化，新套件名带 `_labels`。全部 MC 的覆盖配置必须同时包含 `direction_label=mc`、`ppo_label=mc`、`ppo_normalize_advantage=false`。N-L 带自定义 config 时需要明确标签键，不暗中叠加默认对齐文件；不能与主实验混在同一套件。

## 3. 每轮训练的组织

1. 固定配置、源码指纹和依赖；初始化 Actor/critic，独立评价初始策略。
2. 预留完整一轮最低预算；旧策略采完整回合，冻结旧 critic 生成标签，再更新供下一轮使用的 critic。
3. 方向方法执行：方向重初始化与拟合 → 独立方向检查 → 从旧 Actor 拟合候选 → 两侧独立回报检查 → 接受、半步回退一次或保留旧策略。MAPPO/IPPO 执行 PPO 更新。
4. 共同预算节点使用不超过节点的最近提交策略；跨过节点时评价更新前副本。完成轮次覆盖 final，best 只作开发诊断。
5. 剩余预算不足一轮时停止，报告未用量，以最后提交策略完成 B 节点评价。
6. 汇总种子表、统计表、曲线和一张 3×3 总览；按预定配置继续迁移/审计。

独立源评价不能用于候选接受。回报检查只是 empirical 规则，不具有 Hoeffding 保证。

## 4. 文件布局

```text
results/nav_XX_pilot/
  manifest.json                 # 完整配置、任务表、源码哈希、依赖和设备
  status.json                   # 各条件/种子状态
  training_results.csv          # 每个训练种子一行
  training_summary.csv          # 条件统计及配对差值
  learning_curves.csv            # 每种子、预算节点一行
  overview.png                  # 一张 3×3 总览（--plot）
  ours/seed_40/
    config.json
    summary.json
    events.jsonl                # 合并日志
    checkpoints/best.pt
    checkpoints/final.pt
```

正常子运行仅 5 个文件。PT 包含网络、优化器、计数、随机状态、评价与轮次统计，不保存逐轮 checkpoint 或全部 rollout。best 可能受评价噪声影响，论文和迁移使用 final。

迁移增加 `transfer_results.csv`、`transfer_summary.csv`、`transfer_overview.png`；审计增加相关运行各一个 `audit_snapshots.pt` 和套件 `audit_results.csv`。失败额外保留 `failure.json`，恢复后不抹掉失败历史。统一日志由 stream/record 区分采样、优化、检查、评价与提交，默认没有逐梯度文件。

## 5. 恢复与重画

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/nav_02_pilot --experiments N-C N-A --plot
python manifold_project/experiments/cooperative_navigation/analyze.py manifold_project/experiments/cooperative_navigation/results/nav_02_pilot
```

恢复不附加新 profile/config/budget/device，源码与主要依赖版本必须一致；完成运行跳过，未完成的从最后完成轮次恢复。修复实现后新建套件。`analyze.py` 仅重建 CSV/图，不训练采样。

每回合开始先登记预算预留，结束记实际账目。中断后未提交的采样在恢复时单列 `interrupted_uncommitted`；最后一个未完成回合按整回合保守计费，最多高估 99 步，防止超预算。恢复一致性指正常轮次边界暂停，不把硬终止后额外消耗说成与连续训练一致。强制终止前未提交的计算/评价耗时无法完整追溯，正式作业应保留外部运行记录。

先看 status 是否失败，再看 overview 和 training_summary。统计表的 `kind=paired_difference` 表示 ours 减对照；J/AUC 越大越好，距离/碰撞越小越好。详见[训练指标与调参说明](训练指标与调参说明.md)。
