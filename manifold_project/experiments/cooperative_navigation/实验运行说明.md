# 合作导航：运行与结果说明

本页只说明现有程序；新实验组和启动条件统一见[总实验方案](../../docs/策略流形研究设计.实验方案.md)。当前协议尚未冻结，不以旧长预算配置作为下一步训练清单。实现边界见[实现说明](实现说明.md)。

## 配置预检

在包含 `manifold_project` 的仓库目录执行。已有 PyTorch/CUDA 环境所需的环境包列在 `requirements-environment.txt`。

```powershell
$nav = 'manifold_project/experiments/cooperative_navigation'
python "$nav/run_experiments.py" --help
python "$nav/run_experiments.py" --profile pilot --experiments N-C --conditions ours --config "$nav/configs/first_arrival/mc_20m.json" --dry-run
```

`--dry-run` 仅展开配置，不训练、不创建结果目录。总方案的 `R1-N*` 是研究编号，当前 CLI 的 `N-C`、`N-A*` 等编号不能直接替换为它们。

| 配置 | 实际用途 |
|---|---|
| `source.json` 及 smoke/pilot/formal | 入口基础配置，默认持续任务及最近 2 地标 |
| `label_alignment.json` | 现有 N-L 标签对齐路径与回归检查 |
| `first_arrival/*.json` | 首达任务、500 步截止、固定步数训练配额的接口检查 |
| `learning_20m/*.json`、`study_v3/reference.json` | 较早任务与作者 PPO 适配的回归参考 |

配置按 source、profile、覆盖 JSON 合并，再应用方法覆盖项；判断某次运行应读取展开配置和 manifest。保留配置中的预算、种子和学习率不是新研究计划。Actor、Critic、方向网络学习率分别由 `actor_lr`、`critic_lr`、`direction_lr` 控制；不能只改一个字段便认为各方法已完成公平对齐。

入口保留 `KMP_DUPLICATE_LIB_OK=TRUE` 兼容设置，并在 CUDA 初始化前默认设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`。前者允许重复 OpenMP 运行库加载，不表示依赖冲突已消除。

## 恢复、评价与回放

以下 `$suite` 必须替换为真实存在且保留 manifest 和检查点的目录。旧结果已清理，示例不依赖旧套件。

```powershell
$suite = "$nav/results/<实际套件目录>"
python "$nav/run_experiments.py" --resume-suite "$suite" --experiments N-C --plot --plot-every 10
python "$nav/evaluation/evaluate.py" --suite "$suite" --steps 500 --episodes 200
python "$nav/run_experiments.py" --resume-suite "$suite" --experiments N-T --plot
python "$nav/../visualize_navigation.py" --suite "$suite" --condition mappo --seed 40 --agents 4 --reset-seed 20260922 --action-seed 20260922 --steps 500 --output "$suite/trajectory.gif"
```

恢复使用原任务、配置、源码及依赖，不追加新预算或新配置。任务、输入或奖励改变后应建立新实验。`N-T` 复用 final 作经验迁移评价，不证明运输定理前提；目标结果不得用于选参、选模型或更新归一化。

首达模型的 `--steps` 须等于训练时的任务期限，条件和训练种子须与检查点匹配。GIF 在成功或截止时结束，只展示一个执行过程。

`--plot --plot-every 10` 每隔指定轮次及新评价后覆盖监控图。`[eval]` 表示正在独立评价，期间可能没有训练轮次输出，评价费用另计。

现有实现的单元测试入口如下；通过不代表新研究协议验收完成：

```powershell
python -m unittest discover -s manifold_project/experiments/cooperative_navigation/tests -v
```

## 输出与读表

套件保存 manifest/status、训练 CSV 和总图；每个条件/种子保存配置、汇总、一个 `events.jsonl` 及 best/final。启用审计会额外保存快照。best 仅作诊断，现有主表和迁移用 final；总方案中进一步精简的产物协议尚待实现。

先读 `training_results.csv`（条件与训练种子），再读 `learning_curves.csv`（预算节点），最后看 `training_summary.csv`（跨训练种子汇总及配对差）。训练种子数与评价场景数不同，单种子不能给出跨训练随机性的置信结论。

| 指标 | 含义及读法 |
|---|---|
| J、AUC | 终止前折扣团队奖励及按源预算归一化的曲线积分；不能代替成功率 |
| success_rate、success_AUC | 首达成功比例及其预算曲线积分 |
| restricted_mean_steps | 成功计首达步数，失败计任务截止步数；与成功率共同报告 |
| success_steps_mean | 仅成功场景的步数，不能单独排名 |
| success_by_100/200/500 | 不超过任务期限的相应阈值累计成功率 |
| collision_pairs_total、path_length | 终止前碰撞与路程，解释时考虑成功/失败和任务长度 |
| coverage、distance | 终止时的覆盖比例与每目标最近距离均值 |
| mean_coverage、tail_coverage | 终止前轨迹诊断，不表示成功后持续覆盖 |
| evaluation_steps、source_steps、unused_budget | 独立评价费用、源训练/检查费用、无法再启动一轮的剩余预算 |
| *_se | 单个模型跨评价场景的误差，不是跨训练种子误差 |

训练批 `train_J` 可能只含片段已见奖励，`train_value_target` 可含 Critic 补尾，二者不能与独立完整任务 J 混合排名。密集奖励改善也不必然提升首达成功率。

| 机制指标 | 解释限制 |
|---|---|
| direction_score、return_difference | 独立样本上的经验方向分数、候选与旧策略 J 差，不是默认的高概率改善保证 |
| fit_kl_before/after、p95/max | 样本拟合残差，不能视为全支持一致误差界 |
| policy_step_kl | 候选更新幅度；拒绝的候选不是实际提交的更新 |
| critic_mse、explained_variance | 对当前标签的拟合诊断，接近零不证明价值正确 |
| author_stats.value_loss | 作者归一化/裁剪后的价值损失，不能直接与原尺度 MSE 比较 |
| ppo_kl、clip_fraction、policy_entropy | PPO 更新与随机性诊断，不能仅靠参数数值相同判定公平 |

`overview.png` 为汇总图，`training_monitor.png` 为周期覆盖的监控图。平滑曲线、平台期、单种子胜负和 GIF 都不替代独立统计评价。

选参只能使用源开发数据；改动标签、网络、软更新、奖励或检查规则时，应明确改变的模块。单模块消融分别进行，联合去除检查只作补充。具体参数、预算和正式停止规则统一由总方案及其冻结配置维护。
