# 合作导航：实验运行说明

更新：2026-09-20。本文统一维护安装、执行命令、结果与恢复。研究问题见[实验设计](实验设计.md)，实现差异见[模块说明](模块说明.md)，指标见[训练指标与调参说明](训练指标与调参说明.md)。

当前MAPPO/IPPO均直接调用作者固定提交de66d7a4的代码，默认 `mappo_backend=author`、`ippo_backend=author`。两者共用Actor结构、GAE、ValueNorm、价值裁剪与Huber loss；MAPPO的Critic读集中状态，IPPO的Critic读各机器人自己的本地历史。176维Actor输入在3/4/6/8人环境保持兼容。

任务采用continuing：100步为采样窗口，超时使用reset前最终状态或历史补入价值；达到覆盖不终止。原生奖励不变，独立评价只统计实际奖励。旧有限时域模型和旧本地PPO不能续训成新作者版；已经完成且任务、算法及参数一致的作者MAPPO结果可以保留。源码变化后的断点恢复必须使用原代码快照，不能修改manifest绕过检查。

## 1. 环境与配置

命令在包含 `manifold_project` 的仓库根目录执行，并先激活训练用Python环境：

```powershell
$nav = 'manifold_project/experiments/cooperative_navigation'
```

如果从其他工作目录启动，把 `$nav` 换成实际绝对路径。例如另一台电脑可用 `D:\manifold\manifold\manifold_project\experiments\cooperative_navigation`。`--config` 的相对路径以终端工作目录为准。FileNotFoundError时先运行 `Test-Path -LiteralPath "$nav/configs/learning_20m/mc.json"`；不要省略配置文件来绕过，否则会退回pilot的旧默认预算。

已有可用PyTorch/CUDA时，只需补充环境依赖，并同步整个项目（包括vendor/mappo）：

```powershell
python -m pip install -r "$nav/requirements-environment.txt"
```

无需安装作者仓库的旧版PyTorch、Gym或WandB。完整依赖见[requirements.txt](requirements.txt)，工程验收见[实现验收记录](实现验收记录.md)。PackageNotFoundError:mpe2表示当前解释器缺少该包元数据，应在同一解释器安装。

入口在数值库导入前保留 `KMP_DUPLICATE_LIB_OK=TRUE`；它是既有兼容设置，不代表重复OpenMP依赖已消除。CUDA入口默认设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，保留用户显式值。源码未同步的终端可在启动Python前设置 `$env:CUBLAS_WORKSPACE_CONFIG=':4096:8'`。两项变量均写入manifest，不需关闭确定性算法。

```text
configs/
  source.json            # 共同环境、作者MAPPO/IPPO与方向方法默认参数
  smoke.json             # 接口验收
  pilot.json             # 通用开发预算；当前长训练必须另传learning_20m
  formal.json            # 尚未冻结的正式模板
  label_alignment.json   # N-L：两种PPO均显式local，仅作标签控制
  learning_20m/
    mc.json              # 两种作者PPO，以及no_checks多步回报的公共开发参数
    gae.json             # 与mc只差direction_label，用于no_checks GAE
  study_v3/              # 旧finite_horizon参数参考，不作为当前训练入口
  continuing_selected/   # 后续根据有效源开发结果生成，不预建
```

合并顺序：source → profile → --config → CLI。有效配置写入manifest和各子运行config；`--dry-run`只打印计划，不创建结果。共同作者PPO的价值开关为 `ppo_value_normalization`、`ppo_value_clipping`、`ppo_huber_loss`，默认均true。旧覆盖文件中的mappo前缀别名可读取，但新结果只使用ppo前缀。

## 2. 当前实验顺序

当前只执行下面四组能力筛查，再改进并验证完整ours，最后扩展消融、独立种子与冻结迁移。no_checks不是完整方法，其成绩不记为完整ours的成绩。

| 套件 | 条件 | 源步预算 | 作用 |
|---|---|---:|---|
| learning_20m_author_ppo_s40 | 作者mappo、作者ippo | 各2000万 | 建立PPO学习能力基线 |
| learning_20m_no_checks_mc_s40 | no_checks，多步回报标签 | 2000万 | 检验方向学习＋Actor拟合 |
| learning_20m_no_checks_gae_s40 | no_checks，GAE标签 | 2000万 | 检验方向标签的影响 |

统一seed40、CUDA、Actor/Critic学习率3e-4/1e-3、16个100步窗口/轮，每轮1600源团队步，每组12500轮。检查采样均为0；方向epochs=16、eta=.1，作者PPO epochs=10。MC名称沿用，实际为带末端bootstrap的多步回报；两种作者PPO均始终使用GAE和λ-return，不受direction_label影响。

按顺序运行以下三条命令，共四次训练：

```powershell
# 1. 作者MAPPO和IPPO
python "$nav/run_experiments.py" --profile pilot --experiments N-C --conditions mappo ippo --config "$nav/configs/learning_20m/mc.json" --device cuda --output "$nav/results/learning_20m_author_ppo_s40" --plot --plot-every 10

# 2. 我们的核心版本：多步回报
python "$nav/run_experiments.py" --profile pilot --experiments N-A5 --conditions no_checks --config "$nav/configs/learning_20m/mc.json" --device cuda --output "$nav/results/learning_20m_no_checks_mc_s40" --plot --plot-every 10

# 3. 我们的核心版本：GAE
python "$nav/run_experiments.py" --profile pilot --experiments N-A5 --conditions no_checks --config "$nav/configs/learning_20m/gae.json" --device cuda --output "$nav/results/learning_20m_no_checks_gae_s40" --plot --plot-every 10
```

单独运行某个PPO时，将第一条的 `--conditions mappo ippo` 改为 `--conditions mappo` 或 `--conditions ippo`，并使用对应的新目录。不要先单独训练完成后又执行双算法命令重复同一配置；已完成的有效作者MAPPO可复用，此时只补IPPO。

四组合计8000万源步。每50万步评价1024回合，加起点共41节点，每组另计4198400评价团队步。每轮打印指标，每10轮覆盖training_monitor.png，检查点仅best/final。2000万步不是收敛保证；末段仍上升时记录未收敛，低覆盖平台也不能称训练成功。

完成后统一做源稳定性检查和500步持续覆盖评价：

```powershell
$suites = @('learning_20m_author_ppo_s40', 'learning_20m_no_checks_mc_s40', 'learning_20m_no_checks_gae_s40')
foreach ($suite in $suites) {
    python "$nav/../assess_navigation_stability.py" --suite "$nav/results/$suite"
    if ($LASTEXITCODE -ne 0) { throw "稳定性检查失败：$suite" }
    python "$nav/evaluation/evaluate.py" --suite "$nav/results/$suite" --steps 500 --episodes 200
    if ($LASTEXITCODE -ne 0) { throw "长窗口评价失败：$suite" }
}
```

每个模型评价200段×500步，段内不reset、不训练、不调用Critic；四模型共40万额外评价步。每个套件增加一个long_rollout_h500.csv，关注mean_reward、mean_coverage、tail_coverage和tail_all_covered。500步J与100步J不同，不直接作差；重复评价需另选--output，不覆盖已有结果。

预定源稳定性诊断使用1750万–1950万的最后5个非final节点：回报极差≤2、覆盖极差≤2个百分点、距离极差≤.02，并检查各点评价误差和独立final。若仍提升，再安排独立记录的预算扩展；现有resume只能恢复原预算，不能通过改旧manifest延长。

中断恢复使用原套件和原实验编号：

```powershell
python "$nav/run_experiments.py" --resume-suite "$nav/results/learning_20m_author_ppo_s40" --experiments N-C --plot --plot-every 10
python "$nav/run_experiments.py" --resume-suite "$nav/results/learning_20m_no_checks_mc_s40" --experiments N-A5 --plot --plot-every 10
python "$nav/run_experiments.py" --resume-suite "$nav/results/learning_20m_no_checks_gae_s40" --experiments N-A5 --plot --plot-every 10
```

恢复不再传--config、--device、--profile等新参数。作者ValueNorm统计和优化器一起恢复。已经完成的任务会跳过；非空目录不能用新建命令覆盖。

查看作者IPPO的具体行为，例如：

```powershell
python "$nav/../visualize_navigation.py" --suite "$nav/results/learning_20m_author_ppo_s40" --condition ippo --seed 40 --steps 500 --output "$nav/results/learning_20m_author_ppo_s40/ippo_500.gif"
```

把condition换成mappo可查看MAPPO，并使用不同GIF名称。动画只说明单场景行为，不能替代统计。当前阶段先判断源训练能力，目标规模数据不用于调参；后续正式N-T命令见第3节。

### 2.1 后续开发与诊断

旧有限时域的训练、方向epochs续训及详细判断已清理，相应的复现、补跑与默认父模型命令一并移出本页。study_v3四份配置仅作历史参数参考，不作为当前实验入口。

后续方向诊断使用diagnose_navigation_direction.py并显式提供--checkpoint；分支续训使用continue_navigation.py，且新建分支也必须提供--checkpoint。两者都不再默认寻找已删除的模型。先完成当前持续任务训练，再根据新结果决定是否使用这些工具。

下列公共比较和单模块消融属于后续阶段，必须从新持续协议的有效manifest生成配置，不能借用旧有限时域模型或成绩。

### 2.2 公共配置与PPO比较

选定ours的源配置后，生成完整的公共比较配置和四个PPO专属候选：

```powershell
python manifold_project/experiments/prepare_navigation_comparison.py --selected-suite "manifold_project/experiments/cooperative_navigation/results/实际选定的ours开发套件" --output-dir manifold_project/experiments/cooperative_navigation/configs/continuing_selected
```

生成的matched.json从实际manifest继承有效设置，避免把命令覆盖的预算/设备/学习率遗漏。脚本不自动宣布候选最优，不冻结formal，不读取目标结果。

| 严格保持一致 | 允许不同并明确报告 |
|---|---|
| 源环境、奖励、观测历史、动作空间、gamma、隐藏层宽度、设备/精度 | 两种作者PPO保留ReLU、LayerNorm、正交初始化、无beta混合；损失按作者公式 |
| 源交互总预算，ours检查采样计入预算 | 更新轮数因检查成本而不同 |
| Actor学习率3e-4、Critic学习率1e-3、训练采样批量、小批次样本量 | 两种作者PPO按agent样本打乱，Actor/Critic均由ppo_epochs控制；本地分支按窗口分批，Critic由critic_epochs控制 |
| 独立评价场景、回合数、节点、训练种子和统计规则 | IPPO使用本地Critic，其余使用集中Critic |

eta和ppo_clip都控制策略变化，但不强制数值相同。两种作者PPO共同保留GAE、优势标准化、ValueNorm、价值裁剪和Huber loss，Critic拟合λ-return；方向方法的Critic拟合多步回报。价值选项通过ppo_value_normalization/ppo_value_clipping/ppo_huber_loss共同设置。若要将差异归因于方向目标，另做两种backend均为local的N-L控制实验，不能用整算法对比直接作唯一机制归因。

先做**共同参数控制比较**：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/continuing_selected/matched.json --seeds 40 41 42 --experiments N-C --device cuda --plot
```

这提供matched条件下的结果；如果ours调过而PPO未获得同等搜索资源，不能声称各算法最佳配置下ours更强。为公平调优，MAPPO/IPPO各提供四候选：clip∈{0.1,0.2}×ppo_epochs∈{5,10}，保持公共学习率与批量不变。每个算法候选预算、初筛seed40、验证seed41/42与ours相同；已经跑过完全相同的配置可复用，不重复消耗预算。

```powershell
foreach ($clip in @('0.1','0.2')) {
    foreach ($epochs in @(5,10)) {
        python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config "manifold_project/experiments/cooperative_navigation/configs/continuing_selected/ppo_clip${clip}_epochs${epochs}.json" --conditions mappo ippo --seeds 40 --device cuda --plot
        if ($LASTEXITCODE -ne 0) { throw 'PPO候选运行失败，先处理错误' }
    }
}
```

主方法各选定设置后再冻结同一正式预算、评价协议和种子100–109。formal配置的protocol_status只能在开发选择完成后改为frozen；当前文件保持candidate_not_frozen。如果预算继续增大，正式主比较和消融共同采用最终选定预算，不分别挑各算法最有利的终点。

### 2.3 单模块消融

N-A1替换方向二次项，N-A2去方向检查，N-A3去回报接受/回退模块；每次只改一个模块，全部继承所选ours参数。研究问题和归因边界见[实验设计第7节](实验设计.md#7-每个实验具体做什么)。

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile pilot --config manifold_project/experiments/cooperative_navigation/configs/continuing_selected/matched.json --seeds 40 41 42 --experiments N-A1 N-A2 N-A3 --device cuda --plot
```

该命令去重后只有ours、sampled、no_direction_check、no_return_check四个条件，共12次训练。若与主比较一起运行，可用 `--experiments N-C N-A1 N-A2 N-A3` 自动去重，六条件×三种子=18次，避免重复ours/sampled。fit_quarter单列为N-A4拟合预算敏感性，不能写成“删除Actor拟合模块”。不执行完全删除拟合的无更新变体来制造性能差距。

正式若要声称检查有逐次保护收益，应在训练前决定 `--audit`，保存独立候选供N-D评价；当前版本的检查仍是empirical，不提供安全保证。

### 2.4 训练过程监控

每个完成轮次打印累计源步及百分比、旧策略训练批回报train_J、critic_mse、接受/拒绝原因、更新秒数和最近独立评价。两种作者PPO的critic_mse是更新后整批、反归一化到原尺度的误差，PPO KL和裁剪比例也为更新后整批统计；本地分支仍是最后优化小批次，详见指标说明。方向方法另打印方向分数、回报检查差、拟合KL和候选数。未执行检查显示 `-`，独立评价开始和完成即时打印。

`--plot` 现在默认每10个完成轮次更新一次套件根目录的 `training_monitor.png`，初始评价、新评价节点和训练结束也会刷新。追加 `--plot-every 20` 改为每20轮；`--plot-every 0` 仅保留原最终汇总图。绘图间隔不改变训练配置或评价采样计划，默认不弹窗口。

总图含9个面板：训练回报及20轮滑动均值、独立评价回报、覆盖率、距离、Critic误差、KL、20轮更新比例、方向检查、回报检查。图像覆盖保存，不生成逐轮图片或新的JSON/JSONL。多条件套件只显示当前运行条件，标题标明条件和种子；完成后 `overview.png` 仍汇总全部条件。图片查看器若缓存旧内容，需要刷新或重新打开。

监控只用已有日志及内存记录，不额外采集评价回合。当前2000万步配置每50万步一个评价节点，不能把最新评价值当成每轮重新评价。训练回报来自更新前旧策略的小样本训练批，不与独立源回报混为同一个指标。绘图耗时不包含在train_seconds中，完整作业墙钟会增加。

**已在运行的旧版训练**：在另一个PowerShell窗口运行下面命令，将路径替换为训练终端打印的实际套件目录，无需停止训练：

```powershell
python manifold_project/experiments/monitor_navigation.py --suite manifold_project/experiments/cooperative_navigation/results/实际套件目录 --watch --interval 30
```

该入口每30秒增量读取现有 `events.jsonl`，打印新提交轮次并覆盖 `live_monitor.png`，兼容此前不含新增监控字段的日志。不传 `--watch` 只生成一次；Ctrl+C只停止监控。它不读取模型、不检查训练源码指纹、不改变训练进程或采样，只写一张独立监控图；批次中途的数据不当作已提交轮次。建议同套件只启动一个外部监控进程。

正在运行的Python进程不会自动获得新的内置打印功能，外部监控窗口可以显示这些已有日志指标。同步代码后新建训练将启用内置监控；训练代码指纹已更新，旧套件恢复仍需原版本代码，不修改manifest绕过检查。

## 3. 正式实验与可选诊断

正式参数尚未冻结。完成源开发后，将选定公共参数及各PPO专属设置写入正式覆盖配置，明确 `protocol_status=frozen`、种子100–109和正式评价设置；不要直接沿用开发配置中的seed40。正式模板仅供检查，未冻结时入口拒绝实际训练。

主比较及三项单模块消融使用 `--experiments N-C N-A1 N-A2 N-A3`：去重后六条件，共60次正式训练。N-A4拟合预算敏感性、N-A5联合消融各另加10次，加入一项共70次，两项均加入共80次。正式是否纳入应在冻结前确定；`N-A`别名会包含N-A4，但不包含N-A5。

冻结迁移复用实际完成套件，替换下面的目录名：

```powershell
python manifold_project/experiments/cooperative_navigation/run_experiments.py --resume-suite manifold_project/experiments/cooperative_navigation/results/实际正式套件 --experiments N-T --plot
```

四主方法使用final Actor；N=4复用源final，N=3/6/8各200回合，不训练、不挑best、不更新观测统计。源码和依赖需满足恢复检查。

若要声称逐次保护收益，在训练前确定--audit候选保存计划，后续用N-D独立审计。N-L为本地实现的标签控制组，默认配置已设mappo_backend=local、ippo_backend=local、统一GAE并关闭优势标准化。自定义N-L配置也必须明确上述两项backend和标签设置；不能与其他实验编号混用，不能称为作者PPO主基线。实验定义和成本见[实验设计](实验设计.md)。

## 4. 接口验收与任务动画

仅在需要验证环境或实现时运行smoke，不将它列为每次长训练的前置任务：

```powershell
python -m unittest discover -s manifold_project/experiments/cooperative_navigation/tests -v
python manifold_project/experiments/cooperative_navigation/run_experiments.py --profile smoke --experiments N-C N-A N-T --audit --plot
```



`--plot` 只生成统计图。任务动画使用仓库根目录下的独立入口，先用随机动作认识环境：

```powershell
python manifold_project/experiments/visualize_navigation.py --random --output navigation_random.gif
```

播放已完成训练的 final 策略（把实际套件目录替换为自己的路径）：

```powershell
python manifold_project/experiments/visualize_navigation.py --suite manifold_project/experiments/cooperative_navigation/results/实际套件目录 --condition ours --seed 40 --output navigation_ours.gif
```

`--condition` 可选套件中的 sampled/mappo/ippo 或消融，`--seed` 是训练种子（pilot 为 40/41/42，正式为 100–109）。追加 `--agents 6` 可查看冻结策略在六人场景的执行；`--reset-seed` 改变初始场景，`--action-seed` 控制动作采样，`--fps` 仅改变动画速度。追加 `--show` 会在 GIF 保存后打开播放窗口；默认只生成 GIF，重复运行需另选文件名。

动画使用原 MPE2 动力学及相同历史输入、随机策略动作采样，彩色圆为机器人（圆半径对应碰撞尺寸）、叉号为地标、细线为轨迹，上方显示步数、当前覆盖率和碰撞对数。这是根据真实物理状态绘制的示意动画，不是训练时录像；加载 final 后重新执行一个回合，不更新模型。随机策略演示不代表已训练性能，单条轨迹也不替代正式多种子评价。

工具位于 experiments/visualize_navigation.py，不更改导航训练代码指纹，也不改套件的评价结果。它复用已安装的 NumPy、Torch、MPE2、Matplotlib 和 Pillow；如果当前终端需要 OpenMP 环境变量，播放时同样保留设置。仅加载自己生成且可信的 checkpoint。指定模型所属训练任务须已完成。

## 6. 恢复与重画


```powershell
python "$nav/analyze.py" "$nav/results/learning_20m_author_ppo_s40"
```

恢复不附加新 profile/config/budget/device，源码与主要依赖版本必须一致；完成运行跳过，未完成的从最后完成轮次恢复。修复实现后新建套件。`analyze.py` 仅重建 CSV/图，不训练采样。

每回合开始先登记预算预留，结束记实际账目。中断后未提交的采样在恢复时单列 `interrupted_uncommitted`；最后一个未完成回合按整回合保守计费，最多高估 99 步，防止超预算。恢复一致性指正常轮次边界暂停，不把硬终止后额外消耗说成与连续训练一致。强制终止前未提交的计算/评价耗时无法完整追溯，正式作业应保留外部运行记录。

先看 status 是否失败，再看 overview 和 training_summary。统计表的 `kind=paired_difference` 表示 ours 减对照；J/AUC 越大越好，距离/碰撞越小越好。详见[训练指标与调参说明](训练指标与调参说明.md)。
