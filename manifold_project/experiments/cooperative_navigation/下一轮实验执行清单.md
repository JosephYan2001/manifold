## 2. 第一批只做三组 AN

| 编号 | 方法与设置 | 对应问题 |
|---|---|---|
| A0 | AN，16 回合，方向 16 epoch | 当前源码基线 |
| A1 | AN，16 回合，方向 64 epoch | 同样数据上多优化方向，是否改善学习？ |
| A2 | AN，64 回合，方向 16 epoch | 更大训练批次、较少策略更新轮数，是否改善总预算内学习？ |

共同保持 Actor 拟合 16 epoch、Critic 10 epoch、相同小批次配置、同一网络和任务协议；方向和回报检查关闭。每组 seed 40、预算 200 万源步，最终评价 20 场景。

`direction_steps` 在应用适配器中表示 epoch，并非优化器更新次数。当前每小批 2 回合：A0 每轮方向优化约 128 次，A1 约 512 次，A2 约 512 次。A2 同时改变 Critic/Actor 的每轮样本与更新次数、标签质量和更新频率，属于整批采样敏感性实验，不能单独证明方向估计的纯样本量效应。

A1 若改善，支持现有方向优化预算不足；A2 若改善，支持增加批量值得进一步研究。任何单种子改善都需后续复验。独立固定策略的样本量 × 优化次数机制实验需要补入口，不可将这三组冒充为该机制实验。

## 3. 第一批命令

在已能运行原导航训练的 Python/CUDA 环境中执行。命令从仓库根目录运行。单 GPU 按顺序执行，每组使用新目录，当前入口不能在已有目录上自动续训。

```powershell
Set-Location D:\manifold
$cfg = "manifold_project/experiments/configs/navigation"
$out = "manifold_project/experiments/results/navigation_diagnosis_20261010_2m_s40_v1"

# A0：当前代码 AN 基线
python -m manifold_project.experiments --experiments N-C --profile pilot --methods AN --config "$cfg/no_checks.json" --budget 2000000 --seeds 40 --device cuda --output "$out/an_base" --plot --plot-every 5 --allow-duplicate-openmp

# A1：只增加方向优化 epoch，16 → 64
python -m manifold_project.experiments --experiments N-C --profile pilot --methods AN --config "$cfg/diagnosis/direction_epochs64.json" --budget 2000000 --seeds 40 --device cuda --output "$out/an_direction64" --plot --plot-every 5 --allow-duplicate-openmp

# A2：每轮采样 episode 数量，16 → 64
python -m manifold_project.experiments --experiments N-C --profile pilot --methods AN --config "$cfg/diagnosis/batch64.json" --budget 2000000 --seeds 40 --device cuda --output "$out/an_batch64" --plot --plot-every 5 --allow-duplicate-openmp
```

可给任何命令追加 `--dry-run` 只检查解析配置。不要使用 `--sample-sizes 64` 改导航 batch：该参数用于有限固定基点实验；导航应改 `batch_episodes`。`--fit-steps` 也不是这里的方向训练 epoch 参数。

本轮每组从头训练，在预算节点观察趋势；无成功时同时看源评价回报、覆盖、距离及策略熵，不能只按成功率删掉失败运行。三组总声明源预算为 600 万步，最终报告另计。

## 4. 第二批按结果选择，不立即全跑

如果优化/批量对照仍不能解释问题，做轻量实体网络对照。使用 `N-C` 与 `relation_layers=0`，保留现有按动作和类型加权读取、8 帧历史，避免 `N-R` 默认附带的目标规模评价。

先补当前代码完整网络 MAPPO，然后运行两个轻量版本；与 A0 组成方法 × 网络的四格比较。

```powershell
# 当前代码完整网络 MAPPO 基线；正式算法或网络比较时运行
python -m manifold_project.experiments --experiments N-C --profile pilot --methods MAPPO-E --config "$cfg/no_checks.json" --budget 2000000 --seeds 40 --device cuda --output "$out/mappo_base" --plot --plot-every 5 --allow-duplicate-openmp

# 第二批：轻量网络 AN 与 MAPPO，入口按顺序各运行一次
```

轻量网络仅删除关系层，仍使用可学习实体权重；不是原始特征直接求和。网络对照先用原基线优化/采样设置，不同时叠加 A1/A2 改动。第二批总声明源预算另外为 600 万步。

## 5. 暂缓的实验与决策

| 项目 | 当前处理 |
|---|---|
| 固定旧 Actor/Critic，样本量 × 优化器更新次数 | 需要新增固定策略诊断入口；没有现成训练命令 |
| 导航同 KL 下的指数目标/拟合 Actor/PPO | 需要新增目标策略执行、统一 KL 与同数据 PPO 对照；不能用成对 `finite.probes` 替代 |
| 卡尔曼/EMA 方向递推 | 先确认方差问题，再设计与相同样本量累积估计的比较 |
| 直接运行 N-F 补历史方向诊断 | 旧运行 `save_fit_diagnostics=false`，不能事后恢复未保存方向；现有 FitProbe 也不含上述完整同 KL 比较 |
| SA 无检查消融 | 先修复 method 与检查 condition 混用的问题 |
| 跨规模、仓库与大规模扩种子 | 源学习获得稳定结果后再做 |

第一批读取 `training.csv` 的源步数、独立监控、策略熵、方向/拟合指标，`summary.json` 的计算与模块成本，以及 `final_evaluation/evaluation_episodes.csv` 的最终场景结果。AN/PPO 日志中的 KL 与解释方差计算口径不同，不能直接把数值排序解释为方向准确度排序。

若 A1/A2 有改善，保留原基线与有希望的候选，使用相同预算补 seed 41、42（新输出目录），再决定是否采用。若两组均无改善，优先补固定策略诊断，区分标签误差、方向估计和 Actor 实现；网络对照作为另一条解释路径。最终正式比较应冻结代码及参数，并使用独立确认种子。
