## 1. 论文出发点的核对

[最初归档稿](../../docs/archive/最初设想_旧理论路线.md)研究单源冻结策略在未见系统结构中的性能保证，零样本迁移是其主要动机，但性能保证也不等于算法排名保证。

现行[理论主稿](../../docs/策略流形研究设计.CTDE本地策略改进版.md)第 1.1、1.5 节将核心定位为固定本地信息下的方向估计、共享 Actor 实现和方向运输；第 4.9 节仅建立冻结 Actor 附近的一轮方向运输结论，第 8 章明确没有证明一般多步跨规模优势。现行[实验方案](../../docs/策略流形研究设计.实验方案.md)的 E4 同时要求考察方向偏移与最终策略表现，但 pair 第 3.6 节具体安排了方向机制核验，最终策略跨规模比较主要落在导航和仓库。

因此，不能说“理论已经保证我们的算法迁移更优，只差实验验证”。如果论文希望保留零样本部署作为应用动机，必须加入最终冻结策略评价；如果进一步主张优于其他算法，必须由公平的目标任务比较支持。pair 中的 P-M3 不能替代这项评价。

## 2. 先明确当前 pair 能检验什么

令 p_x 为类型 x 的概率，m_x=E[a|x]，a∈{−1,+1}。代码中的精确团队回报为

\[
J_e(\pi)=n_e\left[\sum_x p_x b_x m_x+\frac{\rho}{2}\sum_{x,y}p_xp_y C_{xy}m_xm_y\right].
\]

因此仅改变人数时，固定策略的人均回报 J/n 不变；团队总回报 J 随人数成比例变化。这对所有采用相同本地类型策略的比较算法成立，不是 ours 特有的泛化性质。

当前 b=(−0.2,0.3)，C=[[1,−0.5],[−0.5,1]]，beta=0.02，所以 m_x∈[−0.98,0.98]。对任意类型组成、任意非负交互强度，m_0=−0.98、m_1=+0.98 同时最大化每个局部项和每个加权交互项：同类型项是正系数平方，异类型项的负系数偏好相反符号。对应动作 1 概率为 (0.01,0.99)。这给出了当前策略概率约束闭包上的共同最优策略；有限 logits 的 MLP 通常只能逼近这个上确界。

原 P-M3 的目标只改变人数、类型组成或非负交互强度，因此源和目标共享这一最优策略。方向可以在同一非最优冻结策略处发生漂移，而各任务的最优策略仍然相同，这两点并不矛盾。

这限制了新增比较的解释力：ours、sampled 和消融已逼近共同最优平台，预期难以显示有实际意义的差距；PG 的差距可能主要反映源训练尚未达到同一平台。以上为奖励结构推导，不是新增目标评价的观察结果。

## 3. 是否做：做一项轻量补充，但不作为优势主证据

建议复用现有模型做 P-T，把“方向机制核验”和“最终策略部署评价”补齐。它不需要重新训练，也不需要新增 Monte Carlo 回合，能精确检查接口一致性、目标性能和源终点差异如何传递。

论文中将其定位为控制实验或附录结果。不能承诺其会展示算法迁移优势，也不应为了获得优势而事后改变目标、换 checkpoint 或缩小源预算。零样本性能优越性的主要实证任务仍是导航/仓库的冻结策略比较。

## 4. P-T 的固定协议

| 项目 | 规定 |
|---|---|
| 源结果 | results/suite_09_论文比较与消融_10种子；每方法相同源预算 262144 |
| 方法 | 主表 ours、sampled、PG；补充表 no_direction_check、no_return_check、fit_quarter |
| 种子 | 原确认种子 100–109，全部使用，不筛选 |
| 模型 | 每次训练的 checkpoints/final.json；不用 best，不按目标结果选择 |
| 冻结范围 | Actor 权重、beta、输入映射及推理规则；不重训、不微调、不更新统计量、不在目标执行方向优化 |
| 策略 | 保留训练概率分布的随机策略；精确积分该分布，不改为贪心动作 |
| 源参照 | N=4、p=(0.6,0.4)、rho=0.7 |
| 人数控制 | N=2/6/8，其他参数保持源值 |
| 组成变化 | p=(0.3,0.7)/(0.9,0.1)，N=4、rho=0.7 |
| 强度变化 | rho=0/0.35/1.4，N=4、p=(0.6,0.4) |
| 评价量 | 精确团队回报 J、人均回报 J/N、目标约束最优人均差距 (J*−J)/N |
| 策略诊断 | 保存两类型动作 1 概率，判断是否已学得同一策略；记录模型哈希和配置 |
| 总量 | 6 方法×10 种子×9 配置=540 条精确评价，其中 60 条为源参照，480 条为目标评价 |

目标上界由上述共同最优策略计算，同时以四个概率边界顶点进行数值交叉核对。这个 oracle 只用于评价，不进入训练、选模或接受检查，不另训练“目标最优算法”。

统计以训练 seed 为单位：给出方法均值和 ours−对照的同种子配对差异及 95% bootstrap 区间。每个目标分别报告，注明逐比较区间未做多重比较校正。不要将同一模型的 9 个环境结果算成 9 个独立种子；精确评价没有额外环境采样误差，但训练种子仍有变异。先报告差异量级，不将机器精度附近的小差异写成实用优势。

目标之间主看人均回报与各自最优差距；不要直接平均不同人数的团队总回报。也不建议以 J_target/J_source 当作迁移保持率：组成和交互强度改变了奖励尺度与最优值，该比率混入任务变化。逐目标同时展示源差距与目标差距，不能由目标领先单独归因于更强的迁移机制。

## 5. 输出与判读

建议仅新增一个语义目录 results/suite_12_零样本迁移_10种子，保存一个 manifest.json（输入哈希、目标配置与统计协议）、一个 records.csv、一个 summary.csv 和一张 overview.png。不复制 checkpoint，不生成逐目标 JSON/JSONL。图内汇总人数控制、组成变化、强度变化和策略概率；主表与消融在同图中区分。

执行前保存评价协议与输入模型哈希，执行后统一解释全部目标；这是新增的事后设计评价，不称为原确认实验的预注册结果。

| 可能结果 | 正确判断 |
|---|---|
| ours、sampled、消融几乎一致 | 当前共同最优环境族不能区分这些训练方案的零样本部署能力 |
| ours 优于 PG，且源差距已存在 | 当前固定源预算下的目标性能更好；不足以证明独立于源学习进度的迁移优势 |
| 仅人数变化时各方法人均回报恒定 | 验证结构控制和部署实现，没有产生算法间迁移机制优劣证据 |
| 组成/强度变化下差距变化 | 分析相同策略误差在不同奖励权重下如何被放大/缩小；不自动认定是迁移能力变化 |
| ours 在某些目标落后 | 完整保留并报告，不更换目标或最终模型 |

对“源性能匹配”的附加比较，当前不以目标结果挑中间 checkpoint：现有保存策略主要保留 best/final。若以后确需隔离源训练进度，须提前规定仅由源指标决定的停止/保存规则，并另行开展训练；源回报相同也不等于策略相同。这不是本次轻量补充的必需工作。

## 6. 真正有区分度的迁移证据在哪里

按既定导航协议完成 N-C/N-A 源训练，冻结四种主方法 final，再以 N-T 评价 N=3/4/6/8 的目标回报、覆盖、距离和碰撞；目标数据不用于选参数或模型。人数变化同时改变拥挤程度和任务数量，不再有 pair 的共同最优策略推导，因此更适合检验实际部署表现。并非复杂任务必然产生 ours 优势，仍由结果决定。

若仍希望在 pair 中建立更强的迁移对照，须另建有机制依据的预定环境族，使最优本地决策确实随交互组成变化，并明确哪些目标满足小偏移条件、哪些用于边界诊断。调整奖励符号或竞争结构属于新实验版本；不能混入当前结果，也不能根据 ours 的输赢挑选目标。先完成低成本 P-T 和导航证据，再判断是否值得开展该扩展。
