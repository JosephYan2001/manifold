## 1. 先用小预算跑通全部实验

```powershell
python manifold_project/experiments/pair_coordination/run_experiments.py --profile smoke --experiments all --plot
```

这会跑 6 个训练条件与 5 项机制实验，共 11 个任务。每个完整训练条件只允许 128 个源回合；结果用于核验入口、成本和文件，不用于方法优劣结论。默认不为每个子运行生成图片，整套只生成一张 overview.png。

## 2. 按文档问题选择实验

| 文档中的实验 | 命令编号 | 运行内容 |
|---|---|---|
| 算法比较 | P-C | 完整方法、采样平方、PG |
| 方向/回报检查及拟合预算消融 | P-A | 完整方法、采样平方、去方向检查、去回报检查、1/4 拟合预算 |
| 有限样本方向估计 | P-M1 | 两个冻结 actor、两种标签、两种方向目标及样本量网格 |
| actor 实现机制 | P-M2 | 精确指数目标、自由表格、共享单 logit；不同步幅与拟合次数 |
| 方向运输 | P-M3 | 自动依赖 P-M1；复用其偏置 actor 的解析方向，评价 9 个源/目标配置 |
| 二阶边界 | P-M4 | 零一阶方向与 4*epsilon² 增益 |
| empirical/Hoeffding 检查 | P-H | 固定正/负/零真值候选，配对检查数据，比较接受决定与成本 |

一次可选择多个编号。P-C 与 P-A 的公共条件去重；P-M3 不会用目标数据重新训练源方向。

以下为已经完成的 pilot 实验入口，供复现和重新开发使用；当前待执行的论文补充实验见下一节。

```powershell
python manifold_project/experiments/pair_coordination/run_experiments.py --profile pilot --experiments P-M1 P-M2 P-M3 P-M4 P-H --plot
```

算法比较和消融试运行：

```powershell
python manifold_project/experiments/pair_coordination/run_experiments.py --profile pilot --experiments P-C P-A --plot
```

pilot 使用训练种子 40/41/42，各完整运行预算 131072 源回合，标准方向/actor 各 64 epoch。这是独立的候选试运行配置，不修改原 train_minibatch.json。不同方法的优化设置尚未完成源调参，不能据此直接报告已充分调优的基线排名。

## 3. 当前论文补充配置与旧 formal 模板

当前三组补充实验已分别保存配置，命令、重复数和读取方式见[论文补充实验运行说明](论文补充实验运行说明.md)：

| 配置 | 实验 | 数量 |
|---|---|---|

| configs/suite_paper_mechanisms.json | P-M1/P-M3 | 640 次配对方向拟合、180 条运输记录 |
| configs/suite_paper_checks.json | P-H | 每条件 200 个数据集，共 9600 条规则记录 |

这些配置沿用已明确的开发参数，PG 学习率固定 0.001，不代表做过充分基线搜索。配置存在不等于训练完成；已有结果见[结果目录索引](results/结果目录索引.md)。

旧 `--profile formal` 仍是候选模板，以下命令仅用于预览旧模板，不替代上述三份配置：

```powershell
python manifold_project/experiments/pair_coordination/run_experiments.py --profile formal --experiments all --dry-run
```

dry-run 不导入 PyTorch、不训练、不创建结果目录，打印条件数和预算。formal 预置正式重复数和机制网格：60 次完整训练、640 次表格方向拟合、24 条 actor 实现记录、180 条运输记录、3 条二阶核验、960 条配对检查记录。

**suite_formal.json 的训练预算、优化次数和学习率仍为候选值**，状态明确标记 candidate_not_frozen。先根据源试运行调整并另存冻结配置，设置 protocol_status 为自定义冻结版本名，再执行：

```powershell
python manifold_project/experiments/pair_coordination/run_experiments.py --suite-config "冻结配置路径.json" --experiments all --plot
```

配置文件：

- configs/suite_smoke.json：全入口验证。
- configs/suite_pilot.json：源开发。
- configs/suite_formal.json：正式重复数量与候选参数。

所有训练使用同一源配置。轮数上限自动设为 budget//episodes+1，让较省检查的变体能继续使用剩余预算；不足以完成下一轮最低成本时停止，不超支。`--device cpu` 或 `--device cuda` 可覆盖设备；`--threads` 默认 1，适合当前小网络。

## 4. 结果去哪看

程序未指定输出目录时仍使用 results/suite_时间戳；已有 8 个目录已改为 `suite_01_机制验证_3数据种子` 等语义名称，见[结果目录索引](results/结果目录索引.md)。建议通过 `--output-dir` 指定尚不存在的新目录；本页以 D:\manifold 为工作目录，需写完整相对路径，如 `--output-dir manifold_project/experiments/pair_coordination/results/suite_09_论文比较与消融_10种子`。

| 文件 | 查看内容 |

套件默认不记录逐梯度更新流 updates，也不生成逐子运行图片。其他原始记录仍保留，便于排查。

套件每次成功训练只保留 4 个 JSON：`config.json`（包括运行环境、请求配置、解析配置和训练计划）、`summary.json`、`checkpoints/best.json`、`checkpoints/final.json`。不再生成重复的 `actor.json`，加载最终模型请使用 `checkpoints/final.json`。运行中、失败或按请求暂停时仍保留进度文件。原始轨迹统一写入一个 `events.jsonl`，每行含 `stream`（如 policy、checks、batches）和 `record`（原始记录）。统计和绘图兼容新旧格式；直接运行 `train.py` 仍采用原调试输出布局。

旧套件日志可用 `python -m manifold_project.experiments.pair_coordination.analysis.merge_logs manifold_project/experiments/pair_coordination/results` 预览，追加 `--apply` 合并。只处理已完成且非暂停的训练，先保存每个套件的 `legacy_logs.zip` 并验证，逐类核对合并记录后再移除旧 JSONL。旧日志迁移保持每类内部顺序，不推断不同文件之间的全局时间顺序。使用代码读取日志时，请调用 `training.logging.read_records(run_dir/"policy.jsonl")` 等接口，它会自动从统一日志提取对应记录。

旧结果可用 `python -m manifold_project.experiments.pair_coordination.analysis.compact_results manifold_project/experiments/pair_coordination/results` 预览精简范围，追加 `--apply` 执行。只处理已完成且非暂停的训练；先将冗余文件与修改前配置/摘要保存到每个 suite 的 `legacy_metadata.zip` 并验证内容，再合并配置和移除重复文件。已有归档不会被覆盖。

## 5. 复用已完成任务

例如先跑 P-C，之后在同一个目录补 P-A：

```powershell
python manifold_project/experiments/pair_coordination/run_experiments.py --profile pilot --experiments P-C --output-dir "实验目录"
python manifold_project/experiments/pair_coordination/run_experiments.py --profile pilot --experiments P-A --output-dir "实验目录" --resume-suite --plot
```

协议、源配置和 CPU 线程数必须一致。完整方法、采样平方及其种子直接复用。--resume-suite 复用任务完成记录，**不是自动续跑中断的单次训练**；失败/中断训练保留在状态表，不静默剔除或自动重试。单次训练可用原 train.py --resume 加载 final.json 到新目录，PG 会恢复 Adam 状态；这种人工续跑尚不会自动并回套件汇总。

## 6. 结果解释必须保留的区别

- PG 是每批新 on-policy 数据做一次 Adam 更新，跨批保留优化器状态；不在旧批次上重复普通 PG epoch。其他方法的 actor_epochs 不决定 PG 更新次数。
- 去回报检查会采用首个有效拟合候选，也取消回报驱动的步幅回退；去方向检查不再采样方向检查批次。
- P-M1 的精确标签是 R-E[R|联合类型]，不是减去一个全局常数。数据 SHA256 用于核对两目标及两标签确实共用源批次。
- P-M2 记录受限类最佳拟合参考及超出该参考的优化误差，并记录概率下限；不把优化不足都解释为表达能力不足。
- P-M3 使用带符号邻居测度的 L1 变化量计算机制界，不误用半 L1；仅人数变化组的方向不变性只适用于当前 iid、归一化完全图。
- P-H 的两规则共享检查数据，不是两次独立采样；evaluation_batch_id 标识复用，单行成本不能跨规则直接相加。manifest 的 unique_sampled_episodes 给出预定实际采样量。
- 主比较使用 final，精确量只用于诊断和 best 归档，不参与候选接受。训练均值的单种子 bootstrap 不报告区间；P-H 比例使用单独的二项区间口径。smoke 曲线不能用于算法排名。检查成本计入训练预算，机制实验采样成本单列。
- 当前耗时包含初始化、训练、诊断与文件保存；首次优化器初始化可能有额外开销，尤其不能用 smoke 的秒数判断计算优势。
