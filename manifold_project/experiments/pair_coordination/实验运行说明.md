# 成对协作运行说明

本文说明当前一步任务的实际接口。新冲突源和多步机制尚未完成，正式研究安排见[实验方案](../../docs/策略流形研究设计.实验方案.md)；模型、公式与指标字典见[实现说明](实现说明.md)。

所有命令在包含 manifold_project 的仓库根目录运行。训练需要已安装 PyTorch、NumPy 的 Python 环境，绘图另需 Matplotlib；相对文件路径按终端工作目录解析。

## 查看和预检

~~~powershell
python -m manifold_project.experiments.pair_coordination.train --help
python -m manifold_project.experiments.pair_coordination.run_experiments --help
python -m manifold_project.experiments.pair_coordination.train --training-config manifold_project/experiments/pair_coordination/configs/train_minibatch.json --dry-run
python -m manifold_project.experiments.pair_coordination.run_experiments --profile smoke --experiments all --dry-run
~~~

dry-run 展示实际配置与预算，不训练、不创建输出目录。单次 train 的预检还会检查 PyTorch 设备；套件预检不导入 PyTorch。单次配置优先级为命令行 > JSON > 默认值，print-config 仅显示生效配置。

| --experiments 编号 | 当前实现 |
|---|---|
| P-C | 完整方向方法、采样平方、直接 PG 比较 |

P-C/P-A 的重复训练条件会去重，P-M3 自动依赖 P-M1。直接 PG 不是 PPO。R1-P1～P7 是研究编号，现有 CLI 不接受它们。

若需验证既有训练入口，可运行小预算接口检查：

~~~powershell
python -m manifold_project.experiments.pair_coordination.run_experiments --profile smoke --experiments all --output-dir manifold_project/experiments/pair_coordination/results/interface_check --plot
~~~

它会生成数据，输出目录必须尚不存在；结果只用于实现检查，不能承担新协议的论文比较。

## 训练参数与源成本

| 参数 | 控制对象 |
|---|---|
| --episodes-per-round | 每轮新源团队回合数 |
| --batch-size-episodes | 每个梯度小批次的完整回合数 |
| --direction-epochs、--actor-epochs | 两模块遍历固定训练数据的次数 |
| --direction-lr、--actor-lr | 两模块的恒定 Adam 学习率 |
| --max-rounds、--max-source-episodes | 外层轮次和全部源采样预算上限 |
| --check-episodes、--eta、--attempts | 检查批量、初始目标步幅、候选次数 |
| --baseline zero/table | 零基线或独立源数据拟合的集中类型表 |
| --actor-model、--direction-model | mlp 或 table |
| --beta、--q-max | Actor 概率下限和方向幅度上限 |
| --device cpu/cuda/auto | 学习设备；采样与精确评价主要在 CPU |

旧别名 episodes/rounds/budget/fit_lr 保留兼容。正 epoch 不能和同模块的旧 steps 同时设置。增加 epoch 增加优化量，不增加采样量；小批次保留回合分组。Critic 类型表直接估计条件均值，没有网络学习率。

令训练批次 N、检查批次 M、可选基线批次 C（零基线 C=0）：

| 更新分支 | 源团队回合成本 |
|---|---|
| 固定 Actor 的方向学习 | N+C |
| 完整方法在方向检查拒绝 | N+C+M |
| 完整方法检查首个 Actor 候选 | N+C+3M |
| 每追加一个回报检查候选 | 再加 2M |
| 去方向检查、检查一个候选 | N+C+2M |
| 去回报检查、方向通过 | N+C+M |
| 零基线 PG | N |

同等源预算下，各算法轮数可以不同，比较曲线应按累计源回合对齐。扩大检查批次或启用基线时也要重算总预算；增加训练时间本身不能保证全局收敛。

## 根据记录排查

| 现象 | 检查与调整方向 |
|---|---|
| 固定批次 loss 振荡 | 检查方向学习率及梯度稳定性 |
| loss 下降、真实方向误差上升 | 检查有限样本过拟合；增加独立源样本，不能仅加 epoch |
| 方向检查均值为负 | 核对标签、方向误差和幅度；增加检查样本只提高判断精度 |
| 均值为正、置信下界为负 | 区分样本不足和界过保守；增大 M 会增加源成本 |
| fit_kl 较初始值下降缓慢 | 检查拟合优化量、学习率及目标是否超出 Actor 可表示范围 |
| fit_kl 小、候选回报仍下降 | 检查方向估计和 eta 引入的有限步幅效应 |
| 接受且回报持续提高却停止 | 检查轮次上限和剩余源预算 |

direction-lr 控制方向网络优化，eta 控制目标概率偏离旧策略的幅度，不能混为同一更新参数。只在源任务上开发参数，按预先规定的多种子方案比较；不能按目标回报挑方法、种子或 checkpoint。具体参数网格由总实验方案维护。

## 输出与绘图

| 文件 | 用途 |
|---|---|
| manifest.json、status.json | 套件配置/哈希与完成、失败状态 |
| training_results.csv、training_summary.csv | 逐方法种子记录与跨种子统计 |
| learning_curves.csv | 按已用源预算对齐的曲线 |
| P-M*/records.csv、P-H/records.csv | 机制原始重复记录 |
| P-M1/paired_summary.csv | analytic−sampled 配对方向误差；负值有利于 analytic |
| P-H/summary.csv | 检查事件比例与 Wilson 区间；零次事件不等于概率为零 |
| overview.png | 套件总览 |
| 子运行 config.json、summary.json | 生效配置与运行摘要 |
| 子运行 events.jsonl | 按 stream/record 包装的日志 |
| 子运行 checkpoints/best.json、final.json | 精确源回报最优策略与最后完成轮次状态 |

单次 train 仍使用独立 JSONL 调试流；training.logging.read_records() 兼容独立流和合并流。默认不保存完整批次；save-batches 可额外保存 NPZ。save-direction-snapshots 可保存配对 Actor/方向快照。checkpoint-every 是兼容字段，不再控制 best/final 保留策略。

以下目录为占位符，需替换为实际有效日志目录：

~~~powershell
python -m manifold_project.experiments.pair_coordination.experiments.plotting "套件目录"
python -m manifold_project.experiments.pair_coordination.analysis.plot_training "单个训练目录" --overview-only
~~~

套件生成 overview.png，单次训练生成 round_overview.png；单次 --detailed 另输出轮内诊断图。绘图只读取日志。主方案提出的新统一产物布局尚未实现。

best 的精确源回报归档是当前实现行为；正式冻结比较须预先确定选模规则。失败种子与已消耗但未提交的源回合不能从统计和成本中删去。

## 恢复与冻结评价

以下文件路径为占位符，须换成现存且协议兼容的模型：

~~~powershell
python -m manifold_project.experiments.pair_coordination.train --resume "运行目录/checkpoints/final.json" --output-dir "新的恢复目录"
python -m manifold_project.experiments.pair_coordination.evaluate "运行目录/checkpoints/final.json" --n-agents 8
~~~

单次恢复只支持已完成轮次边界，沿用原配置，不支持更换任务或总预算。PG 恢复 Adam 状态，方向方法重新建立轮内优化器。套件 --resume-suite 复用同协议目录内已完成任务，不自动续跑中断训练；人工恢复段不会自动并入原套件统计。

evaluate 可用 --config 指定目标，要求类型词表兼容。方向运输使用同一参考 Actor 及其方向；最终 Actor 性能是另外一种评价。

evaluate_transfer.py 限定旧源、旧预算、六方法、固定种子组及共同最优目标族，是旧 P-T 专用入口，不能直接用于新方案。目标、校验和统计规则重写前，不使用其无参数默认运行作为当前迁移实验。
