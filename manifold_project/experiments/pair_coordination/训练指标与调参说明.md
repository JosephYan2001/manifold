# 训练指标与调参说明

## 1. 一轮训练实际做什么

常用配置现在统一使用 `episodes_per_round`、`max_rounds`、`max_source_episodes` 和 `actor_lr`。旧名称 `episodes`、`rounds`、`budget` 和 `fit_lr` 继续作为兼容入口。以下公式中的 N、M、C 分别对应训练采集回合、检查回合和 critic 回合。

两个学习率由 Adam 实际使用，当前均为恒定学习率。当前 `train_minibatch.json` 中 `direction_lr=0.001`、`actor_lr=0.001`。梯度更新日志 `updates.jsonl` 中的 `lr` 记录每次更新实际值。critic 类型表直接按条件样本均值拟合，没有 critic 学习率。

当前有两种优化计数方式。旧配置中 `direction_steps` 和 `fit_steps` 表示整批数据上的更新次数。新的 `train_minibatch.json` 将采集量、小批次大小和遍历次数分开：1024 个 episode，128 个 episode 一批，25 个 epoch，共进行 25×8=200 次更新。一个 epoch 表示每个回合都被使用一次；同一回合的机器人始终成组。

启用 `direction_epochs` 或 `actor_epochs` 后，相应的旧 steps 参数不再控制优化次数。采集与独立检查的源回合成本不随 epoch 数增加。

每个机器人根据自己的类型选择 A 或 B，环境给整支队伍一个分数。训练需要从这些选择和分数中学习：同一种类型的机器人，下次应该更倾向哪个动作。

`policy` 模式的一轮训练依次执行：

1. 冻结当前 actor，采集 `episodes` 个完整团队回合。
2. 使用这些数据更新方向函数 `direction_steps` 次，得到每种类型应该怎样调整动作偏好的建议。
3. 使用新采集的 `check_episodes` 个回合检查方向。通过检查后，将建议乘以 `eta`，转换为新的目标动作概率。
4. 从旧 actor 的副本开始，拟合目标概率 `fit_steps` 次。
5. 分别用旧 actor 和候选 actor 各采集 `check_episodes` 个新回合，检查候选是否提高团队平均分。通过后采用候选，进入下一轮。

`direction` 模式执行前两步，actor 始终固定。因此，这个模式中回报保持不变是预期行为。

## 2. 先看这三张策略曲线

保存开关不影响曲线：曲线使用 JSONL 中的指标。`direction_curves` 展示各轮内部方向学习，`policy_curves` 展示实际执行策略跨轮变化，批量实验的 `comparison` 展示不同种子间的均值与标准差。checkpoint 保存间隔为 5 不意味着曲线只记录每 5 轮；策略指标仍逐轮记录。

打开 `policy_curves.png`，按从左到右的顺序阅读。

### 2.1 精确平均团队回报：实际策略表现如何

日志字段为 `policy.jsonl` 中的 `expected_return`。它表示使用当前 actor 反复执行该任务时，整支队伍每回合的平均得分。当前小环境可以枚举全部事件，曲线由枚举加权计算得到，因此没有抽样评价噪声。

得分越高，策略在这个源任务上表现越好。例如从 0.384 变为 0.786，表示每回合的平均团队得分增加约 0.402。0.786 不是成功率，也不表示完成了 78.6% 的任务。

横轴是累计源团队回合数。4 个机器人共同执行一次计为一个团队回合，所有训练、critic 和接受检查的回合都计入其中。目标规模人数变化时，应同时查看每机器人平均回报，避免把人数增加产生的总分变化当作策略改善。

### 2.2 actor 拟合 KL：实际网络是否接近目标概率

日志字段为 `checks.jsonl` 中的 `fit_kl`。方向函数给出建议后，程序会生成目标动作概率；actor 通过监督拟合尽量输出这些概率。

例如目标为 A/B = 0.8/0.2，拟合后的 actor 为 0.79/0.21，两者很接近，KL 较小。若 actor 仍输出 0.5/0.5，则拟合误差较大。KL 为零表示训练输入上的分布完全相同。

同时查看 `fit_initial_kl`，确认拟合后误差是否下降。这个量按训练批次的类型频率加权；训练未出现的类型没有受到同样的拟合约束。KL 很小只能说明 actor 学会了目标，目标是否有益需要查看回报检查。

坐标轴左上角的 `1e-12` 表示刻度都要乘以 10 的负 12 次方。例如刻度 3.0 的实际值为 0.000000000003。这样的拟合误差已经非常小，曲线看起来上下波动也不意味着拟合存在明显问题。

`policy_curves` 中每个点对应一次候选拟合的最终误差。新增 `actor_fit_epochs` 展示同一候选随 epoch 变化的整批 KL，标记接受结果，最多展示最近 10 个候选。若显示“尚未执行 actor 拟合”，应先检查方向是否被接受。

### 2.3 累计更新接受比例：多少轮真正换用了新策略

它等于“已接受新 actor 的轮数 / 已完成轮数”。例如 5 轮中接受 3 轮，比例为 0.6。一个轮次即使尝试了两个候选，也最多记为一轮接受。

接受比例没有越高越好的统一标准。策略已经接近稳定点时，拒绝小幅或不确定更新可能是合理的。回报不变且接受比例为零时，打开 `checks.jsonl` 判断训练停在哪一步。

## 3. 方向学习曲线说明了什么

打开 `direction_curves.png`。每条线是一轮 actor 冻结后，方向函数在同一批数据上的学习过程。横轴是参数更新次数，增加这些次数不会采集新回合。

| 中文指标 / 日志字段 | 含义 | 怎样阅读 |
|---|---|---|
| 训练方向损失 / `loss` | 当前方向在这批训练数据上的优化目标 | 同一批次下越低越好，可以是负数；负数不表示计算出错 |
| 真实方向误差 / `direction_error` | 学得方向与该旧 actor 处的真实本地方向之间的 Fisher 加权平方差 | 越接近零，方向越准确；其数值不是回报损失 |
| 总体方向分数 / `score` | 该方向在真实源分布下的线性收益与二次代价的综合值 | 在同一旧 actor 下，分数提高与方向误差下降等价；正值支持理想目标的充分小步改进 |

训练损失来自有限样本，后两项来自精确枚举。可能出现训练损失持续下降、真实方向误差却上升的情况：网络越来越贴合这批样本中的随机偏差。增加同一批数据上的训练次数不能补充缺失的统计信息。

不同轮次的旧 actor 已经变化，真实最优方向及其能量也会变化。因此，不要求不同轮次的分数依次升高，也不要求误差跨轮单调下降。正分数也不保证指定 `eta`、有限拟合误差下的实际 actor 一定提高回报。

两种方法 `analytic` 与 `sampled` 在有限数据上的损失不同。比较方法时，优先看相同旧 actor、数据和预算下的真实方向误差，以及多轮训练后的团队回报。

## 4. 接受检查为什么会拒绝更新

`checks.jsonl` 中 `kind=direction` 是方向检查，`kind=return` 是候选 actor 回报检查。

| 字段 | 方向检查 | 回报检查 |
|---|---|---|
| `mean` | 独立完整回合上估计的平均方向分数 | 候选平均团队回报减去旧 actor 平均团队回报 |
| `radius` | 由样本量、方向上限、标签界和错误概率计算的置信半径 | 由样本量、奖励界和错误概率计算的置信半径 |
| `lower_confidence_bound` | `mean - radius` | `mean - radius` |
| `decision_value` | 实际用于接受判断的数值 | 实际用于接受判断的数值 |
| `threshold` | 当前为 0 | 当前为 0 |
| `accepted` | 方向是否通过 | 候选 actor 是否通过 |

`hoeffding` 模式要求 `mean - radius > 0`；`empirical` 模式只要求 `mean > 0`。例如 `mean=0.10`、`radius=0.30` 时，置信下界为 -0.20，置信检查会拒绝，经验检查会接受。经验检查仍使用独立数据，但不具备前者的置信保证。

检查回合数扩大 4 倍，在其他条件相同时，置信半径约减半。当前界比较保守，1024 回合下即使学得方向准确，也可能无法通过检查。先判断拒绝是因为均值不理想，还是半径太大，再决定调哪一个参数。

## 5. 根据现象选择参数

以下数值是基于现有配置的排查起点。每次修改一项，固定源任务，并使用多个种子复核。

| 观察到的现象 | 先检查什么 | 可尝试的调整 |
|---|---|---|
| 同一批数据的方向损失明显来回振荡 | `direction.jsonl` 中逐次更新的 `loss` | 将 `direction-lr` 从 0.01 降到 0.003 |
| 方向损失到最后还在稳定下降，方向误差也下降 | 当前优化是否充分 | 将 `direction-steps` 从 200 增到 400 |
| 训练损失下降，但真实方向误差大或种子间波动大 | 是否只有少量源样本 | 将 `episodes` 从 1024 增到 4096，并增加总预算 |
| 方向检查均值为正，置信下界仍为负 | `radius` 是否大于 `mean` | 增加 `check-episodes`，同时增加 `budget` |
| 方向检查均值为负 | 方向拟合是否准确，输出是否接近上限 | 先处理方向学习；增加检查样本只能让判断更准确 |
| `fit_kl` 明显高于零，且较初始值下降缓慢 | actor 是否充分拟合 | 将 `fit-steps` 从 200 增到 400；若振荡则降低 `fit-lr` |
| 拟合 KL 小，但候选回报检查均值为负 | 方向是否准确、目标步幅是否过大 | 在方向可靠时，将 `eta` 从 0.2 降到 0.1 |
| 轮轮接受、回报继续上升，但过早结束 | `rounds` 与已用回合预算 | 增加 `rounds`，并按下面的成本公式增加 `budget` |
| 所有方向输出都接近上限 | `amplitude_fraction` 接近 1 | 检查是否样本噪声或方向容量限制；调整 `q-max` 后必须重新评估置信成本 |

`direction-lr` 控制网络参数如何学习，`eta` 控制学得方向被转为多大的策略改变。两者作用在不同阶段。降低前者有助于优化稳定；降低后者使目标概率更接近旧策略。

### 5.1 源回合预算如何估算

设每轮训练回合数为 N，检查批次为 M，critic 回合数为 C。零基线时 C=0；类型表基线时 C=`critic-episodes`。

- 固定方向学习：N+C。
- 一轮方向检查未通过：N+C+M。
- 一轮方向通过且检查一个候选 actor：N+C+3M。
- 每增加一次候选 actor 检查，额外消耗 2M。

默认 N=M=1024、零基线、每轮检查一个候选时，每轮消耗 4096 回合，5 轮消耗 20480 回合。若增大 M，需要同步检查 `budget`。当前控制器只在剩余预算足够进行训练、方向检查和至少一次候选回报检查时启动新一轮；预算不足时可能早于 `rounds` 停止。

### 5.2 第一轮排查可以固定哪些参数

当前 `train_minibatch.json` 使用隐藏宽度 32、层数 2、两个学习率 0.001。旧 `train_mlp.json` 使用 0.01；应以启动摘要为准。当前输入只有少量类型，优先检查样本数、优化稳定性、接受条件和步幅，再考虑扩大网络。

`beta=0.02` 使每个动作概率至少为 0.01。它限制 actor 能达到多确定的行为，也影响探索。`q-max=1` 限制方向分量幅度。更改这两项会同时改变可表示范围及分析条件，初期可以固定。

`alpha=0.05` 是置信检查的总错误概率预算，程序会按预设轮数与尝试数分配。增大它会放宽风险要求。`log-every` 只控制记录频率。`seed` 用于独立重复，应报告多个种子的结果，不能挑选得分最高的种子作为方法表现。

## 6. 其它诊断字段

- `information_gap`：完整信息参考方向与本地方向的一阶差距。它反映当前信息限制，不是方向网络拟合误差，也不是集中最优策略与本地策略的回报差。
- `amplitude_fraction`：最大方向分量绝对值除以 `q-max`。接近 1 表示接近幅度限制，不直接说明方向正确或错误。
- `target_min_probability`：目标概率中的最小值。指数目标可以低于 actor 的 `beta/2` 下限，这时即使充分训练也可能保留拟合误差。
- `source_episodes`：累计源回合成本。独立检查和可选 critic 拟合都使用源交互预算。
- `std_across_seeds`：独立种子间的样本标准差。较大表示重复实验波动较大；单种子时记为 `null`，不能据此声称结果稳定。
