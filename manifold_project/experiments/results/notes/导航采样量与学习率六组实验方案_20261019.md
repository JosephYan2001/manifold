# 导航采样量与学习率六组实验方案

2026-10-19 制定。本轮设计为：**N16、N32、N64 × 固定 Actor 学习率、线性衰减，每组 2M 源交互预算，从相同随机初始化开始。** 先做训练种子 40 的机制探索，检查采样量与学习率日程能否改善连续学习；有增量收益再安排独立训练种子确认。另计划对已有 MAPPO 2M 的 final.pt 做一次同场景冻结评价，提供性能参照，不新增第七组训练。

**2026-10-22 状态：六组训练及各 100 场景终点评价已完成，见[结果与旧基线对比](../evidence/navigation/navigation_batch_lr_2m_s40_20261019_v1/analysis_20261022/六组训练与旧基线对比.md)。** 各组均 0/100 成功，源监控曲线仍落后旧 an_base；MAPPO 同场景复评尚未提供。下文保留本轮预定设计。本轮方向 4 epoch 与旧基线 16 epoch 不同；最新归因与收敛决策以结果报告第 6 节为准，已撤回默认追加两组 500k 的建议，不将此方案继续列为待启动任务。[配置与命令](../../configs/navigation/batch_lr_2m/README.md)及[28 项 CPU 验收](../checks/navigation_batch_lr_acceptance_20261019_v1/验收报告.md)保留用于复现。

本方案替代此前“继续做 D1/D2”“再次复核固定教师”“先完成 Critic 诊断才能续训”“只延长 A/C”的执行安排。原始实验数据和历史阶段结论继续保留，当前证据与本轮假设按下面的边界解释。

## 1. 已有证据与本轮问题

| 已有证据 | 可以支持什么 | 尚不能支持什么 |
|---|---|---|
| [固定目标新数据确认](../evidence/navigation/actor_fit_e1_confirm_20261018_v1/analysis_20261018/新种子确认分析.md)：小学习率产生更好的非零验证拟合候选 | 某些已训练基点的 Actor 拟合可被改善 | 从头训练也应全程用 3e-5 |
| [固定教师收益复核](../evidence/navigation/teacher_return_review_20261018_v1/analysis_20261018/固定教师复核分析.md)：两个教师的新评价区间均跨零 | 负收益信号未得到新的明确支持，封顶复核已结束 | 教师已被证明有益、无害或无效 |
| [N64 四格短训练](../evidence/navigation/actor_fit_short_n64_u128_500k_s40_20261018_v1/analysis_20261019/四格短训练分析.md)：各 16 轮，固定 3e-5 两组较差，最佳候选保留进展 | 不应直接推广全程固定 3e-5；候选选择按定义生效 | 大批次一定更差、学习率衰减一定有效、整体算法已无价值 |
| A/C/D 的整批 Critic 解释方差接近零，策略熵接近均匀分布 | 价值预测、标签和目标质量值得随训练记录 | Critic 已是唯一根因，或应立即修改奖励、网络与 η |
| [历史 MAPPO-E 2M 复算](../evidence/navigation/navigation_ep400_history8_2m_s40/mappo/analysis_20261019/MAPPO_2M参照分析.md)：最终回报 −54.320，7/20 成功；约 0.46M 的监控已为 −54.541、3/8 成功 | 相近任务协议下，2M 内可以观察到明显学习进展；AN 需报告相对该策略的差距 | 35% 是稳定成功率、历史与新实验完全可比、或 MAPPO 的方向已被证明更准确 |

MAPPO 的历史终点参照具体为：**1,997,221 源步、295 轮，final.pt 在 20 个独立场景上平均折扣回报 −54.3195、成功 7/20（35%）、失败计上限的平均完成步数 782.65。** 训练每回合最多 400 步，评价最多 1,000 步，35% 是后者的成功率。运行 summary.json 中的 −49.0085、37.5% 来自另外 8 个 source-final 场景，不能替代 20 场景结果。

旧 MAPPO 使用 N16、8 帧实体历史，但训练源码版本与新 AN 不同，更新及价值学习流程也不同；训练种子同为 40 不代表初始参数相同。它是历史性能参照，不是本轮随机初始化、同版本的算法对照。已有结果不支持把 AN 的低效完全归因于预算太短，也不保证 AN 必须在 2M 收敛。若六组只有内部小幅改善、仍明显落后于参照，须同时报告这两个事实。

本轮回答三个问题：

1. 相同交互预算与样本复用遍数下，N16/N32 更频繁地重采样和提交策略，是否优于 N64？
2. 同一 N 下，Actor 学习率从 3e-4 衰减到 3e-5，是否优于固定 3e-4？
3. 衰减的效果是否随 N 改变？

N 改变会同时改变单个方向目标的数据量、每轮优化次数与外层迭代频率。本轮比较这一整体取舍，不把结果单独归因于“方向更准”或“更新更频繁”。学习率衰减只控制 Actor 拟合；教师步幅 η 保持不变。

## 3. 保持不变的设置

| 项目 | 本轮统一设置 |
|---|---|
| 任务 | navigation-episodes-v1-history-v1；源 4 个机器人和 4 个地标 |
| 采样 | 独立重置完整回合；成功终止，否则 400 步截断；真实末状态自举 |
| 观测与网络 | 8 帧历史；full 实体观测；hidden=128、heads=4、relation_layers=2；现有 Actor/Critic 结构 |
| 标签 | GAE，gamma=0.99、lambda=0.95；现有冻结与梯度隔离语义 |
| 优化小批次 | 每批 2 回合；公共配置 minibatch_size=3200，按当前 400 步、4 agent 映射为 2 回合 |
| 方向 | direction_steps=4，即 4 epoch；direction_lr=3e-4；当前解析二次项 |
| Actor | actor_fit_steps=16，即 16 epoch；整批训练 KL 选择最佳 epoch，含零更新；跑完全部优化预算后选择 |
| Critic | critic_steps=10，即 10 epoch；critic_lr=1e-3 |
| 其他优化设置 | 当前 Adam 初始化、梯度裁剪与数值口径保持一致；不同时改优化器或引入跨轮动量 |
| 教师步幅 | 首个 η=0.1；不因学习率或 N 改变而重标定教师或实际 KL |
| 检查开关 | direction_check=false、return_check=false；不增加回报门控或用回报选择 epoch |
| 诊断额外采样 | 本轮默认 0；不重新执行 E1 或固定教师复核，不新增独立方向/教师执行采样 |
| 固定目标快照 | 默认不逐轮保存大目标包；保留正式 checkpoint、日志和逐回合评价数据；不能事后声称能重放所有历史教师 |

各组保持 epoch 数和小批次回合数，而不是强行保持每轮 U128：

| N | 每轮训练步上限 | 每轮 Critic 更新 | 每轮方向更新 | 每轮 Actor 更新 |
|---:|---:|---:|---:|---:|
| 16 | 6,400 | 80 | 32 | 128 |
| 32 | 12,800 | 160 | 64 | 256 |
| 64 | 25,600 | 320 | 128 | 512 |

这保持每条采样数据的重复使用遍数。总梯度更新次数在相同训练回合数下相同，但整批诊断、重新初始化和提交等开销可能不同，因此仍记录实际耗时。

## 4. 学习率日程的精确定义

只改变每轮 Actor 拟合所用的学习率，每轮拟合内部保持常数。方向与 Critic 学习率、η 均不随之衰减。

记 `s` 为本轮采样开始前的累计源交互步数，包含已计费的训练和源监控；`s0` 为首次训练轮开始前同一计数器的值，保存后固定；`T=2,000,000` 为日程终点。采用：

```text
p = clip((s - s0) / (T - s0), 0, 1)
fixed:  actor_lr_used = 0.0003
linear: actor_lr_used = 0.0003 + (0.00003 - 0.0003) * p
```

这样首轮两种日程均为 3e-4；N 不同不会因本轮采样长度不同而改变首轮学习率。沿用 8 回合起点评价且全部跑满时 s0=8,000。用实际计数，不硬编码这个估计。

学习率按源交互进度变化，不按外层轮数或 Actor 优化步数变化。小批次顺序、优化预算与候选集合不因日程改变。零更新轮次照常推进交互进度和计费；因完整批次限制，最后一次拟合的学习率通常略高于 3e-5，不为触及端点追加一次无数据更新。

每轮记录日程类型、s、s0、T、实际学习率及拟合更新次数。恢复时继承这些值；同一已提交边界、同一计数下恢复必须得到同一学习率。将来若另立延长实验，不能回溯修改已执行的衰减日程；本轮不因中途结果自动延长。

## 5. 预算、监控与评价

每组 2M 是**源交互上限，包含训练及源监控**。沿用每 65,536 源步一次监控、每次 8 回合，另有起点和终点，共 32 个节点；评价上限均为 1,000 步。

全部回合跑满时的预算估计如下，不替代实际账本：

| 项目 | N16 | N32 | N64 |
|---|---:|---:|---:|
| 源监控步数 | 256,000 | 256,000 | 256,000 |
| 训练轮数 | 272 | 136 | 68 |
| 训练环境步数 | 1,740,800 | 1,740,800 | 1,740,800 |
| 实际源步数 | 1,996,800 | 1,996,800 | 1,996,800 |
| 未用源预算 | 3,200 | 3,200 | 3,200 |
| Critic / 方向 / Actor 总优化次数 | 21,760 / 8,704 / 34,816 | 同左 | 同左 |

成功提前结束时记录实际成本与轮数，不补齐无效步数。余量不足完整训练批次时正常结束，不冒充中断或缺失训练。

六组源预算总上限 12,000,000 步。每组完成后只评价源规模 `final.pt`，100 个预先固定的新场景、随机采样动作、每回合最多 1,000 步；最终报告另计，共最多 600,000 步。六组 AN 的新增交互上限为 12,600,000 步。

另加载 `evidence/navigation/navigation_ep400_history8_2m_s40/mappo/N-C_source_learning/full/MAPPO-E_s40/checkpoints/final.pt`，冻结模型，在相同 100 个场景上评价一次，最多增加 100,000 步。**本轮新增总交互上限为 12,700,000 步：12M AN 源预算 + 0.6M AN 最终评价 + 0.1M 冻结 MAPPO 评价。** 不新增 MAPPO 训练或优化，不将历史已消耗的 2,012,874 步重复计入新增预算；它们在参照策略的历史成本中单列。异常失败后重试的已消耗成本另行保留，不隐去或混入成功运行。

终点评价统一 `evaluation_seed=20262000`，使用场景种子 20262000–20262099，与此前短训练的 20261020–20261119 分开，也不复用 MAPPO 历史的 1000000–1000019。六组 AN 和冻结 MAPPO 使用相同场景和预先确定的动作随机数规则，不强迫策略采取相同动作。评价不挑选 checkpoint 或学习率；主报告使用 final，不用按监控指标挑出的 best.pt 替换。

MAPPO 冻结评价前核对模型加载、历史输入适配、推理状态、奖励和终止语义，保存 checkpoint 哈希。若无法可靠恢复历史策略的推理语义，保留历史结果并报告不可比较的缺口，不静默替换组件、不自动重训 MAPPO。当前已通过本地检查点的加载及 3 步工程评价检查；正式 100 场景冻结评价尚未执行。检查不等于与历史全部数值轨迹逐步一致。

中途 source-grid 的固定 8 场景、终点 source-final 的 8 场景和最终报告的 100 场景分别标记。学习曲线只连接同一 source-grid 集合；source-final 作为不同场景的独立点，不把切换场景产生的跳变解释为训练效果。跨组监控使用相同预算节点，并保留实际被评价策略的提交步数。

## 6. 需要记录的诊断

保留每轮起点、最佳、最后和所选目标 KL，以及目标→旧 Actor、目标→所选 Actor、旧 Actor→所选 Actor 三个方向明确的 KL。记录所选 epoch、零更新、实际参数改变、策略熵和方向训练 B/D/Fisher 能量。

Critic 在现有训练批次上记录拟合前后整批解释方差、预测与目标均值/方差，记录冻结 Critic 对应的 GAE 标签均值/标准差。诊断使用冻结视图，不修改标签、RNG、参数或优化轨迹；不追加环境采样。已有字段复用，缺少字段作为启动前只读日志补充。

这些指标用于解释任务收益，不能代替执行回报，也不能据整批训练分数声称独立方向泛化良好。每轮最多保留一套汇总与 epoch 级拟合历史，不默认开启每个优化步的整批轨迹输出。

## 7. 预先规定的比较与结论

主要结果是终点 100 场景的平均折扣回报；同时完整报告成功数、失败计上限的完成步数和成本。中途源回报及成功率只作为趋势证据。若报告监控 AUC，使用相同 source-grid 节点，按每段左端点值积分，将最后一个同场景监控值保持到 T，不把另一组 source-final 场景混入同一曲线。

五项主要对照：

1. n16_fixed − n64_fixed。
2. n32_fixed − n64_fixed。
3. n16_linear − n16_fixed。
4. n32_linear − n32_fixed。
5. n64_linear − n64_fixed。

补充报告衰减组内 N16/N32 相对 N64 的差值，以及各 N 的“衰减收益”之差。另完整报告六组各自减去冻结 MAPPO 的回报差及成功数差，使用新 100 场景的结果；历史 20 场景 −54.32、35% 只作背景，不作为新场景的硬性通过线。对六个 AN 策略及冻结 MAPPO 使用共同的完整场景重采样索引，50,000 次 percentile bootstrap，统计随机种子 20261019，报告均值差及探索性 95% 区间。

这些区间未做多重比较校正，仅描述已训练策略的评价场景不确定性；不据一次跨零与否作全局优越性认证。六组 AN 只有一个共同训练种子，不能当作六个训练重复，也不能把七个策略的最多 700 条评价轨迹当作 700 个独立场景。与 MAPPO 的同场景复评比较已得到的策略，不能消除历史训练版本和流程差异，更不能替代同版本、多训练种子的算法比较。预先列出的全部对照都报告，不挑有利比较。

| 结果 | 下一步 |
|---|---|
| 较小 N 在任务回报上改善，且方向/拟合未出现一致恶化 | 将对应采样设置作为候选，再用独立训练种子确认 |
| 衰减在某些 N 下改善任务收益 | 保留该条件下的日程假设；不自动推广到所有 N |
| AN 内部有改善，但相对冻结 MAPPO 仍明显落后 | 承认干预有局部价值、任务性能仍落后；不宣称效率问题已解决 |
| 拟合改善但任务收益没有改善 | 停止继续细调 Actor 学习率，按同期证据选择教师、标签或 η 的一个受控诊断 |
| 各组都进展微弱或区间仍很宽 | 本轮按 2M 结束，完整报告不确定性；结合 MAPPO 历史进展承认本轮干预可能不足，不仅归因于预算太短；不自动扩大到 4M/10M，也不继续追加评价直到显著 |
| 明确出现计算错误、非有限参数或恢复错误 | 停止受影响运行并保留成本；修复与重新启动另记版本，不混合前后数据 |

不因某组暂时落后而提前停止，不在执行中改 N、epoch、衰减终点、评价场景或奖励。数据种子 43/44 的固定目标确认不算本轮独立训练种子的复验。

## 8. 启动前工程与验收

当前 [`fit_actor`](../../cooperative_navigation/training/actor_fit.py) 每轮创建 Adam，Runner 已将采样前计算的本轮实际学习率传给该入口。配置字段为 `actor_lr_schedule`、`actor_lr_final`、`actor_lr_decay_steps`；旧配置默认 fixed。

以下启动前工作已完成，见[工程验收](../checks/navigation_batch_lr_acceptance_20261019_v1/验收报告.md)：

1. 公共配置与 Runner 接通 fixed/linear 日程，校验初值、终值、时钟和端点；旧配置默认 fixed，旧 checkpoint 保持原语义。
2. 日程在采样开始前计算、在整轮拟合期间固定，写入 training.csv、事件日志和 checkpoint；只作用于 AN Actor 拟合。
3. 已提交边界恢复后学习率及后续更新与不中断运行一致；s0/T 不随 resume 重置。中断造成的新采样损耗仍据实际源计数计费。
4. 固定日程与现有固定学习率路径结果一致；诊断开关不改变同批数据上的参数更新；最佳候选仍包含零更新并完整计费。
5. 六份公共配置 dry-run，确认只有 N 和日程不同，映射的小批次始终为 2 回合；首轮固定/衰减使用相同学习率。
6. 确认输出路径不复用历史运行目录，六组初始模型哈希相同，终点评价场景未与此前使用的集合重叠。
7. 单独验收历史 MAPPO final.pt 的只读加载与推理兼容性，记录模型哈希和版本；冻结复评入口不调用训练、拟合或模型选择，不覆盖历史结果。

六份训练配置与一份冻结 MAPPO-E 评价配置已经生成，均使用[公共入口命令](../../configs/navigation/batch_lr_2m/README.md)。AN 训练完成后自动执行本方案的最终 100 场景评价，无需重复评价。

单 GPU 顺序执行 n16_fixed、n16_linear、n32_fixed、n32_linear、n64_fixed、n64_linear；统一设备及软件环境。中断恢复使用该组原公共 --resume，不用恢复入口切换变体。失败目录保留，重试另起后缀并累计成本。
