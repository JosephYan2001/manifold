# D1 D2 问题排查

2026-10-15。现有结果支持优先处理两件事：方向在小训练批次上增加优化后泛化变差，以及 Actor 使用 3e-4 学习率时拟合震荡。没有证据表明只要把同一批数据上的方向训练得更充分，就能改善真实策略收益。随后已完成固定基点的样本量与优化次数对照、拟合整改及连续短训练。

原始结果位于上一级目录的 [D1](../direction_s40/) 与 [D2](../fit_s40/)。本目录保存[复算指标](metrics.json)、[诊断图](diagnosis.png)和可复现脚本 analyze.py。分析仅读取现有文件，未采样、未训练、未修改原始结果。

## 结果完整性

- D1：4 个候选、34 条拟合记录、4 条方向记录、200 条评价回合记录。D2：6 个候选、51 条拟合记录、2 条方向记录、280 条评价回合记录。每个策略均为相同编号的 40 个配对场景，全部 0/40 成功。
- manifest 均为 completed，记录源模型冻结、checkpoint 未改变。重新计算的源 checkpoint SHA256 与 manifest 一致；候选回报、配对收益、成功率均能由逐回合表重算，拟合最佳轮次与实际 KL 能由轨迹表核对。
- D1 共同 KL 为 3.7027204101e-5，最大匹配误差 5.02e-17。它小于请求的 1e-4，但符合代码声明的共同 KL 规则，不是匹配失败。
- D1 环境成本为采样 19200 + 评价 200000 = 219200；D2 为采样 38400 + 评价 280000 = 318400。合计 537600，与 manifest 一致，未混入原 4M 训练预算。
- 入口脚本哈希 f85d39… 与本地 681383… 的差异可由 CRLF/LF 换行完全解释，不是入口代码逻辑差异。manifest 的绝对路径来自另一份工作目录，当前依据相对路径及 checkpoint 哈希确认来源。
- 实际运行未指定独立 init_seed，方向初始化使用数据种子 40 和源轮次；不是验收后示例中的 70。fit_trace_every_updates=0，所以现有轨迹只到 epoch 粒度。两项配置不使结果无效，但不能据此分析单个优化步。

这些完整性检查不替代对当时依赖版本、完整训练批次或真实优势标签的验证。当前输出没有保存方向/候选网络和诊断批次，不能离线恢复每一步梯度。

## D1 方向学得更久，训练分数更好但验证更差

固定 A0 第 545 轮策略、16 个训练回合、32 个独立验证回合，方向训练对比如下：

| 指标 | 16 epoch | 64 epoch |
|---|---:|---:|
| 方向优化次数 | 128 | 512 |
| 训练 B_label | 0.020915 | 0.183151 |
| 验证 B_label | -0.009986 | -0.067736 |
| 验证 D_label | 0.000322 | -0.008060 |
| 验证 Fisher 能量 E | 0.010631 | 0.051617 |
| 验证 tanh 饱和比例 | 0% | 59.33% |
| 验证方向分量接近有效边界比例 | 0% | 0.923% |
| 直接目标原始 KL(old ∥ target) | 5.3322e-5 | 2.5872e-4 |

B_label = 2D_label − E。64 epoch 的训练分数提高约 8.76 倍，但独立验证分数恶化，D_label 从接近零变为负值。这是在当前基点和数据划分上明显的代理目标过拟合信号。标签来自冻结 Critic 的 GAE，因此不能把 D_label 直接等同于真实策略回报导数，也不能仅凭 B 为负断言任何缩小步长都无效。

64 epoch 同时使方向能量、目标步幅和 tanh 饱和增加。tanh 饱和与 q 分量达到上界不是一回事：中心化会消去共同偏移。本结果不能解释为整个方向都顶在 q_max，也不支持立即增大 q_max；先验证独立数据上的方向质量更有价值。

把四个候选匹配到同一实际 KL 后，相对旧策略的回报为：

| 候选 | 平均配对收益 | 原始 95% 场景 bootstrap 区间 |
|---|---:|---|
| 16 epoch 直接目标 | -1.170 | [-3.525, 0.971] |
| 16 epoch 拟合 Actor | -2.164 | [-4.586, 0.064] |
| 64 epoch 直接目标 | -1.267 | [-3.416, 0.896] |
| 64 epoch 拟合 Actor | -2.138 | [-4.752, 0.206] |

四个区间均跨零。进一步对相同场景做候选间比较，64 目标减 16 目标为 -0.097，95% 区间 [-2.425, 2.423]；16/64 组 Actor 减直接目标分别为 -0.994 / -0.871，区间也跨零。这些区间由本次脚本以固定种子、20000 次配对场景重采样计算。

因此当前未显示“64 epoch 方向更好”，也未统计确认“拟合 Actor 导致了回报下降”。原 A1 长训练中观察到的改善可能同时受步幅影响；本实验不能倒推出其历史改善的唯一原因。

## D2 Actor 学习率偏大，末轮可能丢失已获得的拟合进展

固定 A2 第 136 轮策略、64 个训练回合、同一方向与目标，只改变 Actor 学习率。三组起点训练目标 KL 均为 3.3566e-5。

| Actor 学习率 | 最佳训练 epoch | 最佳训练 KL | 最终训练 KL | 最终验证 KL | 训练 KL 上升的 epoch 数 |
|---|---:|---:|---:|---:|---:|
| 3e-4 | 13 | 7.6849e-6 | 1.4734e-5 | 1.5498e-5 | 7/16 |
| 1e-4 | 16 | 5.4130e-6 | 5.4130e-6 | 6.9490e-6 | 5/16 |
| 3e-5 | 16 | 5.8762e-6 | 5.8762e-6 | 7.1755e-6 | 0/16 |

3e-4 的最终训练 KL 是其第 13 轮最佳值的 1.917 倍，训练和验证曲线同步反弹。1e-4 的最终训练残差比 3e-4 低约 63.3%，验证残差低约 55.2%；3e-5 在 epoch 粒度单调下降，最终残差接近 1e-4。这里更支持优化震荡，而非单纯“训练拟合越好、验证越差”的泛化问题。

这不是 Actor 完全学不动：3e-4 最终 KL 仍低于初始化，较小学习率也显著降低了目标 KL。网络容量不足不能单独解释末轮比已达到的中间轮更差。原拟合目标约为 1e-5 量级，且记录采用归一化 FP64，不属于验收样例中 1e-11 极小目标被 FP32 噪声淹没的情况。

回报尚未证明改善。3e-4 的最佳/最终候选收益为 +0.448 / -0.467，1e-4 为 +0.067，3e-5 为 +0.260，所有相对旧策略的区间均跨零。最佳减最终的配对差为 +0.915，区间 [-0.156, 1.935]。D2 本身不匹配候选 KL，也不能用这些回报排序判断方向优劣。

1e-4、3e-5 的最佳轮恰为最终轮，对应逐场景回报严格一致；原表中区间边界略有差异来自按候选名称设置的 bootstrap 随机种子，不是候选参数不同。

## 两项问题如何关联

D1 的 16 epoch 方向对应 Actor 首个拟合 epoch 使训练 KL 升至初始的 3.23 倍，随后才下降，进一步支持当前 3e-4 对小目标存在过冲风险。最终训练/验证残差分别保留初始的 22.9% / 45.0%；64 epoch 方向则保留 32.9% / 73.8%。后者生成的目标更难在独立状态上实现，但仅靠残差不能确定是模型容量、状态覆盖还是目标复杂度造成。

D2 的验证 B_label 为 -0.000425，D_label 为正的 0.003233。它不能与 D1 的负 D_label 混为同一种方向失败；D1 使用 A0，D2 使用 A2，源策略、Critic、源轮次和训练样本量均不同。因此不能用 D2 比 D1 的代理分数更好，直接证明“64 回合解决了小样本问题”。
