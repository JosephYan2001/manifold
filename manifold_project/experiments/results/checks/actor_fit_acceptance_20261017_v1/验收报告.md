# Actor 候选选择与固定目标验收

2026-10-17，CPU 工程测试 17/17 通过，用时 47.49 秒。原始记录：[acceptance.json](acceptance.json)、[tests.log](tests.log)。真实 checkpoint 的命令规划见 [command_plans.json](command_plans.json)。

| 验收对象 | 结果 |
|---|---|
| 中间最佳与原轨迹 | 受控实例选择 epoch 1，仍完成 3 次优化；最终参数与原优化循环逐值一致，最终/最佳状态无共享存储 |
| 零更新与平局 | 拟合结果全部较差或与起点相同时选 epoch 0；保留完整优化次数 |
| 生产提交 | 真实 Runner 的在线 Actor 与所选参数逐值一致；零更新不计为有效 Actor 更新，16 个采样步和 6 次拟合更新仍完整保留；no_checks 不追加 η 尝试 |
| 公共配置 | `best_train_kl` 和学习率正确传入 Runner；非法规则或容差被拒绝 |
| 固定目标重放 | 原 checkpoint 不可用时仍能重放；训练/验证采样调用为 0，无标签重生成，无方向优化；重复拟合的最终/最佳参数、逐 epoch 历史与顺序相同 |
| 评价与文件保护 | 原始教师参与评价；相同候选评价不重复计费；固定目标文件未被改写；更改固定因素或破坏快照校验会被拒绝 |
| 既有回归 | 方法/检查开关、整批统计、快照隔离、KL 口径、只读监控、公共中断恢复与增加预算续训全部通过 |

A2/N64/U512 规划为 16 个方向 epoch；A0/N64/U128 规划为 4 个方向 epoch。两组每档 Actor 都是 16 epoch、512 次更新。两个 bestfit 公共配置也通过原训练入口的 dry-run。

本记录只证明实现与受控 CPU 样例满足验收条件；没有执行两组完整 CUDA 诊断，没有新的导航回报或成功率结论。执行命令及结果解释见 [Actor 拟合最小干预说明](../../../cooperative_navigation/Actor拟合最小干预执行说明.md)。
